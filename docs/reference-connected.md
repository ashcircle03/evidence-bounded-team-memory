# 근거 계획과 누적 검색의 연결

이 후보는 기존 선택 경로를 대체하기 전에 같은 개발 입력으로 평가한다.
새 모델 학습이나 원 논문 성능 재현을 주장하지 않는다.

## 역할과 전달 계약

| 연결 | 레퍼런스의 의도 | 이번 적용과 경계 |
|---|---|---|
| 원문 → 근거 계획 | [Attribute First §3](https://aclanthology.org/2024.acl-long.182.pdf)의 선택 구절을 문장별 근거 묶음으로 조직 | 한 호출에서 원문 인용들을 묶고 무엇을 함께 지지하는지 작성한다. 선택/묶기를 합친 것은 우리의 변형이며, 공식 few-shot 예시나 학습 전체를 재현한 것은 아니다. |
| 계획 → 추가 검색 | [IRCoT §3](https://aclanthology.org/2023.acl-long.557.pdf)의 중간 사실로 다음 검색을 안내하고 문단을 누적 | 계획에 부족한 근거가 있으면 최대 두 질의를 검색한다. 원문의 주체·사건을 유지하도록 지시하지만 그 의미를 코드가 보장하지는 않는다. 전체 반복 CoT 대신 한 라운드로 제한한다. |
| 검색 → 생성 | 기존 근거를 버리지 않고 추가 근거를 누적 | 최초 top8을 순서 그대로 보존하고 질의당 최대4개, 합계 최대8개의 새로운 원문 구절을 추가한다. LlamaIndex BM25를 그대로 사용한다. top8 교체와 별도 질의 생성 호출을 제거한다. 입력량 증가는 비용 비교에 공개한다. |
| 계획·원문 → 답 | Attribute First의 근거 묶음과 문장 대응, [AQA §3.4](https://aclanthology.org/2024.emnlp-main.956.pdf)의 출처별 답 | 계획을 안내로 사용하면서 모든 원문을 읽는다. 다른 조건/상충 답은 분리하고, 문서 간 추론에는 여러 출처를 한 답에 연결할 수 있다. 원문 전체를 읽는 것은 선택 누락에 대한 우회 경로다. |
| 답 → 인용 반환 | 기존 LangChain QuotedAnswer 및 원문 위치 복원 | 재작성/사후 인용 호출 없이 답별 인용을 결합한다. 정확한 원문 위치 확인은 의미 지지 인증이 아니다. |

모델 호출은 계획1회와 생성1회다. 계획 형식/인용 실패는 표시하고 원문을
그대로 최종 생성기에 전달한다. 실패한 계획은 검색이나 사실의 근거로 사용하지
않는다. 최종 생성 오류를 성공으로 바꾸거나 다른 모델로 자동 재시도하지 않는다.
질문은 user 데이터, 단계 지시는 system 메시지에 분리한다. 객관식 답변 형식은
최종 답에만 적용한다. 출처 번호는 최초 원문부터 최종 답까지 동일하다.

계획 자체도 모델 판단이므로 불완전할 수 있다. 반환된 최종 답의 양쪽 근거 보존,
작성자/사건 연결과 부족한 근거 탐지는 고정 평가에서 별도로 확인해야 한다.
계획과 생성의 책임을 합리적으로 연결했다는 설계 가설을 성능 증거로 취급하지 않는다.

## 사용

기존 JSONL 인터페이스에서 `--profile connected`를 사용한다.
`python -m team_memory.reference_qa --help`로 모델·임베딩·loopback API 경로 인자를 확인한다.
`import_history`와 `ask`를 지원하며 MCP/UI/승인 상태 머신은 추가하지 않는다.
기존 `attributed`는 평가가 끝나기 전까지 선택 경로로 유지한다.

평가: [고정 프로토콜](../results/reference-qa/connected-v1/PROTOCOL.md).
