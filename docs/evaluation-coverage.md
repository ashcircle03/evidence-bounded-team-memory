고정 데이터: EverMind-AI/EverMemBench-Dynamic `a6b210a32248e841967b7b64a64281d2ff3f669d`, ibm-research/Wikipedia_contradict_benchmark `c20e361f985ed480a659b35d98b49f2311fcd174`. 계산 노드 작업120027에서15파일28,291,290바이트, QA2400개 및 Wiki253 고유 ID를 재확인했다. 개발에서 사용하는1457개는 전체2400개 중 연구 문제에 맞는 다섯 유형이다.

Ever는 전체 프로젝트 기록에서 Q만 검색한다. A/R는 채점에만 사용한다. 객관식 선택지는 reader에게 보이지만 검색어에는 쓰지 않는다. 네이티브 질문의 기준시각이 없으므로 정답 R로 cutoff를 만들어 누설하지 않는다. 시간 순서의 제안 평가에서는 별도로 당시까지 존재한 기록만 입력해야 한다.

Wiki의 원래 단독·상충 맥락에서 출발한다. 자동으로 날짜·승인·정정 사건을 덧붙여 원래 라벨이라고 부르지 않는다. 해당 파생 과제에는 별도의 관계 정의와 독립 주석이 필요하다.

주 비교군 SpeakerMem-R1의 전체 연구 재현 계획은 이 reader 비교로 대체되지 않는다. `joint`는 저비용 공학 비교군이고, `claims`는 Attribute First를 적용한 후보다. 서로 다른 데이터셋·서로 다른 책임의 점수를 하나의 팀 메모리 점수로 평균하지 않는다.
