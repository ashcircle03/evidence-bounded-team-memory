# records 범위 교정: DB 품질을 저장 안정성으로 축소하지 않는다

2026-11-15 사용자 교정. 이전 작업은 DB에 **무엇이 어떻게 구성되는지**보다 입력된 JSON을 보존하는 데 집중했다. 그 작업은 기반 검사로 남기되, records 연구의 주된 성능으로 보고하지 않는다.

## 현재 코드에서 확인한 공백

- `RecordsAdapter.record.append`는 이미 구성된 source envelope를 저장한다. 원문에서 주장·조건·근거·불확실성을 추출하지 않는다.
- `RelationsAdapter`는 원문 쌍의 sentence 선택·관계 제안을 수행한다. source 전체를 개별 재사용 지식으로 구성하는 경로를 대신하지 않는다.
- `GatewayAdapter.ingest`는 append → compare → proposal.submit으로 이어진다. 주장 구성 품질을 검증하거나 누락된 조건을 표시하는 단계가 없다.
- 따라서 현 구현으로 원문 저장을 완벽하게 해도, 필요한 지식의 누락·조건 오해·주체 혼동이 이후 모듈에서 반복될 수 있다.

## 책임 경계

다섯 모듈은 유지하되 records의 **책임 범위**와 현재 공개 **구현 범위**를 구분한다.

| 모듈 | 책임 |
|---|---|
| records | 개별 원문의 주장·조건·대상·출처·시점·불확실성을 구성하고, 추출 기록과 명시적 승인 상태를 구분해 보존 |
| relations | 구성된 기록과 원문을 함께 보고 기록 간 일치·공존·상충·정정·재검토 관계 제안 |
| retrieval | 질문에 필요한 지식과 원문·조건·유효 상태를 함께 검색 |
| answering | 제공된 근거와 상태에 맞는 답변·검사·대안 보존 |
| gateway | 인증과 흐름 연결, 실패·재시도 전달 |

LLM은 기록의 의미를 추출할 수 있다. 추출 결과에는 원문 span과 생성 경로를 남긴다. 코드의 정확한 span 일치 검사는 출처 존재를 보장할 뿐, 그 구절이 주장을 의미적으로 지지한다는 보장은 아니다. 사람 승인/거절은 명시적 이벤트로 처리하며, 모델이 추출한 승인 표현을 인증된 review 이벤트로 자동 변환하지 않는다. 원문에서 말한 승인과 시스템이 확인한 승인도 구분한다.

원문·발화자·관찰시각, 개별 주장·대상, 적용 조건·유효시각, 부정·추정·제안 여부, 결정의 이유, 직접 근거 span, 추출 버전/실패 상태가 검토 대상이다. 원문에 없는 값은 채워 넣지 않는다. 모든 문서에 결정·조건이 있다고 강제하지 않는다. 구체 schema는 기존 레퍼런스의 구현과 대조하여 결정하며 이 문서의 목록을 그대로 새 필수 필드로 적용하지 않는다.

## 평가의 질문을 바꾼다

> 원문을 DB로 구성하는 과정에서, 이후 질문과 비교에 필요한 의미·조건·출처·상태를 얼마나 충실하게 보존하는가?

| 평가 | 필요한 정답 | 주요 오류 |
|---|---|---|
| 지식 포괄성 | 원문에서 재사용해야 할 주장과 결정·이유 | 중요한 내용 누락, 여러 주장의 부정확한 합침 |
| 충실성 | 각 주장을 실제 지지하는 원문 span | 없는 주장 추가, 반대 의미, 부정·수치·단위 손실 |
| 조건·귀속 | 주장별 대상·발화자·시점·적용 조건 | 다른 버전/실험 조건으로 일반화, 다른 사람에게 귀속 |
| 지식의 자격 | 보고/추정/제안/결정 및 명시적 review 이벤트 | 추정을 사실로, 제안을 승인 상태로 승격 |
| 후속 사용 효과 | 질문·재검토의 정답과 필요 근거 | DB 구성 때문에 발생한 QA/관계 판단의 오류 |

포괄성과 충실성을 precision/recall로 함께 측정하고, 조건/귀속/상태를 별도 보고한다. 구조가 유효한 JSON이라고 의미적으로 맞았다고 채점하지 않는다. 정답 label을 추출 입력에 제공하지 않는다.

## 데이터와 비교 실험

1. 기존 EverMem 대화와 실제 Git 결정 기록에서 먼저 진단 대상을 정한다. 질문·정답을 보여주지 않고 시간순으로 DB를 구성한다. 기존에 사용한 자료는 개발셋으로 표시한다.
2. 주장·조건·주체·근거 span·자격에 대한 정답을 작성한다. 모델 자동 주석은 후보이며, 검토 없이 독립 gold로 부르지 않는다. 모호한 항목은 정답으로 강제하지 않는다.
3. 실제 자료에 부족한 조건 교차·부정·정정 범위·승인 표현 혼동은 최소 차이 합성쌍으로 보완한다. 같은 이야기의 변형은 같은 split에 둔다. 저장 API가 기대하는 JSON을 정답으로 넣는 기존 46개 검사와 분리한다.
4. 원문만 저장 / 채택 레퍼런스의 지식 구성 / 그 구현을 우리 문제에 맞게 수정한 구성 방식을 비교한다. 우선 원문과 모델을 같게 두고 비교한다. 수작업 정답 DB는 진단용 상한으로만 사용한다.
5. 구성된 DB를 동일한 검색기·답변기에 연결한다. 입력·근거 예산과 추출 비용을 보고한다. 근거가 DB에 없는 오류, 존재하지만 검색 못 한 오류, 전달받고도 답을 틀린 오류를 분리한다.

현재 지식 추출 성능은 **미측정**이다. 새 schema·추출 모델·독립 주석셋이 완성되었다고 주장하지 않는다. 먼저 참고 구현의 실제 추출·검증·저장 연결을 확인하고 최소 경로를 재사용한다. 저장 검사 수를 더 늘리는 것으로 이 작업을 대체하지 않는다.
