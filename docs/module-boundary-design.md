# 모듈 연결과 입출력 정리

이번 수정의 목적은 **재검토 후보가 올바르게 만들어졌을 때 그 근거와 승인 의미가
저장·QA까지 바뀌지 않고 전달되는 것**이다. Qwen3-8B와 비교 프롬프트는 유지한다.
재검토 분류 정확도가 개선됐다고 가정하지 않는다. 학습과 모델 변경은 이 범위에 없다.

## 하나의 흐름

`원문 저장 → 기존 비교 모델 → 원문 위치 결합 → 후보별 검증 → 작성자 검토 → QA`

QA는 원문 저장소를 직접 읽는다. 비교 실패가 원문 읽기를 막지 않는다. 새로운 모델
단계나 의사결정 추출기를 앞에 추가하지 않았다. 사실 정정과 재검토는 같은 원문 참조를
사용하지만, 적용 효과는 기존 종류와 작성자 투표에서 계산한다.

| 경계 | 입력 | 출력과 책임 |
|---|---|---|
| 원문 → 비교 | 원문 ID, 작성자, 날짜, 위치, 번호가 붙은 원문 문장 | 기존 모델이 관계 종류·과거 기록 ID·문장 번호를 선택 |
| 선택 → 저장 | 원문 ID와 문장 번호 | 코드가 `quote/start/end`를 함께 확정. 저장 단계는 해당 위치의 원문과 다시 대조 |
| 후보 → 제안 | 근거가 연결된 후보 목록 | 후보별 검증. 잘못된 후보는 오류로 남기고 정상 후보는 보존. 동일 종류/대상 중복은 양쪽 모두 거절 |
| 제안 → 검토 | 원문에 묶인 제안과 원 작성자의 투표 | pending/approved/rejected/review_conflict. 모델 출력은 승인 권한이 없음 |
| 검토 → QA | 원문·제안·투표·현재 시점의 상태 스냅숏 | 사실은 원문으로, 승인 상태는 스냅숏으로 인용. 서로 다른 근거 역할 유지 |

`correction` 승인은 지정된 주장만 현재 사실에서 대체한다. 같은 문서의 다른 주장은
유지한다. `reconsider` 승인은 **재검토 허가**이며, 기존 관측의 오류 판정·기존 결정
폐기·새 실험의 성공을 뜻하지 않는다. `reconsideration_effects`는 모델의 추가 판단이
아닌 투표 상태의 해석이다. 실제 실험 실행/완료 추적은 이번 기능에 포함하지 않는다.

## 실제 레퍼런스에서 가져온 연결 의도

| 구현 근거 | 가져온 의도 | 이 프로젝트에서의 적용과 경계 |
|---|---|---|
| [LangChain HITL, 고정 커밋](https://github.com/langchain-ai/langchain/blob/d9caf083577c43a91c5bf6bd1f7dfc289581184d/libs/langchain_v1/langchain/agents/middleware/human_in_the_loop.py), `_resolve_per_call`, `_process_decision` | 제안된 동작과 승인 후 실행되는 동작을 구분하고, 거절은 실행 대신 별도 결과로 전달 | 기존 작성자 투표 reducer를 유지하고 정정 적용과 재검토 허가의 효과를 분리. LangGraph 전체를 설치하거나 실행한 것은 아님 |
| [Mem0, 고정 커밋](https://github.com/mem0ai/mem0/blob/f1791daa86d469249c9b002f62644d58a1eb96a0/mem0/memory/main.py), extraction 오류 처리와 `_link_entities_for_memory` | 모델 호출 실패를 빈 사실 목록과 구분. 부가적인 엔티티 연결 실패를 원 기록 손실로 확산시키지 않음 | 실패한 비교를 receipt에 기록하면서 원문 QA는 유지. 자동 삭제/업데이트, 추출 파싱 오류를 빈 결과로 바꾸는 동작은 도입하지 않음 |
| [Graphiti Edge, 고정 커밋](https://github.com/getzep/graphiti/blob/747b480ec6b12ecb718f1e2bc588b20ee36ea9c2/graphiti_core/edges.py) | 추출된 사실에 원 episode 출처와 시간 범위를 연결 | 이미 존재하는 source ID·작성자·날짜·원문 위치 계약을 끝까지 유지. 그래프 DB나 자동 사실 무효화는 추가하지 않음 |
| 기존 NLTK `span_tokenize`와 vendored LangChain 인용 스키마 | 원문 구절과 위치를 식별 가능한 근거 단위로 전달 | 문장 ID를 문자열로만 바꾼 뒤 `.index()`로 다시 찾던 경로를 제거. 반환된 실제 위치를 그대로 검증·저장 |

레퍼런스의 경계를 기존 구현에 맞춰 적용한 것이며, 해당 서비스 패키지 전체를
실행했다거나 그들의 성능을 재현했다는 뜻은 아니다. 후보별 검증은 우리 배치 API에
맞춘 구현이다. 여러 후보를 하나의 원자적 거래로 묶어야 한다는 근거가 없으므로,
실패한 재검토 후보가 독립적인 사실 정정을 소거하지 않게 했다.

## 실패·호환성 계약

- 전체 JSON이 깨지면 전체 비교 실패. 일부 후보만 잘못되면 그 후보의 위치·원출력·오류를 남긴다.
- 비교 호출 실패는 `comparison_call` 오류다. `relations=[]`만 보고 올바른 음성으로 채점하면 안 된다.
- 실패 receipt도 저장하여 ask/sync 때 같은 실패를 무한 재시도하지 않는다. 이번 수정은 자동 재시도 정책을 추가하지 않는다.
- 과거 문자열 인용 호출은 계속 지원한다. 새 선택기는 정확한 원문 offset을 함께 전달한다.
- 기존 `review-snapshot/v1` 렌더링은 유지한다. 추가 설명이 있는 재검토 스냅숏은 v2로 생성하여 같은 ID의 인용 문장이 바뀌지 않게 했다.
- 저장 I/O 오류는 비교 후보 오류로 삼키지 않고 상위 호출로 전달한다.

## 확인 방법과 해석

`tests/test_comparison_contract.py`는 후보 순서를 바꾼 부분 실패, 중복 문장의 두 번째
위치, 위조 offset, 중복 후보, timeout과 재시도 방지를 확인한다. 서비스 테스트는
정정 승인 후 같은 문서의 무관한 사실 보존, 재시작 후 QA, 올바른 재검토 후보의 승인
효과 전달을 확인한다. 여기서 제공한 관계 종류는 테스트 fixture이며 모델 점수가 아니다.

실제 Qwen 검증은 `results/module-boundary/v1/runtime/PROTOCOL.md`에 고정했다.
기존 37개 QA 출력(legacy20 + 흐름11 + 전이6)을
같은 입력·정답 기준으로 실행한다. 기존 상태/값·검토 인용 성공 8건과 엄격한 전체
원문 인용 충족은 구분한다. writer/cache 재검토 양성 2건과 근접 음성 2건도 별도로
기록한다. 기존 개발 사례를 반복한 결과이며 독립적인 일반화 성능이나 전체 벤치마크가 아니다.

모듈 연결이 통과해도 모델이 `reconsider`를 `correction`으로 잘못 선택하는 문제는
남을 수 있다. 이 경우 연결부 수정과 의미 분류의 미해결을 함께 보고하며, 테스트
통과를 시스템 완성으로 바꾸어 말하지 않는다.
