# 평가 프로세스와 모델 선택 감사

2026-11-07. 현재 코드, documents-v1 실제 요청/채점, 과거 design_review 결과와
공식 모델·벤치마크 문서를 대조했다. 기존 점수·동결 코드·키는 수정하지 않았다.
새 GPU 작업은 제출하지 않았다.

## 판단

현재 자료는 오류를 재현하는 개발 진단으로 유용하지만 일반적인 설계 우열이나
모델 적합성을 확정하기에 부족하다. 실패 후보를 제품 기본값으로 교체하지 않은
결정은 유지한다. 이를 원 논문 방법의 기각이나 Qwen3-8B의 능력 상한으로 확대하지 않는다.
직전 제안의 IRCoT 추가보다 평가 계약과 독해 모델의 적합성 확인을 우선한다.

## 확인된 평가 문제

1. legacy20와 Ever10을 반복해서 읽고 수정했다. 80회 호출은 30개 고유 문항의
   조건별 출력이며 80개 독립 표본이 아니다. 동일 사건/대화방도 서로 의존할 수 있다.
   기존 문항은 회귀·디버깅에 유지하고, 튜닝에 쓰지 않은 사건/대화 흐름을 테스트로
   분리해야 한다. 개발 점수 두 건 증가만으로 일반화 개선을 주장할 수 없다.
2. 기존 attributed20/20은 과거 출력/재생 결과다. 새 후보에는 인용 관련성까지
   포함한 새 AND 기준을 적용했다. 최종 코드와 설정으로 기준 경로를 함께 실행하고
   동일 루브릭으로 재채점해야 한다. 기존 점수는 역사적 결과로 보존한다.
3. report.py:49는 정답·지지·필수근거·인용관련성·무근거부연·status를 한 번에 요구한다.
   엄격한 제품 성공률로는 의미가 있지만 원인 진단/공식 QA 정확도를 대체하지 않는다.
   reference_documents.py:99의 인용3개 초과도 partial을 만들어 이 점수를 낮춘다.
   필요한 근거4개와 불필요한 인용4개를 구분하는 의미 기준 없이 개수만으로
   지식 판단 실패를 정의하면 안 된다. 기존 결과에서 바꾸지 않고 다음 계약에서 분리한다.
4. Hanqiang 문항의 질문 전제(Mingzhi의 reminder)를 답에서 반복한 경우를
   별도 주장으로 벌점 줄지 명확히 고정하지 못했다. 경계 판단에 따라 BM25 direct의
   엄격한 성공은2/10 또는3/10이다. 단순 정답값은3/10이다. 질문 전제, 새 사실,
   추론/계산, 기록 간 대립을 분리한 예시가 평가 루브릭에 필요하다.
5. 개발한 Codex가 방법을 알고 의미 평가도 했다. output hash·원문 offset 검증은
   재현성 증거이며 의미 평가의 독립성 증거가 아니다. 다른 judge를 쓰더라도 자동으로
   신뢰성이 확보되지 않는다. 정답/오답/과잉인용/양쪽 답 누락/정당한 기권의 판정 예시와
   사람 확인 표본으로 평가자를 점검하고, 모델/방법 이름을 가린 순서 무작위 카드로 비교한다.
6. report.py:59-65는 후보 채택을 dense 개선에 종속시킨다. BM25+새 독해가 유용해도
   전체 후보 채택으로 이어지지 않는 기준이다. 검색/독해/인용의 독립적 결론과
   실제 결합 시스템의 배포 결정을 구분해야 한다.
7. retrieval R22/290→10/290은 관련 기록 회수이며 최소 충분 근거 확보가 아니다.
   빈 답에 대한 '모든 반환 주장 지지=True' 역시 지원되는 답을 냈다는 뜻이 아니다.
   필요 근거 확보율과 답변율, 답한 문장에 대한 citation precision/recall을 별도 보고한다.
8. 최근 QA 비교는 조건별 공존·상충 답에 대한 일부 회귀만 포함한다. 시간순 누적,
   승인 대기/승인 후 상태, 재검토 대상과 이유, 무관한 기록에 대한 오탐을 평가하지 않았다.
   QA 개선을 프로젝트 전체 해결로 간주할 수 없다.

## 모델 선택 감사

- 실제 최신 요청은 Qwen3-8B, enable_thinking=False, temperature0, max_tokens1024다.
  con은 이 설정 안에서 reasoning 문자열을 요구한 것이며 Qwen native thinking 비교가 아니다.
- 공식 Qwen 모델 카드는 non-thinking에서 temperature0.7/top_p0.8/top_k20을 권장한다.
  greedy는 고정 비교에 쓸 수 있지만 권장 설정에서의 품질이나 모델 최선의 능력을
  시험한 것으로 해석할 수 없다. 설정 변경이 반드시 개선된다는 증거도 없다.
- reasoning과 최종 JSON이 같은1024토큰을 공유했고 실제1/80이length로 끝났다.
  직접 답과 reasoning 답의 같은 토큰 상한은 같은 유효 최종 답 공간을 보장하지 않는다.
  길이 실패는 전체 낮은 점수의 유일한 원인이 아니며 독해 실패와 따로 집계한다.
- Qwen3-8B는 무유료 API·실행 편의의 출발점이었다. 이 프로젝트에서 GPT-4o-mini와
  동등한 temporal/attribution/conflict 능력이 확인된 것은 아니다.
- 이전 Qwen2.5-3B/14B Git 진단에서 모델-방법 상호작용이 관측됐다. 그 결과는 현재
  Qwen3-8B QA 성능의 대조군이 아니지만 약한 한 모델에 전체 설계 판단을 종속시키지
  말아야 할 프로젝트 내 근거다.
- Contriever도 저자 구현에 있다는 이유로 택한 후보이며 실제 데이터의 검색 적합성으로
  선별된 모델이 아니었다. 생성 모델, 검색 encoder, 평가 judge의 선택 근거를 각각 둔다.
- 학습된 원 방법/원 모델과 일반 Qwen 프롬프트 어댑터는 구분한다. 모델·학습·추론
  규약이 바뀐 결과로 원 연구의 효과를 기각하거나 재현했다고 표현하지 않는다.

## 다음 평가 계약

세 종류를 구분한다.

| 목적 | 자료 | 점수 |
|---|---|---|
| 공개 QA 비교 | Ever native QA, Wiki 제공 문맥 | 원 평가의 답 정확도와 유형별 결과; judge 대체는 명시 |
| 우리 근거·상태 요구 | 주장/인용, 상충과 조건 공존, 시간순 팀 기록 | 인용 지지/완전성, 양쪽 답 보존, 근거 있는 재검토, 오탐, 승인 전후 QA |
| 엔지니어링 회귀 | 노출된 legacy20/Ever10 및 기존 replay | 기존 기능 손실, 구조·실행 오류, 입력/출력 재현 |

첫 번째와 두 번째의 지표를 각각 보고하고 엄격한 전체 성공률은 추가 지표로 남긴다.
원 데이터의 label이 지지되지 않는 경계 사례는 출력 결과를 본 뒤 임의 수정하지 않고,
사전 근거 감사에서 별도 분류한다. 평가 샘플/모델 선정용 calibration과 최종 test도 분리한다.

모델 후보는 우선 현재8B와 같은 계열 Qwen3-14B로 제한한다. 14B가 더 적합한지는
미측정이다. 별도 calibration에서 정확한 원문 근거만 주었을 때와 동일 원문에
관련 없는 기록을 붙였을 때 작성자·날짜·조건·상충 보존·출력 완결성을 점검한다.
gold answer/해설은 모델에 주지 않는다. 정답 근거 창은 별도 검토하고 실제 검색
성과와 분리한다. 8B thinking은 모델 크기 비교와 분리한 설정 후보로 취급한다.
설정 선택 후 모델·template·precision·decoding·길이 한도를 고정한다. 확률적
decoding은 사전 지정한 seed 반복과 분산을 보고한다. 단순8B/단순14B/모듈8B/모듈14B를
무작정 전수 실행하기 전에 calibration으로 부적합한 설정을 제외한다.

채택은 정답 하나의 수치나 파라미터 수가 아니라 근거 있는 답, 심각한 상태/조건 오류,
실제 호출·입출력토큰·지연·GPU 사용의 조합으로 한다. 같은 모델 내 방법 효과와
모델 교체 효과를 구분하고, 더 강한 단순 방식과 복잡한 약한 모델 방식의 비용도 비교한다.
작은 표본의 +2건은 확대 여부 판단으로만 쓰고 사건 단위 paired 차이와 불확실성을 보고한다.
기존20 전부 보존은 제품 회귀 목표로 유지하되 그것만으로 연구적 우월성을 정의하지 않는다.
