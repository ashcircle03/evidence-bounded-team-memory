# 주장과 근거를 같은 단위로 다루는 QA 후보

목표는 **원문의 서로 다른 답을 빠뜨리지 않고, 답의 각 주장에 그 주장을 지지하는 구절을 직접 연결**하는 것이다. 문서 하나를 인용했다는 사실을 그 문서 안의 모든 주장을 보존했다는 뜻으로 쓰지 않는다.

구현은 `검색 → 원문 구절 선택 → 구절에 연결된 주장 생성 → 위치·구조 확인`이다. 새 `claims` 경로의 모델 단계는 구절 선택과 주장 생성 두 개다. 기존 문서별 전체 답 판정, 초안 재작성, AQA 추가 보정, 사후 문장 인용 호출을 이 경로에서는 사용하지 않는다. 기존 경로는 회귀 비교 대상으로 유지한다.

| 책임 | 가져온 근거 | 적용과 한계 |
|---|---|---|
| 먼저 인용할 구절을 고른다 | [Attribute First, then Generate, ACL2024](https://aclanthology.org/2024.acl-long.182/) | 공식 저장소의 content_selection → fusion_in_context 경로를 사용한다. 주 방법의 세 단계 전체 재현이라고 부르지 않는다. |
| 선택한 근거를 묶어 주장으로 만든다 | [공식 LFQA 프롬프트](https://github.com/lovodkin93/attribute-first-then-generate/blob/cc7b995dfb288da7982ae388994f182bef030b75/few_shot_experiments/prompts/LFQA.json) | all and only selected highlights 및 근거 묶음→문장 연결을 짧은 JSON 주장 목록으로 변형했다. 최소 두 문장/100단어 같은 원래 장문 형식 제약은 제거했다. |
| 주장마다 출처·구절이 붙는다 | LangChain0.3.27 Citation 스키마와 기존 원문 저장 계약 | 정수 Source ID는 현재 입력에만 대응한다. 공백 차이와 제한된 RST 인라인 리터럴 표시를 원문 위치로 복원한다. 코드 연산자·조건 문구는 바꾸지 않는다. |
| 상충과 조건별 공존을 보존한다 | 기존 [AQA의 출처별 답](https://aclanthology.org/2024.emnlp-main.956/) 접근 | 같은 문서라도 다른 근거 구절은 별도 단위다. 작성자와 시각을 전달하고, 언급된 사람을 작성자로 바꾸거나 최신 기록을 승인으로 해석하지 않는다. |
| 실패 상태가 사라지지 않는다 | 기존 단계별 fallback, 명시적 상태 계약 | 이전 답과 근거를 보존하면서 실패 단계·경고를 누적한다. 수정 후보가 정상 파싱됐다는 이유로 앞 단계의 미완료를 지우지 않는다. |

공식 Attribute First 코드 revision은 `cc7b995dfb288da7982ae388994f182bef030b75`다. 프롬프트 발췌와 Apache2.0 라이선스를 함께 보존했다. 기존 Qwen3-8B를 사용하며 원 논문의 모델·시범 예시·학습·성능을 재현했다고 주장하지 않는다.

## 입출력과 상태

기존 JSONL의 `import_history`/`ask`를 유지한다. `python -m team_memory.reference_qa --profile claims`와 기존 store/model-path/embedding-path/api-base 인자를 쓴다. Python 진입점은 `ClaimEvidenceQA`다. UI/MCP는 추가하지 않는다.

- `claims[].text`와 `claims[].evidence[]`가 주장과 원문 근거의 기본 단위다. `answers[].evidence[]`에도 같은 근거 내용이 들어간다.
- `citation_sources[]`는 선택한 좁은 구절이며, `retrieval_sources[]`는 검색한 원래 문단이다. 같은 원문 ID 아래 여러 구절이 있을 수 있다.
- 근거는 원문 ID, 작성자, 위치, 문자 시작·끝, 정확한 구절, 알려진 기록 시각을 가진다.
- `selection_raw`/`generation_raw`는 두 단계의 실제 모델 출력이다. `raw`는 그 주장과 인용 번호의 표시 형태다.
- `ok`: 구조·위치 연결 완료. **정답·의미 지지·모든 관련 근거 검색의 인증이 아니다.**
- `insufficient`: 관련 근거를 선택하지 못했다. 이를 정답 부재의 보증으로 보지 않는다.
- `partial`: 일부 구절 미복원, 잘못된 JSON/ID, 생성 실패 또는 선택한 근거가 답에서 누락됨. 남아 있는 답을 반환한다.
- 요청 자체의 오류는 JSONL `error` 응답이다. 응답은 stdout, 초기화·검색·오류 진단은 stderr로 분리한다. 전역 출력 전환은 단일 요청 루프를 소유한 CLI 경계에만 둔다.

선택 단계가 중요한 근거를 처음부터 놓치면 `unclaimed_evidence_ids`로는 잡을 수 없다. 주장과 구절이 구조적으로 연결돼도 구절이 실제 주장을 지지하지 않을 수 있다. 이 두 한계를 숨기는 추가 검사기는 넣지 않고, 검색 회수율·주장별 의미 지지·필수 내용 보존을 별도로 평가한다.

## 검증과 채택

상태 수정은 기존20개에 대해 저장된112개 후속 호출을 정확히 재생했고 초안20개도 확인했다. 답·근거는20/20 동일하다. 인용 미완료8개가 새로 partial로 드러난다. 이는 새 모델 실행 성능이 아니다. 384토큰 판정 제한은 실제 HTTP 요청 경계의 별도 검사로 확인한다.

첫 비교에서 새 후보는 기존 20개 중 답 내용 15개, 필수 답과 근거 14개를 보존했다. [당시 확대 평가](../results/reference-qa/claims-v3/README.md)는 그대로 보존한다.

후속 형식 수정은 표준 JSON 디코더로 문자열 안의 탭·줄바꿈을 읽고, RST 일반 문단의 짝지어진 인라인 리터럴 표시를 유일한 원문 위치로 복원한다. 원문 전체 파서나 의미 유사도 보정은 사용하지 않는다. 고정 104개 출력을 재생하고 새 최종 생성 5회만 실행해 기존20개의 답 내용은18개, 필수 답·근거는17개로 늘었다. 기존 성공48개를 모두 보존했지만 교체 기준은 충족하지 못했다. `attributed`를 유지하며 `claims`는 실험용 프로필로 둔다.
