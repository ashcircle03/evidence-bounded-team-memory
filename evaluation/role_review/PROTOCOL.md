# 원문과 설명의 대응 검증

개발에는 직전 검증에서 과거 결정·새 보고·대조 결정의 원문을 모두 찾은 훅, reflog, 셸 프롬프트 3건을 사용한다. 과거 제안 및 세 인용을 고정한다. 각 건에서 당시 모델 설명, 정확한 의역, 방향이나 극성을 바꾼 설명, 원문 발췌를 검사한다. 지지되는 설명을 보류한 수, 틀린 설명을 허용한 수, 잘못된 세부를 직접 지목한 수를 구분한다. 수리한 설명은 역할별 인용의 실질적 의미와 전체 설명의 충실성을 별도로 읽는다.

새 Git 보고 5건과 채점 기준은 `build.py`에 고정한다. 같은 Git 프로젝트의 과거 기록에서 수집한 목적 표본이다. 각 사례에는 양성 이력, 주제만 비슷한 결정 두 개가 있는 음성 이력, 대조 결정 하나만 있는 음성 이력을 만든다. 두 결정이 있는 이력은 원문 및 원인 참조를 가린 버전에서 각각 실행한다. 원문 두 결정의 제시 순서를 뒤집어 새 전략을 독립 재실행한다. 가림과 순서 반전은 같은 사례의 반복 관측이다.

직전 전략, 새 전략, 단순 검색과 Qwen을 동일 원문에서 비교한다. 공통 성공은 정확한 결정과 새 보고의 허용 구절을 인용하고, 변경 조건과 행위 결과가 정확하며 근거 밖의 추가 주장이 없는 제안이다. 대조 결정도 정확한 구절과 유효한 차이 설명을 요구한다. 새 전략은 이와 별도로 각 역할의 인용이 실제 주체, 방향·부정이 보존된 동작, 발동 조건을 뒷받침해야 한다. 출처·화자·문자 범위를 맞춘 것만으로는 의미 점수를 주지 않는다. 사례별 의미 채점은 전략 이름을 뺀 카드에서 수행한다. 방법과 산출물 문체는 완전히 눈가림할 수 없다.

QA에서는 과거 질문과 동일 입력으로 모델을 실제 재실행한 뒤, 구조화된 답과 인용을 문항별로 원래 출력과 대조한다. Git 복제본 두 곳에서 같은 질문을 독립 생성해 pull 이후의 결과와 대기 중인 제안의 분리를 확인한다. 동일한 오답은 보존 지표와 정답 지표를 구분해 기록한다. 원인 진단 뒤에는 새 사례를 보고 전략을 다시 수정하지 않는다.

실제 실행에서는 원문 위치가 맞는 역할도 의미가 틀릴 수 있어 역할 카드에 인용의 의미를 따로 채점한다. 자유 생성 설명과 관찰문에서 직접 재구성한 설명을 구분한다. 구체적으로 이 두 경로의 출력을 섞어 자유 생성 검증기의 정확도로 집계하지 않는다.

개발 중 두 단계를 폐기했다. 첫 판은 유효한 구절을 자주 복사하지 못했고, 두 번째 판은 문자 범위는 맞아도 실패 주체와 비교 대상을 혼동했다. 최종판은 주제어를 지정하지 않고 같은 문장 안에서 인자 전달 경로, 부정 서술 및 범위, 구현 교체 후 반환값 및 입력을 결합하는 영어 구문을 우선 사용한다. 해당 구문이 없으면 Qwen의 구절 추출을 사용한다. 따라서 세 구문에 맞춘 개발 적중은 일반화 성과에 포함하지 않는다.

세 번째 개발 실행을 읽다가 함수명이 포함된 커밋 제목에서 닫는 괄호를 일찍 잘라 날짜가 설명에 남은 문제를 발견했다. 이 시점에 새 Git 결과를 열지 않고 괄호 깊이를 추적하는 수정과 최종 파일을 동결했다. 수정 전후 실행을 모두 보존한다.
