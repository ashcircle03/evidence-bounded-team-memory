# 새 팀 기록 파일럿

기존 68문서는 회귀 패널이다. 입력·정답·평가기·v0.2.1 결과의 SHA-256은 freeze.json에 고정했다. 새 패널은 2026년 11월 공개 Matplotlib PR 32604, 32446, 32601, 32598의 15개 메시지다. 네 개의 수정·검토 스레드를 목적 표집했다. 이전 68개 원문과 공백·대소문자를 정규화한 완전 중복은 없다. 대학 팀 내부 자료의 대표성은 별개다. 본문과 병합 시각 이전의 비어 있지 않은 사람 댓글·리뷰 본문만 사용한다. 인라인 리뷰, 링크 대상, diff, 승인 이벤트 및 이후 대화는 자료 범위 밖이다. 본문은 수집 시점 버전이며 최초 작성 시점 원문 재구성이 아니다. 분석 단위는 질문이며 독립 사례 수는 PR 네 개다.

## 주석 순서

1. A와 B에게 각각 ZIP 하나를 전달한다. 상호 답과 기계 출력을 가린다. 질문을 쓰기 전에 메시지별 records.csv를 먼저 봉인한다. 빈 메시지는 미추출인지 미검토인지 제출 시 확인한다. **주 비교의 사람 records는 사전 지정한 A의 질문 작성 전 기록**이다. B의 기록은 불일치 원인 분석용이다. 질문에 맞춰 사람 records를 보완하지 않는다.
2. 각자 PR당 질문 두 개와 기대 답·근거·필수 연결을 작성한다. 질문만 합쳐 재배열한다. 두 사람은 공통 질문 전체에 대해 독립적으로 outcome·핵심답·인용 및 필수 연결을 다시 표시한다. 질문 출처(A/B/공통)는 별도로 보존하고 A가 만든 질문에서만 사람 records의 이득이 집중되는지도 확인한다. 패킷에 없는 전제를 임의로 채우지 않는다.
3. 최초 독립 표기를 보존한다. outcome 일치율, 핵심 답 의미 일치, 허용 가능한 대체 근거 구절, 각 필수 연결의 근거·대상·역할을 비교한다. 표현이 달라도 같은 의미면 그 이유를 기록한다. 합의되지 않은 문항은 별도 집계한다. 정답과 허용 대안을 봉인한 뒤 추론을 시작한다.

## reader와 판정

세 조건에 같은 PR 원문 전체·출처·순서·질문, 같은 Qwen3-8B 리비전과 TEAM_QA_TEMPLATE, temperature 0, seed 42, 출력 512토큰을 제공한다. 검색을 생략해 근거 가용성을 통제한다. 자동·사람 주석은 공통된 주장 그룹과 역할·상태·원문 위치로 표현한다. 이는 records 품질을 보는 통제된 reader 비교다. 기록이 길어지면 임의 절단하지 않고 세 조건의 입력 길이와 실행 여부를 함께 보고한다. 모델 입력에는 질문만 넣고 정답·근거·필수 연결은 주지 않는다.

각 문항에서 세 답을 가리고 순서를 섞어 채점한다. 답은 필수 핵심 명제·조건·상태 충족 여부, 인용은 각 명제에 대해 패킷 안의 원문 존재와 답을 실제 지지하는지, 보류는 answer/partial/abstain의 적합성을 따로 기록한다. 부분답에서 확인 불가한 사항까지 단정하면 실패다. 잘못된 답에 실재 구절만 붙인 경우 인용 지지 점수를 주지 않는다. 같은 질문의 개선·퇴행·동률 및 서로 다른 PR 수를 보고한다. 편의를 위해 만든 질문과 자연 발생 질문을 구분한다.

### 다음 개발 결정

사람도 원문·근거·필수 관계를 합의할 수 없는 사례가 여러 PR에서 반복되면 대상 또는 라벨 정의부터 수정한다. 합의 문항에서 사람 records만 반복적으로 답과 인용을 복구하면, 성공에 필요했던 구절이 자동 records의 어느 단계에서 사라졌는지 추적한 뒤 추출기를 고친다. 두 구조화 조건이 모두 실패하면 reader 입력과 해석을 점검한다. 원문 조건과 차이가 없으면 그 유형의 구조화를 우선순위에서 내린다. 한 PR에만 있거나 결론이 혼재하면 탐색 결과로 보류한다. 합의된 정답 없이 주석자나 모델의 우열을 판정하지 않는다.

## 실행 파일과 제출물

- 각자 ZIP의 records.csv, questions.csv, evidence.csv를 작성한다. A/B 식별자만 붙여 별도로 반환한다. 두 사람의 records 봉인본 파일 해시와 접수 시각을 보존한다.
- `python -m evaluation.team_record_pilot.pilot cross A/questions.csv B/questions.csv shared-questions.csv`로 정답 없는 공통 문항을 만든다. 두 사람은 공통 문항에 독립적으로 답한 후 차이를 검토한다. 의견 차이 원본과 확정 키를 따로 보관한다.
- 자동 records 추출 Slurm ID는 124279다. 연결된 기존 Qwen 및 GUM 체크포인트와 동결된 15개 원문만 사용한다. Slurm COMPLETED/0:0, 프로그램 완료, 입력 해시와 모델 응답 수를 확인한 뒤 finish_records.py를 실행한다. 자동 기록이 failed인 메시지도 원문과 함께 평가한다.
- `python -m evaluation.team_record_pilot.pilot requests shared-questions.csv automatic.json A/records.csv requests.json`로 같은 질문·reader의 세 입력을 만든다. 전체 입력이 컨텍스트를 넘는 경우 세 조건 모두를 같은 규칙으로 제외하고 기록한다. 최종 응답 JSON 파싱 실패는 해당 arm의 형식 실패로 기록한다.
- 같은 계산노드 Qwen 서비스에서 `read_requests.py requests.json responses.json`을 실행한다. `grade.py blind`는 질문 파일, 응답 파일, 새 출력 디렉터리를 받는다. 채점자에게 scorecard.csv와 확정 키·원문만 주고 coordinator-only-key.json은 주지 않는다. 정답 보류 시 지지할 주장이 없어 인용이 불필요하면 NA로 표기한다. disagreements 및 지지 여부는 사람 확인이 필요하다.
