# CPython 외부 기록 평가 v1

원래 질문은 팀원이 새 기록을 받았을 때 관련 과거 판단을 찾아 근거·조건과 함께 재사용할 수 있는가이다. Aimers와 기존 합성 5건은 개발에 사용했으므로 여기서 제외한다. 다음 기준은 검색 및 Qwen 출력 열람 전에 작성한다.

- 표본은 CPython 주석 구현, 자유 스레딩 지원 단계, 명시적 지연 import의 첫 공개 초안 3건이다. 팀 기록을 가진 미사용 프로젝트 한 곳에서 의도적으로 고른 사례다. 같은 사건의 목표가 두 개여도 사건 수를 두 번 세지 않는다. 사전학습 오염 여부는 알 수 없다.
- 각 초안이 공식 main에 처음 들어간 커밋의 첫 부모에 있는 모든 번호 붙은 RST PEP 파일을 검색 모집단으로 삼는다. 양쪽에 같은 문서 발췌를 준다. 과거 문서는 당시 번호·제목·상태와 본문 시작 1,800자, 새 기록은 첫 160줄이다. 파일 전체를 검색한 성적으로 해석할 수 없다. 파일명이나 정답 ID로 후보를 주입하지 않는다. 원문에 원래 있는 제안 번호는 주 평가에서 유지하고 새 입력에서 링크·명시적 PEP 인용을 지운 검색도 별도 측정한다. 동일한 원문에서 직접 읽기와 근거·결정 강조 두 번 읽기를 분리한다.
- 단순 기준은 원문 BM25 상위 1건과 같은 Qwen이다. 현재 모듈은 수정 없이 명시적 결정 구간 검색과 기존 판정 규칙을 사용한다. 비교군은 새 기록으로 직접 1회 판정, 같은 읽기 횟수에서 직접 판정을 재확인하는 2회 방식이다. 최대 2회, 호출당 입력 8,192토큰, 같은 최신 보고와 최대 3개 과거 보조 구절, 같은 A–E 선택지로 제한한다. 실제 토큰 수도 공개한다. 최초 후보를 잘못 고르면 조치가 우연히 맞더라도 결합 정답은 0이다.
- 별도로 QA는 과거 결정 3문항을 업데이트 전후에 물어 정답과 출처의 보존을 확인하고 새 기록 3문항은 업데이트 뒤에만 묻는다. 동일한 BM25 상위 3개 원문과 기존 인용 검증 리더를 쓴다. 답의 의미 단서, 올바른 문서 ID, 실제 원문 인용을 모두 확인한다. 검토 장부는 일반 QA와 분리되어 있으므로 공통 QA 리더를 1회 평가한다. 서로 다른 QA 모델의 승패로 해석하지 않는다.
- 목표·질문은 입력에, 예상 과거 문서·허용 조치·QA 근거는 오프라인 키에만 둔다. 복수 정답은 출력 전에 기록한다. 현 모듈의 실험 중심 선택지를 거버넌스 결정에 대응시킨 부분은 별도 표시한다. 키는 이 시스템을 설계한 에이전트가 기록해 둔 잠정 기준이다. 제삼자가 정답이나 시스템 예측을 보지 않고 독립적으로 판단할 수 있는 검토표를 제공한다.
- 채택 판단은 사전에 다음과 같이 제한한다. 외부 사람의 독립 검토 전에는 연구적 우위를 확정하지 않는다. 이 파일럿에서 단순 방식과 같거나 나쁜 경우 단순 방식을 우선한다. 더 복잡한 방식의 확대 조건은 적어도 서로 다른 2개 사건에서 새로운 대상·조치 결합 정답을 얻고, 기존 정답 손실과 과잉 제안 증가가 모두 없으며, 기존 근거 있는 QA가 보존되는 것이다. 미달하면 현재 버전의 채택을 보류한다. 채점 뒤 같은 사례에서 모듈을 고친 결과는 개발 성적으로만 취급한다.
