# 현재 설계의 유지 판단

사용자 승인 2026-11-05. 이 실험 동안 생산 모듈과 프롬프트는 수정하지 않는다. 실행 전에 입력, 정답 기준, 근거 창, 코드 해시를 동결한다. 성공 사례를 보고 근거 창이나 채점 기준을 바꾸지 않는다.

기존 context_review·role_review·contrast_review/validation의 Git 보고 15개를 모두 사용한다. 각 보고에 실제 이전 결정+유사 결정이 있는 양성, 유사 결정 두 개만 있는 음성, 명시적 원인 참조가 있는 원문과 참조를 가린 변형을 짝짓는다. 60개 입력이나 독립 사건은 15개이다. 과거 개발·평가에 사용된 진단 패널이며 새 독립 테스트 성과로 주장하지 않는다. 패널 선택은 성공 여부에 따른 표집이 아니다. 시간순 원문만 사용하며 정답 기준은 추론 payload에 넣지 않는다.

주 비교: Qwen2.5-3B-Instruct의 원문 전체 단순 판단과 현재 context-review. 동일 60개 입력이며 단순 방식은 한 번 읽고 문단 ID와 짧은 이유를 생성한다. 현재 모듈은 기존 다단계 선택을 그대로 수행한다. 각 사례 상한 입력 120,000토큰, 생성/점수 평가 4,096토큰; 단순 생성 상한 512, 모듈의 각 생성 상한 192. 상한은 공통이나 실제 호출 수와 소비량은 다르므로 동일 비용 실험이라고 부르지 않고 실제 비용을 나란히 보고한다. 상한 초과는 실패로 표시하고 조용히 중단/축약하지 않는다.

병목 대조: 참조를 가린 동일 양성·음성 30개에 대해 원문 전체와 정답 근거 창을 각각 Qwen2.5-3B와 Qwen2.5-14B-Instruct에 제공한다. 두 모델은 같은 프롬프트·정확히 같은 문단·512 출력 상한·greedy decoding을 사용한다. 정답 근거 창에는 정답 행동·설명·대상 표시를 포함하지 않고, 두 이전 결정의 실제 내용과 새 보고에서 판단에 필요한 원문만 남긴다. 큰 모델의 우위는 이 두 체크포인트에 한정해 해석한다. 더 큰 모델로도 실패하면 모델 능력, 과제/프롬프트, 근거 구성 중 하나로 단정하지 않는다.

근거 창은 각 사례의 실제 동작·오류·발동 조건을 보존하는지 oracle-audit.json에서 실행 전에 검토한다. 출처 ID·인용은 코드로 검사하며, 별도로 설명의 대상·동작·조건과 인용의 의미적 충분성을 판정한다. 올바른 대상에 제안했어도 조건 누락이나 원문 밖 주장을 포함하면 엄격한 성공이 아니다. 보류는 양성 실패이고 음성에서는 맞는 판단이다. 형식 오류는 음성의 올바른 보류로 세지 않는다.

방법 이름을 제거한 카드로 의미 채점하며 답과 근거가 드러내는 형식 때문에 완전한 맹검을 보장하지 않는다. 한 AI 평가자의 판단이라는 한계를 명시하고 항목별 근거를 공개한다. 사건별 paired 차이를 보고하며 60개를 독립 표본으로 취급하지 않는다. 자동 판정과 의미 판정을 분리하고 외부 지식으로 인용 부족을 메우지 않는다.

기존 QA: 원래 136개 프롬프트를 실제 3B로 다시 생성해 원래 파서로 20개 성공 항목의 답·상태·인용·출처를 비교한다. 비교 모듈은 생산 QA 경로를 바꾸지 않는다. 실제 Git pull의 승인 대기 제안이 QA를 손상시키지 않는지도 기존 고정 두 사례에서 다시 확인한다. 20개 항목 보존은 QA 전체 정확도나 향상을 뜻하지 않는다.

판정 규칙: 현재 모듈이 단순 방식보다 엄격한 재검토를 늘리지 못하면 유지 근거가 없다. 오탐 감소를 위해 재검토를 잃는 경우 두 수치를 함께 보고한다. 원문→정답 근거에서 같은 모델이 회복하면 근거 선택 병목의 증거다. 같은 정확한 근거에서 14B만 회복하면 3B 판단 능력/모델-프롬프트 조합의 병목 증거다. 단순 방식의 실패를 현재 모듈의 성공으로 계산하지 않는다. QA 보존을 모듈의 유용성 증거로 대체하지 않는다. 결과가 혼합되면 유지·단순화·교체 결정을 해당 요소별로 명시한다.

모든 서버 계산·다운로드·해시는 Slurm 노드에서 수행한다. 14B는 bf16 2 GPU, 3B는 bf16 1 GPU. 기존 누적 상한 150 GPU분에서 300 GPU분으로 늘리며 모든 실패를 포함한다. CPU 다운로드 최대 30분, GPU 작업 최대 20분; OOM/timeout 후 자원 자동 확대 금지. 사용자 전체 동시 running 4개, GPU4개, pending+running8개 제한을 지킨다. 실제 사용량을 작업별로 남긴다.
