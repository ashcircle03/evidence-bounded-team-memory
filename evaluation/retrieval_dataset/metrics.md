# Retrieval 평가 프로토콜

F02의 출력은 Relations에 넘기는 순위가 있는 과거 기록 후보이고, F05의 출력은 Answering이 실제로 받는 근거 묶음이다. 두 출력을 각각 채점한다. 기본 비교점은 K=5로 고정하고 K=1, 3도 병기한다. 5는 이번 비교의 예산이며 최적값은 개발 데이터에서만 탐색한다.

| 과제 | 주 지표 | 보조 지표와 분모 |
| --- | --- | --- |
| F02 선행 기록 검색 | 문서 MRR@5 | 문서 Recall@5. 구절 정답이 있는 사례는 구절 Recall@5도 별도 산출. 양성 질의별 점수의 산술평균 |
| F05 근거 검색 | 상위 5개 내 정답 근거 그룹 Recall@5 | 첫 관련 근거 MRR@5, 모든 주석 근거 그룹이 하나 이상 회수된 질의 비율. 양성 질의별 평균 |
| F05 최종 묶음 | 필수 근거 완비율 | 필수 구절 그룹과 필수 검토 상태 ID를 전부 포함해 전달한 문항 수 / 해당 양성 문항 수. 상태가 필요한 부분집합도 별도 보고 |
| 음성 및 실행 실패 | 음성 오반환율 | 근거 없음이 명시된 문항 중 하나라도 후보를 반환한 비율. 양성에서 빈 결과를 반환한 비율, 실행 실패 건수도 병기 |

**순위와 단위.** 첫 정답 순위가 r이면 RR@5는 1/r, 5위 안에 없으면 0이다. 정답이 정의된 모든 양성을 분모에 둔다. 문서 순위는 같은 문서의 여러 구절 중 최초 등장만 남긴 뒤 매긴다. 구절 순위는 원래 반환 순서를 쓴다. 중복 적중은 정답 그룹당 1회로 제한한다. 같은 점수는 고정된 ID 순으로 정렬한다. 정답 그룹은 필요한 사실 하나와 그 사실을 뒷받침하는 허용 대안들이다. Recall은 적중한 그룹 수 / 필요한 그룹 수다. 정답이 하나면 Recall@K는 Hit@K와 같다.

**주석별 적중 판정.** 자체 span 데이터는 같은 source ID의 반환 구절이 정답의 [start,end) 전체를 포함해야 한다. GitBugs는 이슈 ID 단위로만 계산한다. QMSum은 발화 번호 범위 주석을 사용한다. 연속된 주석 범위 하나를 한 그룹으로 두고, 해당 회의의 그 범위에 속한 발화가 적어도 하나 반환되면 해당 그룹에 적중한 것으로 센다. 긴 범위의 한 발화만 찾아도 적중하므로 주석 발화 중 회수된 비율도 병기한다. 모든 주석 범위 적중은 주석 위치 커버리지로 해석한다. 회의의 모든 범위가 답변에 필수라는 보장은 없다. QMSum에서는 제품의 승인 상태 완비율을 산출하지 않는다.

**예산과 실패.** 최초 검색 순위와 관계 확장·예산 절단 후 최종 묶음을 따로 기록한다. 최종 묶음 비교는 동일한 증거 개수·문자 예산에서 수행하고 그 값과 실제 전달 문자 수를 보고한다. 원문·상태가 한 쌍으로 필요한 문항에서 한쪽만 전달하면 완비 점수는 0이다. 양성의 실행 오류는 성공 점수 0, 음성 오류는 정상 빈 결과와 구분한다. 음성 정상 보류율·오반환율·오류율은 전체 음성을 분모로 함께 보고한다. 시나리오·회의·프로젝트, 후보 풀 크기와 문항 수를 공개하고 출처별로 분리 집계한다. 동일 질문에서 BM25와 현행 팀 검색을 비교하고, 차이의 불확실성은 독립적인 회의·이슈 그룹을 단위로 재표집한다.

## 외부 평가 자료 선정

- **F02 주 평가 후보는 GitBugs.** 프로젝트별 실제 이슈, 생성 시각, 중복 이슈 연결을 제공한다. 새 이슈의 등록 시각보다 앞선 같은 프로젝트 이슈를 후보로 두고, 확인된 선행 중복 ID를 정답으로 쓴다. ID가 해석되지 않거나 선후가 모호한 쌍은 제외하고 개수를 남긴다. 제목·등록 당시 본문만 입력하며 중복 링크·직접 ID 언급과 사후 댓글·상태를 통한 정답 누출을 점검한다. 최초 본문 복원이 불가능하면 이를 보고한다. 중복 표기가 없는 이슈는 확정 음성으로 삼지 않는다. 측정 범위는 비교할 과거 문서 검색이며 정정 유형과 정확한 구절은 별도 과제다. [저자 배포본](https://huggingface.co/datasets/av9ash/GitBugs)
- **F05 주 평가 후보는 QMSum.** 실제 회의 전사와 특정 질문의 사람 주석 발화 범위를 사용한다. specific_query_list 중 유효한 relevant_text_span이 있는 질문만 선택하고, 해당 회의 전체 발화에서 검색한다. 회의 단위 공식 분할을 유지한다. 일반 요약과 정답 요약문은 검색 입력에서 제외한다. [공식 데이터와 스키마](https://github.com/Yale-LILY/QMSum) · [원 논문](https://aclanthology.org/2021.naacl-main.472/)
- **보조 후보는 LongMemEval.** 지식 갱신·여러 세션 질문에는 answer_session_ids를 활용할 수 있다. 근거 대화에 시뮬레이션이 사용되므로 자연 발생 팀 기록 평가의 대체 자료로 취급하지 않는다. [공식 저장소](https://github.com/xiaowu0162/LongMemEval) · [원 논문](https://arxiv.org/abs/2410.10813)

[실제 공개 평가판](public_v1/README.md)은 GitBugs F02 151문항과 QMSum F05 242문항이다. 시점·제목 변경·직접 참조를 검사했고 BM25 예측과 채점 결과를 동봉했다. 기존 SQuAD 200건은 단일 구절 대조군, 한국어 합성 200건은 제품 규칙 회귀, Aimers 3건은 사례 진단으로 유지한다. 실제 정정 전후와 승인·거절에 대한 제품 품질을 주장하려면 독립된 실제 기록에서 원문 양쪽과 상태를 별도로 주석해야 한다.
