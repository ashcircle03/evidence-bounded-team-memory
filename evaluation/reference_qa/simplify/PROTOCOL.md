# 단순화 비교: 실행 전 기준

원래 QA20과 정답 기준은 그대로 둔다. 과거 검색 결과를 고정한20문항에 joint를 새로 실행하고, 기존 attributed20/20과 비교한다. 이는 검색을 다시 평가한 종단간 결과가 아니다. 현재 attributed의 부가 단계17개 실제 프롬프트를 재생하여 과거20개 출력을 그대로 보존하는지도 별도로 확인한다.

새12개는 공개 Gitv2.48.0 문서 질문4개와 합성 팀 기록 변형8개다. 원문내 상충의 순서 반전 쌍을 포함하므로 독립 자연 사례12개가 아니다. 두 구성 모두 전체 기록을 새 저장소에 적재하고 동일한 LlamaIndex 혼합 검색·작성자 메타데이터·Qwen3-8B 비사고 모드·temperature0·32768문맥·1024출력 상한을 사용한다. 검색된 원문과 순서의 일치를 검사한다. arm 순서는 사례마다 교대한다.

일차 평가는 답의 내용·조건·작성자·필요한 대안의 보존, 반환 인용 원문이 각 답을 지지하는지, 근거 없는 추가 답이 있는지다. 부재 문항은 명시적인 답 없음이 성공이다. 인용문 위치의 일치만으로 의미를 정답 처리하지 않는다. 각 판정에 원문 근거와 이유를 기록한다. 개발 담당 AI 채점이며 독립 인간 평가가 아니다.

채택 조건: joint가 기존20/20을 유지하고, 새12개에서 attributed보다 일차 성공 수가 적지 않으며, within-source 두 순서에서 양쪽 주장을 보존하고, 무관한 보고·작성자·부재 문항의 오답을 늘리지 않아야 한다. 새12개의 모델 요청 수가 attributed의 절반 이하여야 단순화 효과로 인정한다. 하나라도 만족하지 못하면 전면 교체하지 않는다. 결과를 보고 사례 예외나 의미 규칙을 덧붙여 다시 실행하지 않는다.

비용은 요청·실제 입력/출력 토큰·답변 시간과 GPU 할당 시간을 함께 기록한다. 같은 개별 호출 상한에서 추가 단계의 비용을 포함한 효율 비교이며, 동일한 총 토큰 예산을 소진시키는 대회가 아니다. 실패·준비도 GPU 예산에 포함한다. 추가 모델 API는 쓰지 않는다. 승인 상태·과거 결정 재검토·병합의 성능은 이 QA 실험으로 주장하지 않는다.
