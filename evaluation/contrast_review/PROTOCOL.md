# 같은 보고에서 이전 결정을 구별하는 평가

이전 실험에 없던 Git 보고 6개를 고른다. 각 보고에 실제 재검토 대상과 같은 구성요소의 다른 결정(혼합), 또는 주제만 가까운 결정 두 개(해당 없음)를 연결한다. 두 조건에서 보고 원문과 후보 수를 고정하며 과거 결정 하나만 바꾼다. 가까운 결정 하나만 남긴 음성도 따로 확인한다. 같은 보고를 여러 번 보여준 결과를 독립 표본으로 합치지 않는다. 보조 조건에서는 해당 보고의 SHA 및 과거 결정의 제목이 그대로 인용된 문자열을 가린다. 직접 언급 인물·함수·행동이나 부분적 의역은 남는다. 원문과 달라지지 않은 보고는 따로 표시한다.

직전 실험의 fixed-review, 그 전 pairwise, 제품 기본 simple, 새 contrast-review를 같은 Qwen2.5-3B-Instruct, BF16, greedy로 비교한다. 기존 simple은 64, 실험 전략은 96 생성 토큰으로 동작한다. 새 방식은 한 보고를 두 결정과 독립/불충분 선택지에 동시에 대조한다. 후보마다 같은 횟수로 각 위치와 글자를 거치게 한다. 전체 기록의 판정과 선택한 원문 문단만의 판정이 대상까지 일치해야 제안을 발행한다. 둘 다 유효할 수 있거나 어느 것도 해당하지 않으면 이번의 단일 대상 제안은 보류한다. QA 및 기본 전략은 따로 변경하지 않는다.

평가 전에 각 양성에서 허용되는 과거·신규·대안 문단과 바뀐 조건, 대안이 다루는 별개 동작을 고정한다. 결과는 (1) 올바른 과거 ID에 실제 제안, (2) 양측 정확한 원문과 올바른 적용 조건을 설명한 제안, (3) 대안의 실제 원문과 왜 이번 보고에 해당하지 않는지도 맞힌 구별, (4) 무관한 후보들만 있을 때의 오탐으로 나눈다. (2)는 모든 방식에 공통으로 적용하고 (3)은 추가 기능으로 별도 보고한다. 단순 기준선에는 별도 설명 필드가 없으므로 제안·구절을 채점한다. 정확한 설명은 핵심 변화와 방향을 짚고, 그와 모순되거나 근거 없는 원인을 추가하지 않아야 한다. 한 평가자가 방법과 시나리오 표기를 가린 카드로 채점한다.

사전 채택 기준은 원문 혼합에서 (2)가 직전 방식보다 증가하고, 무관한 두 후보에 대한 오탐이 0이며, 기존 QA의 정답·인용이 보존되는 것이다. 절대 수치와 (3)을 함께 보고한다. 동일 모델이라고 계산 예산까지 같다고 가정하지 않는다. 기존 QA 성공 20문항의 원래 배치와 채점기를 재실행하고 실제 Git pull 전후에도 같은 원문에서 QA 입력과 답·인용을 대조한다.
