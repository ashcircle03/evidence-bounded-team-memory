# 선택 문단 주변의 근거 복구 검증

개발은 직전 실험의 FreeBSD getcwd와 빈 loose object의 git fsck 두 건이다. 선택된 과거 결정과 새 문단을 고정한다. 공통 질문·답 형식·모델·출력 상한으로 선택 문단, 바로 앞뒤 한 문단, 앞뒤 두 문단, 무관한 기록의 문단을 추가한 조건을 비교한다. 세 번째 조건은 FreeBSD의 실제 실패 설명이 선택 문단보다 두 문단 앞에 있는 상황을 분리한다. 무관한 문단은 같은 주제의 다른 작업이며 원래 문서·화자·범위를 보존한다. 문단 수를 확장 두 문단 조건에 맞추며 문자·토큰 길이의 차이를 기록한다. 각 조건에서 구절 순서를 반전해 별도로 생성한다.

성공은 실제 영향을 받는 동작, 관측 오류·반환값·결과, 발동 조건을 설명하고 그 부분을 원문에서 인용한 경우다. 단지 어떤 수정이 회귀를 고친다는 서술은 실패 동작으로 세지 않는다. 원문 일치만으로 의미를 맞혔다고 계산하지 않는다. 생성 설명, 인용의 문자 일치, 의미 일치, 순서 민감도를 각각 기록한다. 근거 없는 내용을 덧붙인 설명과 없는 내용을 보류한 경우를 구분한다.

개발 결과를 바탕으로 문맥 확장과 근거 추출을 구현한 뒤, 새 Git 보고 5건의 입력과 의미 기준을 동결하고 직전 전략·수정 전략을 비교한다. 각 보고의 실제 이전 결정이 있는 이력과 주제만 가까운 결정만 있는 이력을 사용한다. 참조를 가린 변형은 별도로 평가한다. 모델에 채점 기준이나 정답 문구를 주지 않는다. 새 사례 결과를 본 뒤 구현을 조정하지 않는다.

기존 QA는 원래의 20개 성공 평가 항목과 136개 프롬프트의 배치·위치를 복원해 실제 재생성한다. 실제 Git pull 복제본에서도 대기 중인 제안과 기존 QA의 답·인용을 함께 확인한다. 학습된 벤치마크 전체의 성능이나 통계적 일반화로 해석하지 않는다. 모든 모델 계산은 Aurora Slurm에서 수행하며 새 목표로 GPU 상한을 30분 추가한다. 개별 작업 최대 8분, 동시 프로젝트 GPU 작업은 하나로 실행한다. 실패와 재시도도 계산한다.
