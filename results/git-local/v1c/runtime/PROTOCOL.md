# Two local environments, real Qwen — pre-run protocol
Two private Git checkouts A/B and a bare Git remote on the same Aurora compute node. Each has an independent Qwen3-8B server/GPU, private index/cache and fresh QA worker processes. Shared read-only checkpoint weights; no shared index, QA responses or receipts. This is logical isolation, not a two-machine/network benchmark.
Use current production SourceStore + explicit reader.prepare_index + TeamMemoryService.ask. Test records/index/QA only; not automatic claim extraction, relation inference, approval semantics, divergent concurrent branch merges, or deployment latency. Historical source import is not retrospective approval.
Frozen original7 corpora /20 questions. Fresh inference at A initial, B clone, A pull, A restart, B pull, B restart =120 QA. Initial clone necessarily prepares its own full index once. B appends1 source/corpus; A pulls/prepares then restarts without prepare. A appends a revised version of that logical document plus1 new source/corpus; B pulls/prepares then restarts without prepare. Changed source versions preserve old hash-addressed objects. No in-place mutation of an immutable object. Four dated canary questions on the first corpus prove new/revised records are visible. No gold answers/witnesses in the runtime packet. Existing answers/ratings accessed only by the offline evaluator after output is fixed.
No document parsing/embedding on questions or restart. Delta prepare must process exactly1 then2 records/corpus; no-op0. Verify exact parsed source IDs, embedding count, independent index paths, Git tracked-files whitelist, clean status and final source equality. Existing original source objects must remain byte-equivalent.
Evaluate answer correctness and quote support separately: exact raw+answer/evidence equality permits inheritance of original source-based ratings; changed output needs source-based manual review, never auto-pass by ID. Check source ID, quote offsets, author/time, necessary evidence. Report all120, per-phase scores, canaries, fresh HTTP traces/finish reasons, provenance and failures. No tune/retry for a score.
