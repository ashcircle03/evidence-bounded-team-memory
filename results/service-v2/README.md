## 결론

기존 AttributedQA와 timeline을 한 저장소/호출 경로에 연결했다. 고정된 세 원문 합성 흐름에서
조건별 답, 승인 전·후, 과거 질문, 무관한 질문, 재시작을 실제 Qwen3-8B로 처리했다.
핵심 답과 원문 근거는 맞았지만, 검토 상태를 설명하는 세 문장의 이벤트 인용이 완성되지
않아 두 응답은 partial이다. 전체 문제 해결이나 자연 벤치마크 성능 향상을 주장하지 않는다.

원작성자 승인은 고정 fixture의 가상 Alice 행동을 재생했으며 실제 사용자의 의사를 대행하지 않았다.

## 남은 인용 한계

pending/current 응답의 미인용 문장은 “정정이 pending이다”, “원보고가 지워지지 않았다”,
“정정이 승인됐다”는 상태 설명이다. 이는 문서 원문의 문장이 아니라 검토 기록에 근거한다.
`assertion_reviews`와 `review_context`에는 실제 상태가 연결되어 있지만 기존 LangChain
구절 인용 단계는 문서 안에서 그 설명의 구절을 찾으려 한다. 모델이 답변 문장을 근거처럼
돌려준 부분은 원문 대조에서 거부했으며 가짜 인용을 붙이지 않았다. partial을 유지한다.
상태 설명 문장과 검토 이벤트를 직접 잇는 인용 계약은 남은 작업이다.

## 적용 범위

- 새 입력은 공백/줄바꿈 보존. 과거 store 형식/해시 파일은 유지하며 이미 잘린 공백은 복구 못함.
- 처리 영수증/색인은 각 checkout의 로컬 상태. 한 checkout은 단일 프로세스 소유.
- 원작성자 인증·Git 전송은 호출자 책임. native 기억 재작성이나 추가 판정 LLM 없음.
- 긴 누적 원문의 timeline direct 비교 문맥 한도, 검색 누락, 미노출 실제 Git 재검토는 미해결/미검증.
- EverMemBench·WikiContradict의 새 점수는 없음. 기존20/Ever10은 노출된 회귀 자료다.
- 기존 client venv/server conda를 사용하고 양쪽 패키지/실제 interpreter를 보존했다. 클린 재설치 검증은 별개다.
