# 조건별 답·인용을 같은 생성 결과로 반환하는 비교

124326과 같은 합성 입력 4개(독립 근거 쌍 2개 × 질문 표현 2개)로 공식 answer.generate를 실행한다. 기대 outcome, 필요한 주장 및 인용은 [기존 평가 기준](../live-versions/README.md)을 그대로 사용한다. 예외 문구를 학습하거나 추가하지 않는다.

## 레퍼런스 선택

[LangChain에서 가져온 FactWithEvidence](../../../team_memory/_vendor/langchain_citation/__init__.py)의 fact와 substring_quote를 그대로 사용하고 해당 구절을 고를 evidence_id를 함께 생성한다. 서로 다른 조건이 같은 의미의 답을 지지하면 같은 대안에 묶고, 결론이 달라지면 대안을 나누는 방식은 [Adaptive QA의 복수 답–문서 쌍](https://github.com/Shaier/Adaptive_QA/blob/f72bdb3e5d1f4bf83a3dd84596039b67ddd145e8/experiments/few_shot.py)을 응용했다. 첫 시도는 같은 결론을 이름 없는 목록으로 묶었다. 124339에서는 실패·성공도 한 목록에 들어가 2/4만 통과했다. 두 번째 형식은 Qwen이 주장마다 같은 단위의 결론값(conclusion)을 생성하고 코드는 공백·대소문자만 정리해 같은 값을 묶는다. 그 형식도 124343에서 2/4였으며, 동치인 결론을 서로 다른 문구로 적는 문제가 확인됐다. 최종 형식은 같은 생성 안에서 각 주장과 근거를 먼저 쓰고 질문의 핵심 결론이 조건에 따라 달라지는지(same_answer)와 비교 이유를 직접 반환한다. 이 필드는 생성된 주장과 같은 객체에 보존된다. 최종 형식에서 Qwen이 의미를 판정하며, 코드에서는 질문 키워드나 문장 수로 이를 다시 추정하지 않는다. 각 근거 아이디는 원래 bundle에서 조회해 조건을 전달하고 인용 구절을 원문과 대조한다. 원문 일치는 의미 지지의 충분조건은 아니다.

원래 fuzzy matching은 인접한 다른 구절을 대신 선택할 수 있어 사용하지 않는다. 기존 사후 인용은 이미 쓴 답에 출처를 붙이는 인터페이스이므로 그 출력에서 조건별 답의 동치 관계를 복구하기 어렵다. 이 경로는 처음부터 구조화해서 같은 Qwen의 한 답변 호출로 묶음과 근거를 반환한다. 기존 정정·미해결 상충 경로와 일반 QA 경로는 유지한다. ## 같은 4건에서의 결과

두 질문은 각각 “버전에 따라 어떻게 달라지나?”와 “v1과 v2에서 각각 어떻게 되나?”였다. 최종 Qwen은 오류 종료와 실패 종료에 같은 결론을 표시했고, 오류 종료와 성공 종료에는 다른 결론을 표시했다. 각 응답의 두 주장이 v1/e1, v2/e2에 개별 연결됐고 두 원문을 그대로 인용했다. 모든 공식 응답은 ok, 무인용 구절은 0개였다.

| 조건 | 124326 종전 | 124339 목록 | 124343 결론 문자열 | 124347 같은 호출에서 의미 비교 |
|---|---:|---:|---:|---:|
| 답·조건·인용·outcome 전체 통과 | 1/4 | 2/4 | 2/4 | 4/4 |
