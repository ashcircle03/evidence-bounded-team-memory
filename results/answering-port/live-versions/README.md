# 실제 Qwen 버전별 QA 점검

독립 시나리오 두 개에 같은 질문 표현 두 개를 사용했다. 각 실행에서 bundle은 질문과 두 원문 및 조건만 제공한다. 정답 라벨은 모델 입력에 없다. 비교 전 기대값은 아래와 같다.

| 근거 | 질문 1 / 질문 2의 기대 outcome | 필요한 내용과 인용 |
|---|---|---|
| v1 오류 종료, v2 실패 종료 | answered / answered | 두 버전 모두 실패. 하나의 합친 결론이면 양쪽 근거, 분리된 결론이면 각각 해당 근거 |
| v1 오류 종료, v2 성공 종료 | conditional / conditional | v1 실패와 v2 성공을 각 조건 및 해당 원문에 따로 연결 |

답 내용, 공개 outcome, 반환 claims의 조건 및 evidence_ids를 각각 검사한다. 같은 결론을 한 문장에 합칠 때도 적용 버전과 출처를 추적할 수 있어야 한다. 구절에 버전명이 등장하는 것과 공개 conditions 필드에 버전이 들어가는 것을 따로 본다. 같은 질문 쌍이므로 4개 독립 사례의 일반화 점수로 해석하지 않는다.

현재 공식 AnsweringAdapter와 AttributedQA를 사용한다. 고정 bundle에서 검색은 실행하지 않는다. 임베딩 의존성만 MockEmbedding으로 주입하며 답 생성·문서 검사·후속 인용 호출에는 계산 노드의 실제 Qwen3-8B를 연결한다. 평가 중 운영 코드나 질문별 예외 규칙을 변경하지 않는다.

## 결과

124326은 aurora-g3에서 GPU 1개로 21분 7초 실행되어 COMPLETED/0:0으로 끝났다. 네 요청에서 기존 생성·검사 경로의 실제 Qwen 호출은 총 14회였다. 원문에서 보고한 각 버전의 실행 결과는 네 응답의 본문에 모두 등장했다. 첫 표현의 동일 결론 사례에서는 도입문이 버전별 차이가 있다고 잘못 서술했다.

| 원문 결론 | 질문 표현 | 공식 outcome / 상태 | 주장별 조건·인용 |
|---|---|---|---|
| 실패·실패 | vary by version | answered / partial | 도입문 무인용, 두 결론이 한 문장에 합쳐짐. conditions는 비고 e1·e2가 같은 claim에 연결됨 |
| 실패·실패 | in v1 and in v2 | answered / ok | 각 버전과 근거가 분리됨 |
| 실패·성공 | vary by version | answered / partial | 조건부 라벨 누락. 무인용 도입문과 한 문장에 묶인 두 인용 |
| 실패·성공 | in v1 and in v2 | answered / ok | 각 조건과 근거는 정확하나 conditional 라벨 누락 |

첫 질문은 변화가 있다는 전제를 더 강하게 암시한다. 순수한 단어 교체 효과와 질문의 화용적 전제를 구분할 수 없다. 기존 변환은 문장당 한 버전만 연결하며 무인용 문장이 있으면 conditional 변환을 건너뛴다. 두 번째 질문은 다루는 버전이 명시되었어도 버전 비교 문구 패턴이 일치하지 않는다. 두 실패는 현재 코드 및 원출력과 일치한다. 전체 기준은 1/4에서만 충족됐다. 이번 측정에 따른 규칙 수정은 없다.
