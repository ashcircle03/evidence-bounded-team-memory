# 원문 근거 패치 — 수정·실측·기각

**요청한 문제는 아직 해결되지 않았다.** 실제 오픈소스 구현을 조사해 구조를
수정하고 같은 Qwen3-8B로 두 후보를 실행했다. 재검토 일부는 나아졌지만 일반
정정과 상태 인용이 회귀해 둘 다 기본 구현에 적용하지 않았다. 기본 경로는
이전 `cup-completion-v3b`로 복구했다. 기존 양성2건 오분류와 음성2건 불필요
제안이 해결된 기본 모델을 전달했다는 뜻은 아니다.

## 실제로 가져온 부분

- [Trustcall](https://github.com/hinthornw/trustcall/blob/8c7312b591542cf9349ce00d2811e890ea6eef91/trustcall/_base.py)의 `_ExtractUpdates`/`PatchDoc`/`_apply_patch`: 전체 문서를 다시 쓰는 대신 기존 문서에 패치를 적용하는 계약. 실행에는 같은 `jsonpatch1.33`와 `jsonpointer3.0.0` 원본 패키지를 사용했다. Trustcall/LangGraph 전체를 실행한 재현은 아니다.
- [Graphiti](https://github.com/getzep/graphiti/blob/747b480ec6b12ecb718f1e2bc588b20ee36ea9c2/graphiti_core/utils/maintenance/edge_operations.py)의 관계 endpoint/type 검사, 동일 사실 처리, 시간 범위별 무효화: 출처·범위가 다른 사실을 무조건 정정하지 않는 검사 구조를 우리 결정/근거 참조에 맞게 적용했다. Graphiti 서비스를 설치·재현한 것은 아니다.
- [vLLM0.8.5 구조화 출력](https://docs.vllm.ai/en/v0.8.5/features/structured_outputs.html): `guided_json`을 실제 HTTP 요청에 전달했다. LlamaIndex의 `additional_kwargs`가 per-call 설정을 덮는 문제는 별도 설정 복사로 해결했고 HTTP 경계 검사로 확인했다.
- [Zep 논문](https://arxiv.org/abs/2501.13956)의 시간·원문 출처 보존을 참고했다. 결정 재검토 정확도까지 이 논문이 보장한다는 해석은 하지 않았다.

파일별 의도·동작·한계는 [설계 문서](../../docs/source-patch-design.md)에 있다.
새 프롬프트만 비교한 실험이 아니다. 원문만 보는 추출 단계, 수정 가능한 필드,
실제 패치 적용, 타입에 따른 제안 생성, 실패/보류 기록, 구조화 디코딩을 바꿨다.

## 비교 조건

같은 고정37개 QA 출력: 기존20 + 알려진 합성11 + 추가 합성6. 그중 상태 적용을
묻는8시점을 따로 본다. Qwen3-8B의 같은 revision, nonthinking/temp0,
같은 원문·질문·기존 키·QA reader. 모델에 정답 키를 주지 않았다. 두 실행 모두
GPU1·conda·Slurm12h, node 지정 없음, 유료 API 없음. 임시 저장소만 계산 노드의
`/local_datasets`로 옮겨 공유 파일시스템 대기를 줄였다. 원문·제안·투표·스냅샷과
모든 실제 모델 입출력은 회수했다. 반복 개발셋이며 독립 사람 평가나 자연 QA
전수 벤치마크가 아니다. 아래 의미 판정은 구현한 AI가 원문을 보고 수행했다.

| 항목 | 이전 v3b | v1 값/조건 패치 | v2 결정 근거 참조 패치 |
|---|---:|---:|---:|
| 기존20 핵심 답+필요 근거 | 20/20 | 20/20 | 20/20 |
| 양성2, 올바른 재검토와 원문 근거 | 0/2 | 0/2 | 2/2 |
| 음성2, 불필요 제안 수 | 2 | 0 | 0 |
| 음성2, 올바른 근거로 처리 완료 | 0/2 | 0/2 | 1/2 |
| 원래 정상인 공존에서 새 불필요 제안 | 0 | 0* | 1 |
| 상태8, 정정 관계·적용·검토 인용까지 보존 | 8/8 | 4/8 | 2/8 |
| 상태8, 답의 값·투표 상태만 비교 | 8/8 | 4/8 | 7/8 |

`*` v1 공존 비교는 형식 오류로 실패했다. 제안이 없다는 사실을 올바른 판단으로
세지 않았다. v1 음성도 잘못 추출한 행동/조건 때문에 우연히 no-op이 된 것이어서
근거 있는 기각으로 세지 않았다. v2 음성1건은 출처ID 오류라 성공이 아니다.

상태8의 두 행을 혼동하면 안 된다. v2는 사실 정정4종을 `reconsider`로 바꿨다.
그 잘못된 객체에 대한 거절/충돌 투표를 인용해 값이 우연히 맞아도, 원래 정정의
승인·거절 상태가 보존된 것은 아니다. **값·투표 표면만 보면7/8이지만, 요구한
정정 관계와 그 상태 근거까지 보존한 것은 Cedar의2시점뿐**이다. 이는 같은8건을
다른 분모로 합치거나 결과가 나쁜 사례를 제거한 점수가 아니다. 구문상 인용
offset/hash가 유효하다는 검사와도 별개다.

## 왜 기각했는가

v1은 과거 결정의 **근거**를 `value`로 받으려 했지만 모델이 `disabled` 같은
행동을 넣었다. 새 정책은 `conditions`만 바꾼 것으로 해석돼 재검토가 누락됐다.
writer에서는 version5 증거로 version4의 가능 여부를 true로 바꾼 잘못된
delta가 생겼다. JSON/필수 필드 오류로3개 비교도 실패했다. 정정 제안이 만들어지지
않은 경우의 상태 실패는 실제 승인 후 reader 오류와 구분했다.

v2는 값을 재요약하지 않고 결정/근거의 원문 참조를 별도 필드로 두었다.
기존 사실 비교 입력은 성공적으로 실행된10건에서 v3b와 정확히 같았다.
그러나 추출기가 일정·온도·보관기간·간격·측정 결과를 이유 있는 결정으로
오인했다. 타입 검사는 잘못된 입력 타입을 일관되게 처리했을 뿐 의미 오류를
고치지 못했다. 특히 온도 정정이 재검토로 바뀌면서 소유자가 approve해도
45C 정정 적용으로 해석되지 않았고, QA는40C와 pending이라고 답했다.

| 확인한 사례 | v2 실제 결과 |
|---|---|
| Writer version4→5 | 올바른 재검토; QA도 병렬 커밋 시험 근거 회복 |
| Cache 정책 변경 | 올바른 재검토; QA에는20초 삭제 조건이 여전히 빠짐 |
| Writer 단순 속도 향상 | placeholder source ID로 처리 실패; 성공한 음성 아님 |
| Product-image cache | unchanged/no patch로 불필요 제안 억제 |
| JPEG/PNG 다른 조건 | 측정을 결정으로 오인해 새 불필요 재검토 |
| 일정·온도·보관기간·간격 정정 | 4종 모두 재검토로 잘못 우회 |

따라서 **현재 Qwen 설정과 추출 계약에서 ‘결정과 명시적 판단 근거’를 식별하는
단계가 병목**이라는 결론이다. 모델 자체의 한계인지 추출 계약의 한계인지는
이 비교만으로 분리하지 못했다. 타입 검사를 더 붙이면 해결된다고 주장하지 않는다.

## 결과 파일과 복구

- v1: [실제 출력·근거](v1/cases.md), [문항별 판정](v1/ratings.json), [기각 결정](v1/decision.json), [패치 검사](v1/patch-verification.json).
- v2: [실제 출력·근거](v2/cases.md), [문항별 판정](v2/ratings.json), [관계별 원문 대조](v2/relation-audit.json), [기각 결정](v2/decision.json), [패치 검사](v2/patch-verification.json).
- 각 폴더의 `freeze.json`, `runtime/`, `calls.jsonl`, `result.json`, `verification.json`, `dispatch.json`, `server.json`에 고정 패킷과 실행 증거가 있다.
- [복구 재생 검사](restoration.json): 기본 service와 QA 파일이 v3b와 같은지 확인하고, 이전 실제 비교11건 및 검토 인용16건을 재생했다. **새 모델 QA를 추가 실행했다는 뜻은 아니다.**

실제 작업120393은10분04초·220호출,120394는11분10초·236호출.
둘 다 Slurm `COMPLETED/0:0`, 프로그램complete, 패킷/입력해시 확인 완료.
합계 **21.23 GPU분·456모델 호출**, 실패 후보와 준비 시간 포함. 재시도하거나
후속 작업을 남기지 않았다. 로컬 계약 검사309개는 모델 성능 점수가 아니다.

현재 기본 서비스는 v3b로 복구했다. `source_patch.py`, `decision_patch.py`는
실패 후보의 검토/재현용이며 기본 경로에서 호출하지 않는다. 기본 경로에 추가된
선택적 진단 필드는 기존 모델 출력에 없으면 아무 동작도 하지 않는다.
