# records 수정 결과와 채택 판단

**저장 손실은 줄였지만 기존 정답 연결을 모두 보존하지 못했다. 수정안은 선택 가능한 후보로 남기고 기본 추출기를 교체하지 않는다.** 전체 내용을 잘 복사하는 것과 뒤 모듈이 활용할 수 있는 주장–조건–이유 연결을 만드는 것은 별개다.

동일한 원문 68개, 동일 Qwen3-8B 리비전·temperature 0·seed 42·non-thinking·출력 2,048토큰으로 비교했다. 정답과 평가기 파일은 기존 v3 해시 그대로다. 기존 simple/grouped 136개 실제 출력은 재사용했고, 후보 68개만 새로 실행했다. QA 질문/추론은 포함하지 않았다.

## 구현한 것

- **부모 주장 안에 문맥을 배치:** root/details/condition/basis/time/subject를 중첩 출력한다. LlamaIndex SchemaLLMPathExtractor의 중첩 타입과 항목별 검증·제거 방식을 records에 맞게 변형했다. 해당 KG 추출기를 그대로 실행한 것은 아니다.
- **구절별 원문 위치:** LangExtract Resolver를 실제 호출해 지정된 원문 segment 안에서 정확히 정렬한다. 같은 시간이 여러 문장에 나와도 위치를 구분한다. fuzzy 보정은 하지 않는다.
- **개별 주장의 상태 속성 유지:** 한 묶음 안의 제안과 미승인 관찰에 각자의 stance를 저장한다. 묶음 대표 stance로 덮어쓰지 않는다.
- **부분 실패 보존:** 잘못된 구절을 격리하고 나머지 유효한 추출을 보존한다. 실패 이유와 원문은 남긴다. 이번 실제 출력은 모두 정렬에 성공했으므로 부분 실패 처리 효과 자체는 이번 모델 비교로 입증하지 않았다. 해당 동작은 계약 테스트로 확인했다.
- **비내용 분리:** 인사/응답/형식 구절을 ignored에 표시하되 원문은 보존한다. 이것은 모델 판단이므로 잘못 제외한 내용은 누락으로 채점한다.

참고 구현: [LangExtract Resolver](https://github.com/google/langextract/blob/main/langextract/resolver.py), [추출별 attributes](https://github.com/google/langextract/blob/main/langextract/core/data.py), [LlamaIndex SchemaLLMPathExtractor](https://github.com/run-llama/llama_index/blob/main/llama-index-core/llama_index/core/indices/property_graph/transformations/schema_llm.py). 정확한 설치 버전/해시는 [references.json](references.json)에 있다.

내용 재현 100%는 ‘내용을 어디엔가 보관했다’는 뜻이지, 올바른 역할·관계·상태를 모두 구성했다는 뜻이 아니다. 원문 바이트와 메타데이터도 68/68 보존했고 실제 append→재시작→reader 전달을 통과했다. 여기서 reader 전달은 구조와 출처가 도착한다는 검사이며 Qwen QA 정답 검사가 아니다.

불필요한 추출 역시 한 숫자로 성공이라고 할 수 없다. 정답 단위와 일치하지 않는 출력 행은 20→7, 잘못된 타입 연결은 26→16으로 감소했다. 그러나 **정답의 독립 주장에 대응하지 않는 claim 행은 25→27**, 인사 등이 포함된 행은 8→8, 독립 기록을 합친 쌍은 4→5였다. 원문 사실을 완전히 허구로 생성한 행과, 조건/이유를 불필요한 독립 주장으로 만든 행을 혼동하지 않았다.

## 원출력으로 확인한 원인

| 사례 | 실제 원출력 | 판정 |
|---|---|---|
| e01-full / e03-partial | `For chilled parcels…`, `For cracked containers…` 전체를 root에 복사하고 `condition: []` | 내용은 있지만 조건 관계가 없다. 저장기가 지운 것이 아니라 모델 출력부터 비어 있다. |
| e04-full / e04-partial 등 | 제안과 `This trial is not approved.`를 서로 다른 root로 출력 | 각 stance는 보존하지만, 미승인이 어느 제안에 붙는지 연결을 잃었다. |
| e05-full / e05-partial | `Recorded event time: on Tuesday.`를 별도 root로 만들고 시간을 그 root에 연결 | 실제 완료 주장에 붙어야 할 시간이 고립됐다. |
| m03-partial | saline 조건을 올바른 금지 주장뿐 아니라 freshwater 허용 주장에도 연결 | 조건의 적용 범위를 확대했다. 기존 완전 정답이 틀려졌다. |
| n03 | 문장 분할이 `etc.` 뒤를 잘라 `in the future`를 다음 segment에 두었고, 모델이 이를 서로 다른 root로 복사 | 이유의 필수 범위가 분리되어 누락됐다. segment를 단순 위치 표시가 아니라 quote의 경계로 강제한 입력 계약도 원인이다. |
| n10 | `I've reviewed the document.`를 ignored/acknowledgement로 제외 | 실질적인 검토 이력을 사교적 응답으로 잘못 분류했다. |
| n12 | `this morning`, `In the afternoon`을 root 문장에만 남기고 time 목록은 비움 | 이전에 맞힌 시간 연결 두 개를 잃었다. |
| n13 | 같은 인사 구절이 root와 ignored에 동시에 등장 | JSON 형식 검증과 정확한 인용만으로는 추출 항목 사이 의미 일관성을 보장하지 못한다. |

자연 기록 14개 중 12개는 condition/basis/time/subject 목록이 전부 비어 있었다. 일부 method/caveat는 claim 표현에서 채점되므로 ‘연결 점수 전체가 0’이라는 뜻은 아니지만, 문장 복사가 원자 주장과 역할별 연결을 대체하고 있다는 직접적인 징후다. 68개 모두 정상 stop으로 끝났으며 토큰 상한에 잘린 출력은 없었다. 이 실패를 출력 잘림 탓으로 돌릴 근거는 없다.

## 레퍼런스 적용에 대한 판단

**정확한 구절 정렬과 속성 보존은 유효한 저장 기반이다. 그러나 중첩 JSON 구조만 가져와서는 레퍼런스가 의도한 의미 관계를 얻지 못한다.** 이번 후보는 빈 문맥 목록과 문장 전체 root를 모두 허용하므로, 유효한 JSON을 만들어도 연결을 구성하지 않아도 된다. LlamaIndex의 typed path 검증을 참고했다는 사실이 우리 records의 완전성까지 보장하지 않는다.

또한 원문 위치를 정확히 찾으려는 segment 설계가 `etc.`처럼 문장 경계 인식이 틀린 경우 추출 단위를 제약했다. 위치 정렬 도구와 의미 단위를 동일시한 부분은 고쳐야 한다. LangExtract가 이 형태의 sentence 경계를 요구한다고 해석하면 안 된다.

유지할 기반은 **불변 원문, 정확한 위치, 추출 단위별 속성, 명시적인 부분 실패, 저장 후 동일성**이다. 현재 후보 전체의 기본 채택은 보류한다. 이후 수정 대상은 새로운 검사 모듈이 아니라 **입력/추출 계약의 의미 단위와 연결 표현**이다. 문장 경계와 의미 단위를 분리하고, 주장 안에 포함된 조건의 별도 연결 누락과 검토 이력의 잘못된 제외를 다뤄야 한다. 이번 결과를 보고 정답, 판정 기준, 사례별 출력 선택 규칙을 바꾸지는 않았다.

## 검증·재현

- 관련 단위/계약 검사 100개 통과.
- Aurora job 122986: COMPLETED, ExitCode 0:0, GPU 1개, 실제 24분 14초(24.233 GPU분). 모델 준비와 모든 실행 시간 포함.
- 새 실제 모델 호출 68개, 유료 외부 API 호출 0개.

- 고정 평가기로 기존 136개 출력의 점수를 모두 정확히 재현.
- 비교 스크립트의 Python tuple과 과거 JSON list 비교 오류만 직렬화 정규화로 수정했다. 원본 스크립트와 [수정 기록](comparison-compatibility-fix.json)을 남겼으며 정답·채점·채택 기준은 바꾸지 않았다.
- 합성 54개는 18개 이야기의 근거 변형이며, 자연 14개는 실패 사례에서 골랐다. 일반화 성능이나 독립 표본 68개의 추정으로 해석하지 않는다.
