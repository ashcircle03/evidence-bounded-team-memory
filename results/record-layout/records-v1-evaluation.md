# records v1의 저장 계약과 공개 평가

원문과 기존 그래프는 기본 입력으로 계속 사용할 수 있다. QA-SRL 추출을 사용하는 호출자는 같은 원문에서 나온 술어 위치와 질문·답 출력을 선택적으로 전달할 수 있다. [실행 예제](../../examples/records_argument_roundtrip.py)는 DB를 다시 열고 두 역할과 출처를 복원한다.

## 보장하는 값

- 원문, 출처 ID, 작성자·발화자, 기록 시각, 원문 내 문자 위치를 저장한다. 작성자와 행동 주체는 별도 값이다. 표는 기존 행·열·헤더 좌표를 따른다.
- 선택 필드 `record_arguments`의 버전은 `records.arguments/v1`이다. 각 항목은 술어 구절, 역할 질문, 답 구절을 가진다. 제공된 템플릿이 질문을 유일하게 복원하면 원래 슬롯 표기도 보존한다. 위치는 원문 기준 0부터 세는 반열림 문자 구간이다.
- 숫자·대상·조건을 재작성하지 않는다. 같은 답 구절이 여러 번 등장해 위치를 단정할 수 없거나 원문에 없으면 건너뛴다. `skipped`는 입력에서 건너뛴 항목 수다. 값이 0이어도 모델이 모든 동작을 찾았다는 뜻은 아니다. 부분 실패가 이웃 동작이나 원문 저장에 미치는 영향을 검사한다.
- `model_extracted_unverified`는 추출의 자격이다. ‘누가 승인했는가’에 대한 모델 답은 승인 이벤트가 아니다. 날짜·주체·이유가 생략된 문장의 실제 사실성을 이 모듈이 보증하지 않는다.
- 공식 append와 snapshot 재조회 후 동일한 구절을 보내며, 선택된 증거 범위 안에 술어와 인자가 함께 있는 연결만 입력에 싣는다. 검색 자체의 recall과 최종 QA 품질은 이번 평가 범위 밖이다.

## 고정 사례

기존 48문서에서 저장 및 재시작 후 원문·그래프를 비교했다. 저장된 원출력이 있는 22문서의 명시적 연결 61개가 모두 전달됐다. 누락됐던 행위자 2건·수동태 대상 2건·전치사 대상 1건이 복원됐고, meeting-08의 기존 명사구도 유지됐다. meeting-07의 잘못된 discuss 구절, meeting-10의 확인되지 않은 승인 주체도 원출력에 있었다. 이 오류 때문에 자동 연결을 기본값으로 승격할 수 없다. 68문서 회귀에서는 문서별 기존 정답 51개와 오연결 19개, record 해시가 모두 보존됐다. [원문 구절과 출처](records-storage-gate.json) · [68문서 회귀](regression.json)

## 공개 개발 자료와 채점

QA-SRL Gold Standard의 Wikinews·Wikipedia 공식 개발 문장 1,000개만 추출기에 전달했다. 정답 술어·역할 질문·답 위치는 평가기에만 전달한다. 사람 주석의 토큰 구간과 재구성된 문자열이 다른 3개는 원본 인덱스로 채점한다. Causality Treebank 개발 140문장 중 단일 if/unless 선행절과 명시적인 단일 결과절이 있는 49개를 평가한다. 모호한 결과절 7개, 단일 명시적 if/unless가 아닌 75개, 중첩·복수 관계 9개를 제외했다. Treebank 내부 CONDITION 라벨 자체를 적용 조건으로 간주하지 않는다. 한국어·표의 일반화는 이 두 영어 공개셋으로 평가할 수 없다. [QA-SRL Gold](https://github.com/plroit/qasrl-gs/tree/f7c64ae9b6fe48ff3910c3e59850a12ec278bf83) · [Causality Treebank](https://github.com/springto/Fine-Grained-Causality-Extraction-From-NL-Requirements/tree/0410828ae3f0b3a9b4beeb4d719cb399b650f7e5)

공통 엄격 점수는 같은 술어 위치·역할·답 구절을 모두 요구한다. 기존 broad claim에 자동 검출한 동사가 하나만 있을 때만 그 동사를 대응시킨다. 기존 subject는 추출 프롬프트의 affected object 정의에 맞춰 R1로 읽고, 시간과 이유는 when과 why로 읽는다. 조건과 시간은 별도다. 명시적으로 저장하지 않은 행위자에는 점수를 부여하지 않는다. raw 비교에서는 정렬할 수 없는 고유 예측도 오탐에 포함한다. 합친 후보는 기존과 참조 연결의 합집합이고 같은 연결은 한 번 센다. 조건 평가는 선행절 원문 전체와 결과절 내부의 동작 위치를 요구하며 동일 문서에서 여러 예측으로 점수를 중복 획득할 수 없다. 양성 조건 표본에서의 precision이므로 무조건 문장의 오탐률을 추정하지 않는다.

공식 QA-SRL Gold 평가기 배포본은 없는 함수 get_paraphrase_score를 import한다. 동일 패키지의 is_paraphrase로 이름만 연결한 호환 실행을 별도 보고한다. 이 평가는 금본위 술어별로 동작하며, 표면 슬롯을 생성하는 참조 방식에만 의미가 있다. 공통 엄격 비교는 누락 술어와 과잉 술어를 모두 포함한다. 원본 슬롯 해석에는 같은 연구 계열의 QANom get_slots와 question_to_sem_role 구현을 사용했다. 원 논문에서 QA-SRL 학습은 Fitzgerald 2018, 평가는 2020 gold를 사용했다. 체크포인트가 실제로 소비한 개별 배치와 Qwen 사전학습 데이터는 확인할 수 없다. 공개 학습 분할의 중복 검사는 아래에 기록했다. [원 논문, 표 2](https://aclanthology.org/2022.emnlp-main.528/) · [역할 평가 구현](https://github.com/kleinay/QANom/tree/2bce70e8a39b40157ba97f38e1a8ae7619b30162)

기존 48문서의 원래 정답 단위로 확인한 기본 그래프는 정답 10개, 오연결 24개가 문서별로 동일하다. 새 QA 역할을 추가로 저장하면 기존 그래프 자체는 보존되지만 모델이 잘못 붙인 논항도 노출될 수 있어 별도로 판정한다. 22문서에 원출력을 재생했고 나머지 26문서는 기존 입력 호환성을 확인했다.

공개 평가용 변환 코드는 참조 개발 결과와 Qwen 두 건의 저장 호환성을 확인하면서 정리했다. 이 비교는 개발 평가다. [입력·평가 코드 버전](records-public-run.json) · [공통 채점 코드](../../evaluation/record_layout/public_score.py)

팀원은 저장소 루트에서 `python -m examples.records_argument_roundtrip`으로 저장과 재조회를 확인할 수 있다. 입력에 선택 필드가 있으면 갱신된 source schema를 사용하는 소비자와 함께 배포한다. 원문만 있는 기존 저장소는 마이그레이션 없이 읽는다.

공개 학습 분할과 문장을 추가 대조했다. QA-SRL Bank 2.0의 orig·expanded 학습 파일은 각각 44,482문장, QANom 공개 학습 파일은 7,114개 고유 문장이다. 개발 1,000문장과 같은 문장 ID는 없었으나, 소문자화와 공백 정규화 후 **같은 개발 문장 2개**가 세 학습 분할에서 모두 발견됐다. 개발 결과에는 이 두 문장이 들어간다. 이는 공개 학습 분할에 대한 비교이며 실제 학습 배치 또는 사전학습 전체를 재구성한 결과는 아니다. [중복 ID와 데이터 해시](public-data-overlap.json)

영어 1,000문장에서 참조 모델의 답 구절 언급 7,416개 중 4,896개는 원문에 유일하게 정렬됐고, 167개는 같은 구절이 반복됐으며, 2,353개는 같은 토큰열을 찾을 수 없었다. 유일한 위치를 찾지 못한 항목은 근거 링크로 저장하지 않는다. 동사 호출 2,573회 중 447회에서 종료 토큰 없이 생성이 끝났다. 토큰 한도가 개별 오류의 원인인지는 별도 인과 실험 없이 단정할 수 없다. [구절 진단](public-reference-alignment.json)

전체 테스트 실행에서 535건이 통과했고 로컬 HTTP 포트 바인딩 제한으로 한 건이 실패했다. 해당 검사는 정상 루프백 환경에서 단독 재실행해 통과했다. records·계약·관련 adapter를 골라 재실행한 검사는 146건 모두 통과했다.

## 결과 및 배포 판단

Slurm 124911은 aurora-g4에서 GPU 1개로 28분 28초 실행되어 COMPLETED/0:0으로 끝났다. 프로그램 종료와 입력 해시, Qwen 결과 1,049개의 고유 ID를 확인했다. 참조 모델은 술어 2,688개를 처리했고 Qwen은 문서당 1회, 입력 1,238,811토큰과 출력 143,631토큰을 사용했다.

| 방식 | 개발 1,000문장 동작 F1 | 동작·역할·구절 F1 (원출력 → 저장) | 저장 후 정밀도 / 재현율 | 조건 49건 복구 | 조건 정밀도 / 재현율 |
|---|---:|---:|---:|---:|---:|
| 기존 Qwen records | 43.1% | 3.7% → 3.9% | 16.2% / 2.2% | 29 | 67.4% / 59.2% |
| QA-SRL 참조 | 93.4% | 31.3% → 37.1% | 53.4% / 28.5% | 19 | 90.5% / 38.8% |
| 결합 후보 | 80.8% | 29.9% → 35.6% | 45.0% / 29.5% | 35 | 54.7% / 71.4% |

참조 방식의 저자 평가기 호환 점수는 gold 술어 기준 unlabelled argument F1 52.7%, labelled argument F1 39.5%다. 공통 엄격 F1은 배포용 보조 연결의 효용을 측정한다. 기존 Qwen의 자연어 주장에 행위자가 들어있더라도 별도 역할과 위치를 구성하지 않으면 점수를 얻지 못하므로, 3.9%를 팀 기록의 독해 정확도로 해석할 수 없다. 엄격 채점에서 참조의 저장 후 상승은 원문 위치를 확정할 수 없는 출력을 제외하며 정밀도가 개선된 결과다. [원출력·저장·역할별 P/R/F1](public-dev-comparison.json)

조건별 채점에서는 한 정답을 중복 검출한 추가 연결도 FP에 들어간다. 이를 분해하면 기존 방식의 FP 14개는 중복 6개와 대상·구절 오류 8개, 결합 방식의 FP 29개는 중복 19개와 오류 10개다. 중복을 무시해도 정밀도는 각각 78.4%와 77.8%로 결합의 개선을 확인할 수 없다. 참조 단독은 중복 0개, 오류 2개였지만 필요한 조건 30개를 놓쳤다. [오류 분해](public-condition-errors.json)

공개 입력 1,049건을 각각 공식 DB에 넣어 다시 열었다. 저장을 허용한 연결 4,866개 모두가 재조회 및 원문 전체를 근거로 전달받은 다음 모듈의 입력에서 복원됐다. 불완전하거나 유일하게 정렬할 수 없는 입력 2,629개는 건너뛰었고 동일한 연결은 한 번만 보관했다. 이 검사는 검색이 이미 해당 문서를 찾았을 때의 전달을 검증한다. [재조회 결과](public-dev-roundtrip.json)

**배포 결정은 기존 records를 기본값으로 유지하고 역할 저장을 선택 기능으로 제공하는 것이다.** 참조 단독은 meeting-08을 잃었고 결합은 회귀 사례의 새 오연결과 조건 정밀도 하락이 관측됐다. 자동 추출의 기본값 후보가 모두 개발 단계에서 탈락해 공식 테스트셋을 소비하지 않았다. 독립 테스트 성능 주장은 보류한다. 팀 배포본은 0.2.1+records.1 wheel과 저장·재조회 예제이며 공개 패키지 레지스트리나 GitHub 새 태그 배포는 수행하지 않았다.
