# CUPMem 서비스 통합 개발 결과

원문 입력 → CUPMem 갱신·검색 → 근거 복원 → 재검토 제안 → 작성자 검토 → QA를 연결한 개발 실행이 완료됐다. 저장된 검색 결과에 독해만 다시 적용했던 이전 실행과 달리, 이번에는 새 엔진과 저장소에서 전체 흐름을 수행했다. UI나 MCP는 포함하지 않는다.

`119817`은 Aurora 계산 노드에서 conda를 활성화해 실행했으며 Slurm `COMPLETED / 0:0`, 프로그램 `complete`, 제출 파일·실행 코드·입력 해시를 확인했다. [구현 명세](../../../docs/cupmem-service-v1.md), [입력](../../../evaluation/cupmem/service-inputs.json), [사전 판단 기준](../../../evaluation/cupmem/service-expected.json), [동결 해시](../../../evaluation/cupmem/service-freeze.json)는 결과를 보고 변경하지 않았다.

## 어떤 입력을 처리했나

기존 개발용 합성 Cedar 기록 두 개와 무관한 Birch 기록 하나다. 모델에는 원문·작성자·시각·위치를 주었으며, 정답이나 사람이 추출한 결정·조건은 넣지 않았다.

1. Cedar는 한 프로세스에서 배치당 40초였다. 배포 환경이 한 프로세스만 허용해 추가 실험을 중단했다. 감사 폴더는 `Cedar-audit`다.
2. 배포 환경이 네 프로세스를 허용하게 됐다. 네 프로세스에서는 12초였고 이전 한 프로세스 측정은 그대로 유효하다.
3. 별개 Birch 프로젝트의 회의실이 B201에서 B302로 바뀌었다.

두 번째 입력을 반복해서 넣고, QA 3회를 수행한 뒤 가상 원작성자의 명시적 `review(..., approve)`를 호출했다. 그 후 세 번째 기록을 넣고 QA 2회를 수행했다. 자동 승인이나 실제 사람의 승인 실험이 아니다.

## 재검토와 QA 결과

| 확인 항목 | 실제 결과 | 판단 범위 |
|---|---|---|
| 과거 결정 재검토 | 한 프로세스 제약에 따른 실험 중단과 새 네 프로세스 허용을 연결한 `reconsider` 제안 | 과거 결정·이유·바뀐 조건의 원문 구절을 선택했다. |
| 조건이 다른 측정의 공존 | 40초·한 프로세스와 12초·네 프로세스의 `coexist` 제안 | 두 관측을 보존했다. 재검토만 승인했고 공존 제안은 `pending`으로 남았다. |
| 무관한 기록 | Birch 입력에서 제안 0개 | 음성 사례 하나의 결과이며 일반 오탐률이 아니다. |
| 중복 기록 | 기존 접수 결과 반환, 추가 모델 호출 0회 | 새 제안이나 원문을 중복 생성하지 않았다. |
| 승인 처리 | 지정한 원작성자 호출 뒤 재검토만 `approved` | 원문 세 개는 그대로 보존됐다. |

| 질문·시점 | 최종 답 | 원문 인용 |
|---|---|---|
| 검토 전: 조건별 실행 시간 | 한 프로세스 40초, 네 프로세스 12초 | 두 측정 문장 각각 인용 |
| 검토 전: 감사 폴더 | `Cedar-audit` | 기존 기록의 폴더 문장 |
| 검토 전: 중단 이유와 바뀐 조건 | 기존 한 프로세스 제약 → 네 프로세스 허용 | 기존 중단 이유와 새 허용 문장 |
| 검토 및 무관한 입력 후: 실행 시간 | 한 프로세스 40초, 네 프로세스 12초 | 두 측정 문장 각각 인용 |
| 검토 및 무관한 입력 후: 감사 폴더 | `Cedar-audit` | 동일한 기존 폴더 문장 |

질문 **3종, 5회 호출** 모두 고정 기준의 답과 인용 요건을 충족했다. 서로 다른 5개 사례의 정확도라는 뜻은 아니다. 인용 8개 모두 원문 문자 위치가 일치했고, 실제 독해 요청에 해당 구절이 있었으며, 반환한 원출력이 실제 모델 응답과 일치함을 확인했다. 10개 API 작업의 상태는 모두 `ok`였다. 의미 판단은 개발자 한 명의 수동 검토이며 독립된 블라인드 평가가 아니다.

같은 실행의 중간 CUPMem 답은 실행 시간·폴더 질문 4회에서 요청한 값을 주지 않고 전제가 오래됐다고 답했다. 추가 독해는 이 값을 원문에서 복구했다. 중단 이유 질문은 중간 답에도 필요한 내용이 있었다. 이 내부 비교는 최종 독해의 역할을 보여주지만 독립된 베이스라인 비교나 전체 CUPMem 성능 평가가 아니다.

## 남아 있는 한계와 설계 판단

이 서비스는 다음 개발의 실행 가능한 출발점으로 유지한다. 공식 CUPMem의 기억 작성·갱신·검색과 임베딩을 재사용하고, 원문·승인 기록을 별도로 보존한 채 기존 독해·인용 처리로 연결하는 경로가 이 사례에서 작동했다.

재검토 설명에는 “invalidates the earlier decision”이라는 표현이 남았다. 전제 변화는 재검토 근거지만 과거 결정을 자동으로 무효화하는 것과 다르다. 반환 상태는 검토 전 `pending`이고 원문을 삭제하지 않았으나, 설명까지 완벽하다고 보지 않는다. 공존 제안의 `new_condition`은 배포 허용 구절을 인용하며 실제 네 프로세스 측정 조건은 `incoming` 구절에 있다. 근거 역할 배정의 정확성은 위치 검사만으로 보장되지 않는다.

원문이 적어 실제 최종 독해 입력에 당시 기록 전체가 들어갔다. 따라서 원문 검색의 대규모 재현율, CUPMem의 필수성, 단순 원문 독해 대비 이득은 측정하지 못했다. 원문 검색은 2,048개 문장 후보로 제한하며, 엔진 재시작은 명시적인 원형 writer 재실행을 요구한다. 현재 구현은 한 프로세스가 저장소를 소유하는 조건이다.

이번 실행은 STALE 400개 사례 재현, EverMemBench 자연 QA, 기존 20개 QA 회귀 평가가 아니다. 과거 다른 모델의 20/20을 이 서비스 성과로 합치지 않는다. SpeakerMem-R1 주 베이스라인 교체도 결정하지 않았다. 추가 실험이나 결과에 맞춘 의미 규칙 수정 없이 이번 구현 범위를 마무리했다.

## 비용과 검증 자료

| 항목 | 실측 |
|---|---|
| 모델 | Qwen3-8B BF16, thinking 비활성화, 로컬 vLLM |
| 자원 | GPU 1개 / CPU 8개 / RAM 48G, 노드 지정 없음 |
| 할당 시간 | 16분 59초, 16.9833 GPU분 |
| 서비스 실행 시간 | 508.33초 |
| 나머지 할당 시간 | 약 510.67초: 캐시 준비·서버 시작·종료 등 포함 |
| 물리적 모델 요청 | 86회, 전부 응답 완료, 외부 모델 API 0회 |
| 토큰 | 입력 183,770 / 출력 13,817 |
| QA 한 번의 호출 수 | 원형 경로 8회 + 최종 독해 1회 |
| Slurm batch MaxRSS | 2,444,736K; 전체 RAM·VRAM 피크를 뜻하지 않음 |
| 코드 검사 | 제출 전 전체 211개 테스트 통과, 서비스 직접 검사 18개 포함 |

요청별 시간의 합은 일부 병렬 호출이 있어 실제 경과 시간과 다르다. 이번까지 실패를 포함한 캠페인 사용·예약량은 473.5167/500 GPU분, CUPMem 범위는 178.4667/200 GPU분이다. 응답 품질 외에 **한 질문당 9회 호출 비용**도 후속 개발에서 다뤄야 한다.

[비용·결론 JSON](summary.json) · [Slurm·프로그램 완료 증거](accounting.json) · [로컬 동결 확인](freeze-verification.json)

`run.json.gz`와 `calls.jsonl.gz`는 실제 결과·86개 요청/응답의 원본 바이트를 그대로 압축한 자료다. 압축 전후 해시는 [artifact-manifest.json](artifact-manifest.json)에 있다. 저장소 루트에서 GPU 없이 기계적 검사를 재실행할 수 있다.

```sh
tmpdir=$(mktemp -d)
gzip -dc results/cupmem/service-v1/run.json.gz > "$tmpdir/run.json"
gzip -dc results/cupmem/service-v1/calls.jsonl.gz > "$tmpdir/calls.jsonl"
python3 -m evaluation.cupmem.service_verify \
  "$tmpdir/run.json" "$tmpdir/calls.jsonl" "$tmpdir/verification.json"
```

이 명령은 저장된 실행을 검사하며 추론을 새로 수행하지 않는다. API 연결은 [서비스 사용법](../../../docs/cupmem-service-v1.md)과 [실제 실행 코드](../../../evaluation/cupmem/service_run.py)를 참고한다.
