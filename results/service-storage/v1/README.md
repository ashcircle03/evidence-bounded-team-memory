# 질문 독립 색인 v1

원문 입력 때 검색을 준비하고 질문에서는 준비된 세대만 읽도록 변경했다. 변경 없는 문서의 분할·임베딩을 재사용한다. [설계·사용 계약](../../../docs/modules/index-lifecycle.md), [이전 감사](../README.md).

## 완료된 로컬 확인

| 동작 | 변경 전 문서 임베딩 | 변경 후 문서 임베딩 |
|---|---:|---:|
| 원문 2개 import | 0 | 2 |
| 첫 질문 | 2 | 0 |
| 반복 질문 | 0 | 0 |
| 재시작 후 질문 | 0 | 0 |
| 원문 1개 추가 | 0 | 1 |
| 추가 후 질문 | 3 | 0 |

위 수치는 실제 ReferenceQA 경로의 MockEmbedding 계수이며 의미 검색 성능이나 실제 모델 속도 측정이 아니다. [변경 후 계수](lifecycle.json), [변경 전 계수](../audit.json). 질문 자체의 임베딩은 매 질문 1회다.

- 기존 QA 20문항의 고정 근거에서 실제 요청 130개를 정확히 대조한 기록 재생: 답변·인용 보존 **20/20**. 새 추론/정답률 측정이 아니다. [문항별 비교](qa-preservation/replay.json).
- 전체 로컬 검사 445개 + 하위 검사 87개 통과. 이후 pull·초기 import 실패 복구 2건을 추가한 수명주기 검사 9개 통과(앞선 7개와 중복).
- source 패키지를 저장소 밖에서 실행한 서비스·상태 인용 검사 17개 통과. 계약 예제 24개 통과는 fixture-only다. [명령·결과](local-checks.json).
- 준비되지 않은 질문은 문서 임베딩/관계 sync 없이 INDEX_STALE. 문서 1개 추가·중복 입력·승인·재시작·게시 실패 복구를 검사했다.

## 실제 임베딩 비교

고정한 [프로토콜](PROTOCOL.md), [설정](config.json), [입력·코드 해시](freeze.json)로 Slurm **122918**에 제출했다. 이 문서 최초 커밋 시 실행 중이며 실제 모델 검증 완료로 해석하지 않는다. [제출 장부](dispatch.json).

동일한 7개 원문 집합/기존 20질문에서 frozen cabaf1f 전체 구축과 준비된 색인의 근거를 비교한다. 재시작, 문서 1개 추가, 중복 입력, 확장된 같은 corpus의 전체 구축과 증분 준비를 비교한다. 답변 LLM은 호출하지 않는다. 실제 모델 검증 결과는 완료·종료코드·입력 해시를 확인한 후 추가한다.

## 의도적으로 남긴 한계

현재 SimpleVectorStore는 새 세대 전체를 저장하고 BM25 corpus 통계도 쓰기 시 재구성한다. 문서별 캐시의 파일 I/O도 필요하다. 따라서 전체 저장 비용이 변경량에만 비례하거나 대규모 서비스가 완성됐다는 주장은 하지 않는다. 원문·기록을 Git으로 공유하고 색인은 private 파생 저장으로 두며, 중앙 서비스로 전환할 경우 저장 backend를 교체할 수 있도록 경계를 분리했다.
