# 팀 지식 파일럿 결과

**후보 모듈은 기본값으로 채택하지 않았다.** 일반 QA에서는 두 방식 모두 답과 인용을 6/10 맞혔고, 서로 다른 두 문항을 얻고 두 문항을 잃었다. 무관한 충돌 때문에 잃은 기존 정답은 없었다. 답이 실제로 갈리는 조건과 재검토가 필요 없는 조건에서 목표를 달성하지 못했다. [문항별 비교](cases.ko.md) · [집계 JSON](summary.json)

### 판단이 달라진 사례

- **후보 QA가 얻은 2건**은 PEP 680의 TOML 모듈 이름과 PEP 618의 길이가 다른 strict zip 예외다. 예를 들어 618에서 단순 방식은 원문에 없는 `strict=ValueError`를 인용했다. 후보는 조건과 예외를 함께 명시한 구절에서 `ValueError`를 반환했다.
- **후보 QA가 잃은 2건**은 PEP 597의 경고 종류와 PEP 654의 예외 그룹 처리 구문이다. 597은 `EncodingWarning`이라는 답은 맞혔지만 대명사로 시작해 그 이름이 없는 구절을 가리켰다. 654는 처리 구문 `except*` 대신 타입 `ExceptionGroup`을 골랐다. 552의 알고리즘 이름은 두 방식 모두 입력에서 검색하지 못했다.
- **실제 충돌**에서 단순 방식은 8번 한쪽 답만 전달하고 2번 인용 검증에 실패했다. 후보는 5번 한쪽 답만 전달하고 4번 인용 검증에 실패했다. 나머지 1번은 두 출처를 냈지만, PEP 654 쪽 답이 처리 구문이 아니었다. 원문 양쪽에서 정답 문자열을 볼 수 있던 9건도 결합 정답으로 이어지지 않았다.
- **개발 회귀**에서 두 방식 모두 Lizhen Zhou가 제안한 발언과 화자를 맞혔다. 다른 문항은 올바른 출처에 ‘최소 10근무일’이 적혀 있었으나 답에서 ‘최소’를 누락했다.
- **재검토**에서는 양성 10건 모두에서 두 방식이 과거 결정과 새 기록을 연결하고 재시험을 제안했다. 그중 3건은 사전 기준상 전제나 정책의 재평가가 필요했다. 음성에서도 후보는 이미 승인된 컴파일러 배포의 완료를 받자 무관한 화물 운송 결정을 재시험하자고 했다. 같은 사례의 단순 방식은 `KEEP | P1 | N1`을 냈다. 실제 파서가 이 출력을 거절해 알림은 없었고 올바른 유지 응답도 전달되지 않았다. [전체 원출력](outputs.json) · [출처와 판정 이유](review-cards.json)

### 기본값과 해석 범위

기존 인터페이스의 `ask --model`은 기존 QA 리더를 유지한다. 이 리더의 새 10문항 성능은 이번 양자 비교에서 측정하지 않았다. 새 구절 기반 QA를 사용할 때는 `--strategy simple`을 기준선으로 사용한다. `pull`의 기본 검색도 단순 방식을 유지하고 후보를 선택 옵션으로 둔다. 양성에서 순증 2건과 기존 정답 보존을 함께 요구한 사전 채택 기준을 충족하지 못했다. 높은 오탐률 때문에 현재 제안은 작성자가 검토할 초안으로만 사용한다. 제안 승인은 과거 결정 자체를 대체하지 않는다.

QA 원본은 날짜를 고정한 공개 PEP 10건이며 각 원본에 두 가지 통제 변형을 만들었다. 같은 원본에서 나온 세 조건은 독립 사건 셋으로 세지 않았다. 충돌 추가분과 재검토 양성·음성 20건은 연구자가 작성한 모의 기록이다. 팀의 실제 운영 분포에서 측정한 정확도는 아직 없다. [사전 계획](../../evaluation/team_pilot/PROTOCOL.md) · [동결한 사례와 입력](../../evaluation/team_pilot/freeze.json)

### 실행과 판정

Aurora 작업 `119269`는 RTX 3090 한 장에서 Qwen2.5-3B-Instruct BF16으로 실행했다. 2분 57초, `COMPLETED`, 종료 코드 `0:0`이었다. 생성 루프는 20.16초였다. 동결한 104개 프롬프트의 해시와 원출력을 재생했다. 각 방식 52회 기준 단순 방식은 입력 59,221·출력 433토큰, 후보는 입력 56,896·출력 405토큰이었다. 실행 중 사용자가 GPU 여유 예산을 늘렸다. 이 작업은 최초 4분 제한 안에서 한 번에 끝났다.

방식 이름을 가리고 동일 문항·조건의 같은 출력을 합친 73개 카드를 문맥 검토했다. 프로젝트를 수행한 에이전트가 단독으로 판정했다. 사전 자동 점수와 달라진 것은 단순 방식의 PEP 654 원본·무관 충돌 두 출력이다. 응답 ‘the except* syntax’와 인용이 처리 구문을 정확히 지정해 문맥 검토에서 정답으로 인정했다. 두 집계를 모두 공개한다. [자동·문맥 검토 집계](summary.json) · [검토 카드](review-cards.json)
