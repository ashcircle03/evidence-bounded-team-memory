# 설계 판단: 공통 기반은 유지하고 일반 재검토 판단을 단순화한다

2026-11-05. **현재 `context-review`를 일반적인 재검토의 기본 방식으로 채택하지 않는다.** 원문·출처·승인 상태 보존과 기존 QA는 유지한다. 재검토에서는 14B의 단순 원문 읽기를 새 비교 기준으로 두고, 명시적인 원인 참조를 추적하는 기능을 별도 구성요소로 남긴다. 이번 goal에서는 이 판단을 검증했으며 생산 모듈이나 기본값을 바꾸지 않았다.

## 판단을 바꾸는 관측

동일 Git 사건 15개 각각에 실제 재검토 대상이 있는 양성과 주제만 비슷한 결정만 있는 음성을 만들었다. 아래 성공은 대상·인용·설명의 실제 동작과 조건이 모두 맞는 엄격한 성공이다. 참조 가림은 원인 커밋 ID와 참조 제목을 가린 통제 조건이다.

| 입력 | 모델 | 단순 방식 성공 /15 | 현재 모듈 성공 /15 | 단순 방식 음성 오탐 /15 | 모듈 음성 오탐 /15 |
|---|---|---:|---:|---:|---:|
| 원문 참조 포함 | 3B | 1 | 2 | 9 | 0 |
| 원문 참조 포함 | 14B | 7 | 7 | 4 | 1 |
| 참조 가림 | 3B | 2 | 0 | 6 | 0 |
| 참조 가림 | 14B | 6 | 3 | 4 | 2 |

**3B의 실패만 보고 설계 전체가 잘못됐다고 단정할 수는 없다.** 같은 모듈도 14B에서 회복했다. 같은 정확한 근거 창을 준 단순 판단에서도 3B의 성공 1/15가 14B에서는 4/15였다. 이 두 체크포인트에서는 판단 모델과 프롬프트의 조합이 성과에 영향을 줬다. 모델 크기만의 인과 효과나 학습된 SpeakerMem-R1의 성능으로 해석하지 않는다.

**모델을 키우는 것만으로 현재 설계가 정당화되지는 않는다.** 참조를 가린 14B에서 현재 모듈은 단순 방식의 성공 6건 중 4건을 잃고, 다른 1건을 얻었다. 결과는 6→3건이며 음성 오탐은 4→2건이다. 모델은 같으므로 이 차이는 문단 선택·재확인·기권 등 현재 파이프라인을 사용하는 데 따른 결과다. 어느 단계 하나의 인과 효과를 분리한 ablation은 아니다.

원문 참조 포함 조건의 14B에서는 두 방법 모두 7건 성공하고 모듈의 오탐이 더 적었다. 따라서 명시적 참조를 이용하는 기능을 버릴 근거도 없다. 다만 공통 성공은 2건뿐이고 각 방법만 맞힌 사건이 5건씩이다. 단순 방식을 그대로 대체하면 기존 성공을 잃는다. 이 두 성공 집합을 합친 수치를 구현하지 않은 결합 시스템의 성능으로 보고하지 않는다.

## 어디에서 판단이 달라졌는가

| 관측 | 의미 |
|---|---|
| 참조를 가린 3B 모듈은 양성 15개 모두 첫 문서 비교에서 기권 | 오탐 0은 관계를 정확히 구별했다는 증거가 아니다. 모든 재검토를 막은 결과다. |
| 참조를 가린 14B 모듈은 첫 비교 3개, 구절 재확인 4개, 관측 선택 2개에서 기권 | 모델을 키워도 여러 중간 관문에서 필요한 제안이 사라진다. 나머지 6개 제안 중 엄격한 성공은 3개다. |
| 원문 14B 단순 방식은 실제 이전 결정 15/15를 골랐지만 엄격한 성공은 7/15 | 대상 선택과 정확한 설명은 별도 병목이다. 인용이 있다고 해석까지 맞는 것은 아니다. |
| 원문 14B 모듈은 대상 12/15, 엄격한 성공 7/15 | 선택한 기록의 제목이나 옛 배경 문단만 붙이는 오류가 여전히 남는다. |

문항별로는 다음 차이가 있다. [전체 원출력과 인용](cases.ko.md)을 함께 확인할 수 있다.

- **FreeBSD·git fsck:** 원문 14B 모듈은 작은 버퍼·권한 부족의 EACCES와 빈 loose 파일의 잘못된 읽기 오류를 각각 복구했다. 단순 방식은 FreeBSD의 실제 실패를 모호하게 설명했고, fsck에서는 빈 파일을 corrupt로 표시하면 안 된다는 반대 방향의 주장을 덧붙였다.
- **hook·reflog:** 14B 단순 방식은 누락된 `invoked_hook` 전달과 `lookup_commit` 변경을 설명했다. 모듈은 hook의 제목·Valgrind 로그, reflog의 최초 구현 이력을 골라 현재 재검토할 결정의 구체적 근거를 잃었다.
- **음성 range-diff:** 모듈은 출력 대상을 `stdout` 대신 설정된 파일로 보내는 과거 결정을, `--no-patch`·`--stat` 전달 누락 보고와 연결해 오탐했다. 이 원문 표현은 현재 참조 정규식이 인식하지 못해 일반 의미 비교로 넘어간다.
- **참조를 가린 음성 ASan·header:** 각각 LSAN 추적 옵션과 헤더 엄격성 검사를 실제 원인 결정 대신 재검토했다. 인용 문자열은 진짜였지만 두 구절의 관계는 틀렸다.

오탐 열은 대상이 없는 음성에서만 센다. 양성에서 설명이 틀린 제안도 안전한 제안이 아니다. 예를 들어 원문 14B 모듈의 전체 제안 13건 중 엄격한 근거를 갖춘 것은 7건이고, 나머지는 양성의 설명·근거 실패 5건과 음성 오탐 1건이다.

## 정확한 문단만 주면 해결되는가

| 참조를 가린 단순 판단 | 원문 전체 성공 | 선정 근거 창 성공 | 원문 전체 오탐 | 선정 근거 창 오탐 |
|---|---:|---:|---:|---:|
| 3B | 2/15 | 1/15 | 6/15 | 6/15 |
| 14B | 6/15 | 4/15 | 4/15 | 5/15 |

어느 모델도 선정 근거 창에서만 새로 성공한 사건은 없었다. 14B는 근거 창에서 대상 선택 자체는 8→10건으로 늘었지만 설명까지 맞은 결과는 줄었다. **검색만 고치면 해결된다는 가설은 이번 결과가 지지하지 않는다.** 정확한 구절을 받아도 이전 동작과 새 실패의 관계를 잘못 설명할 수 있다.

근거 창은 실행 전 Codex가 골랐으며 인간의 독립 검증을 받지 않았다. 축약이 주변 문맥을 제거하는 효과도 있으므로 진정한 성능 상한이라고 부르지 않는다. 이 결과만으로 더 큰 모델도 불가능하다거나 원문 전체가 항상 낫다고 단정하지 않는다.

## 유지할 부분과 바꿀 부분

| 구성요소 | 결정 | 근거와 범위 |
|---|---|---|
| 원문·출처·정확한 인용 위치 보존 | 유지 | 잘못된 해석을 원출력까지 추적하고 출처 오류를 판별하는 데 필요하다. 문자열 일치만으로 관계의 진실성을 보증하지는 않는다. |
| 작성자 승인과 미승인 제안의 구분 | 유지 | 실제 Git pull 두 검사에서 pending 상태를 보존하며 기존 QA가 유지됐다. 팀 전체 장기 협업의 검증은 아니다. |
| 기존 3B QA 경로 | 유지 | 답·상태·인용·출처가 기존 회귀 검사 20/20에서 동일했다. 미해결 양쪽 답 3개와 조건별 답 1개를 포함한다. |
| 명시적인 원인 참조 확인 | 별도 기능·비교군으로 유지 | 원문 조건에서 오탐을 줄였으나 인식 가능한 표현에 한정되고 실제 문단·설명 오류는 남는다. |
| 다단계 의미 선택·재확인·기권을 묶은 현재 일반 재검토 | 기본 채택 보류, 단순화하여 재설계 | 참조 가림에서 14B도 단순 방식보다 성공이 적고 오탐이 남는다. 작은 패치로 현 구조를 계속 정당화하지 않는다. |
| 14B 단순 원문 읽기 | 다음 재검토 실험의 기준선 | 3B보다 회복하지만 음성 오탐 4/15가 있어 자동 지식 변경에 쓸 수준으로 입증되지 않았다. QA 전체 모델 교체도 검증하지 않았다. |

다음 검증은 이 15개에 맞춘 규칙 추가보다 **새 사건에서, 단순 판단을 실제로 개선하는 한 가지 기여**를 고정해 비교해야 한다. 원문에서 이전 결정·새 관측·관련 조건을 유지하고, 확실하지 않은 제안은 출처와 함께 작성자 검토로 넘기는 방향이다. 현재 연구의 성공 기준은 더 긴 처리 단계가 아니라, 같은 새 사건과 명시한 비용에서 근거 있는 재검토를 늘리고 무관한 결정과 기존 QA를 지키는 것이다. 이번 결과는 다음 설계의 성공을 미리 입증하지 않는다.

## 비용과 결과의 신뢰 범위

| 14B 방법, 양성·음성 합 30개 | 모델 호출 | 입력 토큰 | 생성·선택 평가 토큰 | 모델 호출 경과 초 |
|---|---:|---:|---:|---:|
| 원문 단순 | 30 | 43,819 | 3,539 | 217.53 |
| 원문 모듈 | 284 | 111,264 | 1,420 | 125.95 |
| 참조 가림 단순 | 30 | 42,877 | 3,403 | 210.26 |
| 참조 가림 모듈 | 423 | 171,034 | 1,334 | 146.17 |

모듈은 더 많은 호출과 입력 토큰을 쓰지만 한 토큰의 선택 평가를 많이 하므로, 측정된 모델 호출 시간은 더 짧았다. 호출·입력 증가를 곧바로 GPU 시간 증가라고 부르지 않는다. 두 방법의 실제 비용은 같지 않으며, 같은 GPU 배치에서 기록한 시간은 서비스 처리량 벤치마크가 아니다.

이번 goal은 실패와 준비를 포함해 64.15 GPU분, CPU 전용 작업 walltime 합 31.50분을 썼다. 캠페인 전체는 191.60/300 GPU분과 71.28/100 CPU 작업분이다. 원시 실행에는 재검토 결과 306개가 있고, 잘못 축약한 두 음성 oracle의 별도 교체와 추가 진단 행을 구분해 최종 비교는 모델별 150개, 합 300개다. 6개 추론 작업은 모두 Slurm `COMPLETED`, `0:0`, 프로그램 완료와 입력 해시를 확인했다. 실패한 다운로드 1개와 첫 14B 경로 오류 1개도 자원 합계에 포함했다.

이 패널은 과거에 사용한 Git 사건 15개이고, 변형들을 독립 표본으로 세지 않는다. 한 AI 평가자가 고정 기준으로 의미를 판정했다. 완전한 맹검·독립 평가자 합의·새 사건 일반화는 입증하지 않았다. 특히 올바른 인용은 있지만 설명에서 동작·조건을 생략한 경계 사례는 엄격한 성공에서 제외했으며 항목별 이유를 공개했다. 정확한 우열 수치는 독립 재채점이 필요하다. **따라서 이번 결론은 연구 개발 방향의 결정이며, 모델이나 제품의 확정적인 성능 주장으로 쓰지 않는다.**
