# MeeQA 단일 회의 reader 지시 비교

124297의 저장된 434개 발언에서 기존 reader 입력 16개의 SHA-256을 재현했다. 124303에서 같은 Qwen3-8B 리비전·system 지시·원문·records·출력 스키마·seed·출력 예산·호출 순서를 사용하고 user 지시문만 교체했다. 기존 작업은 g1, 새 작업은 g4에서 실행했다. 예측별 노드 간 재현성은 별도로 측정하지 않았다. 새 작업은 GPU 1개, 21분 43초, COMPLETED/0:0으로 종료됐다.

| 조건 | 답 가능 4개 중 잘못 보류 | 답 불가 4개 중 올바르게 보류 |
|---|---:|---:|
| 기존 지시 + 원문 | 2 | 0 |
| 단일 회의 지시 + 원문 | 2 | 1 |
| 기존 지시 + 원문·records | 2 | 3 |
| 단일 회의 지시 + 원문·records | 3 | 2 |

네 조건 모두 답 가능 4건에서 사람 답 완전 일치 0건, 인용 위치 완전 일치 0건이었다. records 조건에서 통화량 문항을 추가로 보류했고, 직원 사기 문항의 올바른 보류를 잃었다. 원문 조건은 repo 문항의 올바른 보류를 얻었다.

16개 예측을 먼저 저장한 뒤 회의록 채택과 구매 대상 문항의 가장 짧은 사람 정답 범위와 구절을 명시했다. 두 입력 조건 모두 두 문항에서 계속 보류했다. 사람이 선택한 간접·조건부 발언을 Qwen이 충분한 답으로 받아들이는지와 extractive 형식·긴 입력의 영향을 이 실험만으로 분리할 수 없다. 이 지시는 채택하지 않는다.

## 두 발언만 제시한 후속 진단

124307에서는 동일 Qwen3-8B에 질문과 사람이 고른 발언만 주고 직접 답 / 간접·조건부 답 / 답 없음 중 하나를 고르게 했다. 회의록 수정 여부에 대한 채택 동의(③)와 25유로 제품의 구매 의향에 대한 대상 고객 조건(④)은 모두 간접·조건부 답으로 분류됐다. 두 문항의 핵심 발언은 v0.2.1에서 전달됐다. 전체 문맥에서 답과 인용을 생성할 때의 보류와 달리, 짧은 분류에서는 두 발언을 답으로 인정했다. 문맥 길이·지시·출력 과제가 함께 달라져 각 원인의 기여는 구분할 수 없다. 이 결과는 공식 answering 모듈 전체의 평가나 세 범주 전반의 정확도를 뜻하지 않는다. 이 두 사례를 근거로 records를 변경하지 않았다.
