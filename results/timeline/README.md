# 누적 기록 최소 시스템: 설계 판단

이번 비교에서 선택한 경로는 **원문 직접 읽기**다.
선택 근거는 사전에 고정한 재검토·불필요 제안·문항별 QA 보존 조건이다. **[최종 해석과 구성요소별 결정](interpretation.ko.md)**에서 음성 오탐, 관계 종류 오류, 원출력은 맞지만 검증에서 탈락한 QA를 구분한다. 이 결과만으로 실제 팀 기록 전체에서의 신뢰성을 주장하지 않는다.

| 같은 Qwen2.5-14B, 같은 원문 접근권 | 원문 직접 읽기 | 색인 추가 |
|---|---:|---:|
| 근거 있는 필요한 검토 | 8/12 | 7/12 |
| 잘못되거나 근거가 부족한 제안(반복 포함) | 14 | 12 |
| 답·출처·조건·상태가 맞는 QA 시점 | 111/140 | 111/140 |
| 자연 QA 반복 확인 | 55/60 | 57/60 |
| 모델 호출 수 | 220 | 320 |
| 입력 토큰 | 247256 | 366533 |
| 출력 토큰 | 17717 | 18999 |

색인 추가로 새로 맞힌 QA 시점은 7개, 직접 읽기가 맞혔는데 잃은 시점은 7개다.
검토가 필요 없는 흐름에서의 오탐은 직접 읽기 5/8, 색인 추가 3/8이다. 위 제안 실패 합계는 양성에서의 잘못된 관계 종류와 반복 제안도 포함한다.

140개는 20개 흐름에서 질문을 반복한 평가 시점이다. 자연 질문은 20개이며 60개의 독립 문항으로 해석하지 않는다.

채택 조건별 판정:
- 근거 있는 필요한 검토 증가: 미충족
- 불필요 제안 비증가: 충족
- 같은 QA 시점에서 기존 정답 손실 없음: 미충족
- 원문 손실 없음: 충족
- 검토 없이 승인 상태로 승격하지 않음: 충족

두 경로가 공유하는 원문 보존·구절 단위 정정·검토 기록·출처 검사는 유지한다. 색인은 위 조건을 모두 충족할 때만 선택한다. 과거의 여러 단계 의미 검증 모듈은 이 비교의 기본 경로에 넣지 않았다.

실제 Qwen 입력·출력을 Git 두 복제본으로 재생한 40개 흐름에서 입력 일치와 상태 수렴을 확인했다. 별도 3B 기존 QA는 20/20에서 답·상태·인용이 보존됐다. 이는 새로운 14B QA 성과를 대신하지 않는다.

이번 목표의 확인된 전체 Slurm 사용량은 103.45 GPU분, CPU 전용 작업 경과 시간은 0.22분이다. 준비·실패 시도도 포함한다. 호출 구간 경과 시간은 직접 읽기 17.97분, 색인 추가 19.76분이며, 이는 개별 방식에 할당한 GPU 시간과 같지 않다.

합성 작업 기록 20개와 원문을 바꾸지 않은 EverMemBench-Dynamic topic 02의 근거 확인된 QA 20개를 결합했다. 검색 대상이 작은 원문 전체 읽기 비교이며, 실제 Git의 장기 기록이나 전체 공식 벤치마크의 성과가 아니다. 제안에 대한 의미 채점은 구현한 AI의 출처 검토이며 독립 평가자 일치도를 측정하지 않았다.

작성자 승인은 조건이 맞는 실제 생성 제안에 대해서만 수행한 모의 사용자 행동이다. 승인 누락으로 원하는 최종 지식 상태에 도달하지 못한 실패와, 승인 이후 QA 실패는 [문항별 진단](decision.json)에 구분했다. 작성자 필드 검사는 실제 GitHub 계정 인증과 연결되어 있지 않다.
