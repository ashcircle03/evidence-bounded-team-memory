# 개발 실행과 호환성 확인

Aurora 작업 119554는 `COMPLETED`, 종료 코드 `0:0`, 경과 시간 12분 3초로 끝났다. Qwen2.5-14B-Instruct bf16의 실제 응답 110개가 기존 제출 코드와 현재 최소 시스템에서 같은 입력으로 재생됐다. 실제 bare Git remote와 두 복제본으로 10개 흐름·방식 조합을 검증했다. 로컬 모의 응답 검사를 모델 성과로 세지 않았다.

다섯 개발 흐름은 모두 합성이다. `natural_before` 등의 필드명으로 기록된 보존 질문도 개발에서는 합성된 고정 사실을 묻는다. 최종 평가의 원본 EverMemBench QA와 구분한다.

`unsupported_alerts=3`은 음성 오탐 2건과 양성의 잘못된 관계 종류 1건을 합친 엄격한 제안 실패 수다. 셋 모두 검토 자체가 불필요했던 것은 아니다. Maple에서는 같은 R7 조건의 40/12 불일치를 정확히 설명했지만 `conflict` 대신 `reconsider`를 반환했다. 원래 점수와 사전 채택 기준은 바꾸지 않았다.

- Cedar: 달라진 프로세스 허용 조건과 재검토 이유는 찾았다. 다중 답에 `single`을 붙이거나 원문에 없는 조건 표현·잘못된 출처를 사용해 QA가 무효 처리됐다.
- Birch: 서로 다른 입력 조건의 관측을 재검토 대상으로 잘못 올렸다. QA는 조건별 답을 보존했다.
- Maple: 같은 조건의 미해결 충돌을 `reconsider`로 분류하고 QA에서는 `conditional`로 표시했다. 직접 읽기에서는 조건 인용을 원문 그대로 복사하지 않은 오류도 있었다.
- Pine: 정정할 구절만 골랐고 승인 이후 새 값과 같은 원문의 무관한 사실을 보존했다. 승인 전 두 보고의 종류를 `conflict` 대신 `conditional`로 표시해 해당 QA 시점은 실패했다.
- Oak: 새 보고가 시험을 수행하지 않았다고 명시했는데도 미검증 상태가 바뀔 수 있다고 추론해 불필요한 검토를 제안했다. 기존 사실 QA는 유지했다.
