# 판단: 독해 불가능보다 주장–맥락 연결과 컴파일 경계가 먼저 문제다

실제 Qwen3-8B136회(68입력×2방식), 고정된 입력·정답·채점기로 확인했다. 작업122970은 Slurm COMPLETED/0:0, 서버/클라이언트 complete, 입력/코드 해시 및 실제 요청136개 재구성 검증을 통과했다. 새 모델·추가 검사 모듈·생산 코드 변경은 없다.

## 무엇을 비교했나

- 합성18개 기본 이야기 × 근거 충분/부분/없음 =54입력. 쉬움/중간/어려움 × 가용성9셀에 각각6개.
- 난이도는 단일 문장 → 인접 문장 간 연결 → 먼 범위·유사 대상·반복 구절로 사전 지정했다. 측정된 난이도 척도나 서비스 분포 추정이 아니다.
- 여기서 ‘근거 없음’은 초점 주장의 두 조건·이유·시각·한정 중 어느 것도 제공되지 않는다는 뜻이다. 주장은 여전히 있다. 없는 값을 요구하거나 추측하게 하지 않았다.
- 별도 EverMem14원문은 과거 실패를 보고 고른5사례에 속한다. 자연 n06의 잘못된 부재 라벨은 출력 열람 전에 발견해 격리했다. 해석 가능한 자연 부분 집계는13입력이다.
- `simple`은 간단한 역할/형식 설명, `ours`는 기존 그룹 추출 설명과2개 예시. 둘 다 같은 Qwen3-8B revision, non-thinking, temperature0, seed42, 출력2048토큰, guided schema, 정렬기, 저장 경로다. SpeakerMem-R1/CUPMem 원 시스템 재현 비교는 아니다.

## 근거가 충분한 경우부터 본 결과

다음은 ‘초점 주장 + 필요한 역할 연결 + 그룹 태도 + 잘못된 대상/누락 근거 추측 없음’을 요구하는 고정 부분 기준이다. 최종 QA 정답률이 아니다.

| 사전 난이도 | 입력 수 | 단순 원출력 통과 | 기존 원출력 통과 | 단순 컴파일 후 | 기존 컴파일 후 |
|---|---:|---:|---:|---:|---:|
| 쉬움 |6|0|3|0|3|
| 중간 |6|0|0|0|0|
| 어려움 |6|0|1|0|0|
| 합계 |18|0|4|0|3|

쉬운 문장에서도 실패한다. 따라서 ‘어려운 데이터라 어쩔 수 없다’고 설명할 수 없다. 반대로 같은8B가 기존 예시/설명으로 일부를 성공하므로 모델이 전혀 읽을 수 없다고도 할 수 없다. 두 방식은 공통 출력 계약을 쓰므로 이 비교만으로 모델의 본질적인 능력 한계를 확정하지 않는다.

54개를 합치면 저장 전후 통과는 simple17→17, ours30→28이다. 하지만 ours의 통과28개 중18개는 두 한정을 모두 제공하지 않은 입력이다. 이 총점으로 복잡한 기록 구성이 해결됐다고 주장하면 안 된다. 전체9셀은 [README](README.md)에 보존했다.

### 1. 입력 부족

빠진 정보를 요구하지 않은36개 부분/없음 변형에서, 두 방식 모두 이번에 지정한 withheld 값의 무근거 보완은0건이었다. 이것은 모든 종류의 환각이0이라는 뜻이 아니다. 단순 방식은 h04-none에서 다른 대상의 ‘warehouse rollout is approved’를 초점 제안 그룹에 섞은1건이 별도로 있었다.

자연 n10에는 구체적인 정책코드가 없고 n14에는 polling 선택 이유가 없다. 이런 정보는 앞선 다른 메시지에 있더라도 현재 ONE-message 입력에서는 제공되지 않는다. 이것을 추출 누락으로 채점하지 않았다. 대화 참조 해소가 필요하다면 입력/조회 계약에서 별도로 지원해야 한다.

### 2. 원출력에서의 의미 역할·대상 연결

기존 방식은 충분한 입력18개 중17개에서 필요한 구절을 원출력 전체에 남겼다. 나머지 e02-full도 `Thursday`는 추출했으며 정답 표기의 `on`만 달랐다. 그러나 초점 그룹으로 연결한 것은 고정 구절 기준6/18이었다. 핵심 병목은 상당 부분 구절 발견 이후의 바인딩이다.

- **m05-full**: `on Friday afternoon`을 뽑았지만 `The calibration event occurred`라는 별도 그룹에 붙였다. 실제 `the valve calibration finished` 그룹에는 날짜가 없다. 기록 전체에는 있고 뒤 모듈이 보는 해당 주장에는 없다.
- **m01-full**: `sector D2` 조건을 주장 없는 a그룹에, 실제 결정을 c그룹에 뒀다. 원출력의 연결 오류이며 이어서 compiler가 전체 소스를 거절한다.
- **e02-full/partial**: `because the hinge needs repair`를 `basis` 대신 `condition`으로 분류했다. 쉬운 명시적 이유에서도 실패하므로 난이도만의 문제가 아니다.
- **e01-full/e03-full**: 단순 방식은 조건·이유까지 한 문장으로 보존하지만 별도 필드로 나누지 않았다. 기존 예시가 있는 방식은 조건/주장/이유를 올바로 나눴다. 기존 입력 구성의 국소적인 이득은 실제로 존재한다.

### 3. 기록 표현·컴파일 경계

- **h05-full, h05-partial**: 원출력의 초점 주장·시간·조건 연결이 고정 기준을 통과했다. 하지만 `at 16:40`이 다른 사건에도 등장해 `Ambiguous repeated context span`으로 모든 claims가 거절됐다. 원문은 보존됐지만 구조화된 연결은 사라졌다. 이는 디스크 손상이나 입력 부재가 아니다.
- 기존 방식의 합성 compiler 거절5건 = 반복 구절3건 + orphan context2건. 정답 최소 구절을 사람이 직접 넣은 사전 검사에서도 반복 구절3변형이 거절됐다. 고유한 더 긴 구절이면 통과할 가능성까지 부정하는 결과는 아니다.
- **e04-full/partial**: 모델이 ‘시험해볼 수 있다’를 proposal, ‘아직 승인되지 않았다’를 observation으로 추출했다. 둘을 같은 그룹의 단일 stance로 만들면 unknown이 된다. 초점의 올바른 태도를 낸 합성6변형에서 mixed-stance collapse가 관찰됐다. 일부 다른 caveat 라벨까지 옳았다는 뜻은 아니지만, 그룹 하나의 stance로 모두 표현하려는 계약은 별도 문제다.
- 자연 n01에서는 의미상 맞는 완료 보고가 나왔지만 따옴표 표현 변경 등이 exact alignment를 통과하지 못해 소스 전체가 실패했다. 의미 내용이 맞음과 원문 인용이 정확함을 구분해야 한다.

### 4. 영속 저장과 전달

136출력 모두 실제 RecordsAdapter에 append하고 새 adapter로 다시 snapshot을 읽었다. 원문/그래프가 동일했고, 생성된348개 claim packet의 record_context·작성자·시각·연결 구절 범위를 확인했다. 추가 손실0건이다. 실패 그래프도 실패 상태와 원문이 그대로 저장된 결과이며, 의미적으로 올바른 기록136개라는 뜻이 아니다. 새 OS 프로세스 재시작이나 최종 Qwen QA는 이 검사 범위가 아니다.

## 평가 자체에서 발견한 문제

고정 점수는 바꾸지 않았다. 아래는 점수와 분리한 감사 기록이다.

1. **n06 라벨 오류**: `file storage solution`이 첫 문장에 있는데 unavailable로 표시했다. 출력 열람 전 격리했다. 자동 원점수에서는 두 방식 모두 이 연결을 누락하고도 통과했다. 데이터셋 정답 오류가 좋은 점수를 만들 수 있다는 실제 예다. [사전 기록](pre-output-label-audit.json).
2. **e02-full 표면 일치 과엄격**: `on Thursday`/`Thursday`를 다르게 센다. 시간 의미가 사라진 것으로 해석하지 않는다. 다만 이 사례는 별도로 basis→condition 오류가 있어 결합 실패 자체는 남는다.
3. **n13 미채점 오류**: 기존 방식이 `by requesting the interface every 10 seconds`를 condition으로 잘못 붙였지만, optional reason만 있는 부분 기준에서는 통과했다. 따라서 자동 통과를 전체 record 품질로 해석하면 안 된다. 실제 ‘방법’과 ‘조건’의 구분은 이번 자연 부분 정답의 커버리지 밖이었다.
4. **원출력 stance 점수의 합성 규칙**: frozen scorer도 compiler와 같은 group stance collapse를 사용한다. 원출력 점수의 stance 실패를 곧바로 모델의 개별 문장 이해 실패로 해석하지 않는다. [별도 진단](diagnostic-audit.json)은 focal row와 group collapse를 따로 보여준다.

n06을 제외한13개 자연 메시지의 부분 기준은 simple raw3→compiled2, ours raw4→compiled3이다. 위 n13 미채점 오류 때문에 이 수치 역시 전체 기록 정답률이 아니다. 이 실험은 실패 위치 진단을 완료한 것이며, 완전한 의미 품질 벤치마크는 아직 아니다.

## 유지할 것과 수정 우선순위

- **유지**: 원문/출처/작성자/시각 불변 보존, 질문과 분리한 추출, 실제 저장·전달 계약. 이번 실행에서 전달 계층의 추가 손실은 없었다.
- **유지하되 제한 명시**: 기존 LangExtract 설명·예시 기반 추출. 단순 방식보다 국소 typed 역할은 나아졌지만 충분한 근거의 중간/어려운 연결을 안정적으로 만들지 못했다. 단순 추출로 전면 교체할 근거도 없다.
- **첫 수정 대상**: 문서/문장 범위의 조건·시각을 해당 주장에 연결하는 계약. 원문 전체에 있는 qualifier와 focal claim의 연결을 별도로 보존/검증해야 한다.
- **함께 정리할 표현 문제**: proposal 자체의 태도와 ‘미승인’이라는 한정의 역할, 반복 구절의 위치 식별, 한 추출의 오류가 소스 전체 claims를 없애는 실패 범위.
- **다음 평가의 선행 조건**: 이번 gold를 몰래 바꾸지 말고 별도 버전에서 독립 검토, 의미를 해치지 않는 구절 경계 동치, 예상하지 않은 잘못된 필드까지 측정하는 정밀도 기준을 추가한다. 새 사례 검증 전 적용/학습 성과를 주장하지 않는다.

따라서 다음 개발 판단은 ‘더 강한 모델을 먼저 붙일 것’으로 정해지지 않았다. 지금은 **찾은 정보를 claim별로 사용 가능하게 구성하는 records 계약과 컴파일 경계**에 직접적인 수정 근거가 있다.
