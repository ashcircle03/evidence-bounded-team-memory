# CPython QA에서 답과 인용이 0/9였던 이유

원래 실행에서 **Qwen2.5-3B-Instruct가 6번 직접 `null`을 생성했고, 나머지 3번은 질문이 요구한 사실을 고르지 못했다.** 인용 검사에서 거절된 세 출력 모두 형식 문제도 있었지만, 형식이나 문서 번호만 복구해 정답이 되는 사례는 없었다. 반대로, 사람이 같은 입력에서 찾은 정답 구절과 문서 번호를 주면 기존 검증기와 채점기가 9/9를 통과시켰다. [원출력](outputs.json) · [문항별 입력 해시·원문 위치·검증 결과](qa-audit.json)

## 어느 단계에서 실패했나

이 평가는 과거 결정 3문항을 새 기록 전·후에 반복하고 새 기록 3문항을 추가한 **서로 다른 6문항, 총 9회**다. 단순 검색과 재검토 모듈이 공유하는 QA 경로를 사용했다. GPU 작업 119252의 시스템 지시문과 사용자 입력을 SHA-256으로 대조했다. 정답이 있는 문서와 **정답 구절 자체**가 9회 모두 모델에 보였다. 각 입력은 문서 3개, 1,722~3,850토큰이었다. 출력은 2~56토큰으로 생성 한도 96보다 짧았다. 사전에 감지된 충돌 후보도, 충돌 검사로 제외된 구간도 없었다. [입력 복원 코드](../../evaluation/cpython/audit_qa.py) · [원래 QA 코드](../../team_memory/qa.py)

## 같은 모델로 병목을 분리한 대조

작업 119258에서 같은 체크포인트와 BF16, greedy decoding, 출력 한도 96토큰으로 36개 응답을 생성했다. 원래 조건의 9개 원출력이 모두 그대로 재현됐다. 입력 범위와 출력 요구를 교차로 바꿨다. ‘정답 구간 제공’에서는 각 문항의 정답이 들어 있던 구간 하나만 남기고 원래 문서·구간 번호를 유지했다. ‘답만’은 검증 가능한 인용을 요구하지 않으므로 **답 내용**만 사전 정답 기준으로 채점했다. [대조 실험의 전체 원출력](qa-control-outputs.json) · [입력 생성과 채점 코드](../../evaluation/cpython/qa_controls.py)

|---|---:|---:|

정답 구간을 제공한 두 조건에서도 어떤 출력이 달라졌는지 문항별로 확인했다.

| 위 표의 문항 | 구간 제공 · 구조화 응답 | 구간 제공 · 답만 |
|---|---|---|
| 1·2 · 649의 상태 전·후 | 둘 다 `null` | 둘 다 `Accepted` ✓ |
| 3 · future import 기한 | 기한과 문서가 맞고 줄바꿈이 달라 인용 거절 | `at least 1 year` ✗ |
| 4·5 · 철회 선택지 전·후 | 둘 다 철회 선택지와 문서가 맞고 줄바꿈이 달라 인용 거절 | 둘 다 PEP 703 전체를 철회할 수 있다고 답함 ✓ |
| 6 · 성능 손실 플랫폼 | `null` | `macOS` ✓ |
| 7·8 · 690의 상태 전·후 | 둘 다 `null` | 둘 다 `Rejected` ✓ |
| 9 · 한 줄 import | 올바른 구문과 그 다음 줄까지 인용, 채점 통과 | `lazy import json` ✓ |

- **입력에서 답을 찾는 문제.** 답만 요구해도 세 문서에서 7회 기권했다. 정답 구간만 주면 이 7회 모두 답을 냈다. 다만 3번은 전체 문서에서는 정확한 기한을 냈다가 구간만 주자 `at least 1 year`라고 틀렸다. 구간 선택이 모든 문항을 개선하지는 않았다.
- **인용 때문에 생기는 별도의 손실.** 정답 구간을 준 구조화 조건에서 3·4·5번은 올바른 문서와 답을 골랐지만 RST 줄바꿈·들여쓰기를 공백으로 바꿨다. 예를 들어 4·5번의 원문은 `roll\n   back`이다. 모델이 고른 문서에서 공백 차이만 있는 유일한 구절을 찾아 원문으로 복원하면 기존 검증기·채점기를 통과한다. 이 사후 보정은 그 조건의 **1/9를 4/9**로 바꾼다. 최초 실행의 0/9에는 이 세 답이 생성되지 않았다.
- **정답 기준의 한계.** 정답 구간을 준 구조화 조건의 유일한 성공인 9번은 요청한 한 줄 다음의 예시까지 복사했다. 사전 기준은 올바른 문서의 연속 구절 안에 `lazy import json`이 있으면 인정한다. 문자 그대로 한 줄만 반환하라는 기준으로 보면 과잉 인용이다.
- **다음 설계에서 확인할 가설.** 먼저 정답 위치를 모르는 상태에서 짧은 후보 구간을 선택하고, 모델이 고른 구간 ID에서 시스템이 원문을 인용하도록 한다. 같은 질문에서 후보 구간 적중, 답 내용, 인용 유효성을 따로 측정하면 무엇이 달라졌는지 판단할 수 있다. 실제 상충 사례의 양쪽 보존은 별도 문항으로 확인해야 한다. 이번 9회는 답이 하나인 문항들이며, 정답 위치를 준 성적은 배포 성능을 추정하지 않는다.
