## 원출력에서 확인한 실패

- 새 모듈의 일반 QA 입력 10/10에 올바른 출처와 정답 문자열이 노출됐고 결합 정답은 3/10이었다. 단순 검색은 6/10에 노출됐다. q06의 정상 답 `[PATCH]` 옆에 별도 설정의 파일 접미사 `.patch`를 두 번째 답으로 내놓았다. 두 출처를 따로 읽은 뒤 각 구절이 같은 속성에 대한 답인지 검사하는 부분이 충분하지 않았다. q03의 한 구절에는 0과 −1의 의미가 모두 적혀 있었는데 응답은 무한 재시도에 해당하는 −1을 골라내지 못했다. [실제 사용자에게 전달된 답과 인용](final-outcomes.json) · [입력 노출 여부](input-coverage.json)
- 상충·조건 분기 10건 중 새 모듈은 9건에서 양쪽 원문과 답 문자열을 받았다. d01에서는 기본 원격 이름 `origin`과 상반된 보고 `upstream`을 각각 인용했다. d07에서는 담수의 L-2와 기수의 B-8을 조건에 맞게 연결했다. d06에서는 35분과 50분을 각각 인용했지만 어느 소성 조건의 시간인지 답에서 연결하지 못했다. 단순 검색도 같은 실패를 보였다. 출처 문자열 노출은 의미 이해를 보장하지 않으며 특히 짧은 숫자에서는 노출 지표가 낙관적일 수 있다. [문항별 표](cases.ko.md)
- 양성 10건 모두 새 모듈 입력에 사전 지정한 과거·신규 단서가 있었다. 실제 Git 사건 세 건에서 새 모듈의 최종 조치는 모두 유지였다. r15와 r16의 원출력은 다른 과거 커밋을 골랐다. r17에서는 실제 버퍼 해제 커밋과 double-free 보고를 연결했지만 조치를 `RETEST`로 골랐고, 비교 실측을 요구하는 규칙이 제안을 막았다. 메모리 안전성의 재현 실패도 기존 가정을 재평가할 근거라는 점이 드러났다. [당시 Git 실패 보고](https://github.com/git/git/commit/b59ec03cb5) · [원출력](outputs.json) · [조건별 입력 점검](cost-and-review-inputs.json)
- 음성 10건의 새 출력 중 4건은 `P1`, `N1` 같은 발췌문 번호 대신 문서 경로 속 식별자를 내서 검증에 실패했다. 네 경우 모두 원출력은 재시험을 요청했다. r11에서는 전기함의 문이 추가된 것을 광학함의 변경으로 설명했다. 출력 형식만 수리하면 올바른 판단이 되는 사례로 셀 수 없다. 실제 Git 음성에서는 3/3 유지였고, 모의 음성에서는 3/7 유지·4/7 오류였다. 실제 Git 양성은 0/3, 모의 양성은 4/7이었다. [채점과 출처별 집계](scored.json)

## 두 복제본에서의 실행

작업 119276에서 서로 다른 Git 복제본에 Jaewon과 Seonghun의 Aimers 원문을 일반 Markdown으로 커밋했다. 공유 AI나 수작업 구조화 없이 수신 측의 `pull --notes-dir`이 TabM의 이전 기각과 새 TM-S 블렌드 결과를 연결해 재시험을 제안했다. 팀원 복제본의 질문에서 승인 전 제안과 인용을 확인했고, 다른 작성자 이름으로 낸 승인은 거절됐다. 원작성자 역할의 승인 후 상태는 `approved_review`였고 원문 네 건의 ID가 모두 유지됐다. 검토와 승인은 재현용 행위이며 실제 팀원의 승인 이력과 구분했다. [실제 Qwen·Git 기록](git-integration.json) · [두 복제본 재생](../../evaluation/revision/README.md)

## 비교 범위와 재현

새 사건 40건에 일반 QA의 무관 충돌 반복 10건을 더했다. 원본 QA 10건은 Git v2.49.0 설정 문서의 서로 다른 주제다. 상충 QA 다섯 건은 실제 원문에 만든 반대 보고, 조건 분기 다섯 건은 통제한 두 작업 기록이다. 재검토 사건 20건 가운데 여섯 건은 실제 Git 커밋 이력이며 나머지는 연구자가 구성했다. 역사 양성 세 건은 보고자가 과거 커밋을 직접 언급한다. 사례나 판정에 독립된 복수 주석자는 참여하지 않았다. 방식 이름을 가린 출력 91개를 문맥으로 검토했고, 동결한 자동 채점과 달라진 세 건을 공개했다. [사건과 정답](../../evaluation/revision/final-key.json) · [의미 판정 변경](adjudication.json)

최종 작업 119273은 Aurora RTX 3090에서 1분 48초, 종료 코드 `0:0`으로 끝났다. 새 평가 170회와 옛 회귀 116회의 입력 해시를 전부 확인했다. 직접 비교의 문항당 상한은 합산 입력 8,192·출력 192토큰이다. 새 모듈의 QA만 출력 64토큰씩 최대 세 번에 나누었다. 실제로 단순 검색은 50회·입력 60,109·출력 535토큰, 새 모듈은 110회·입력 80,049·출력 1,903토큰을 사용했다. 같은 상한에서도 새 모듈의 실소비량이 높았다. 기존 리더는 일반 QA 10회·입력 12,884·출력 352토큰이다. 두 번의 별도 Git 통합 실행이 구버전 Git의 경로 옵션과 빈 저장소의 브랜치 추적 설정으로 실패해 각각 23초와 24초를 썼다. 통합 실행의 수정은 최종 286개 추론 입력에 영향을 주지 않는다. [동결 해시](../../evaluation/revision/freeze.json) · [원입력과 원출력 재생](../../evaluation/revision/README.md)
