# 과거 결정의 근거 선택과 재검토 검증

새 보고가 들어왔을 때 팀원의 AI가 관련된 과거 결정을 다시 찾고, 어느 조건이 바뀌었는지를 두 원문으로 설명할 수 있는지 검사했다. 후보별 비교는 근거를 찾는 단계에서는 개선됐지만, 새 Git 사례에 재검토 이유까지 정확히 전달한 경우는 0/4였다. 후보별 방식은 `pull --strategy pairwise`로 사용할 수 있으며 기본 전략은 `simple`이다.

## 비교 방법

같은 Qwen2.5-3B-Instruct 체크포인트에 같은 과거 원문들과 같은 새 보고를 줬다. 비교한 기존 방식(`joint`)은 이전 실험의 원문 전용 판정기로, 여러 과거 문서를 한 번에 읽고 판단·과거 문단·신규 문단을 정해진 선택지에서 고른다. 새 방식(`pairwise`)은 과거 문서 하나와 새 보고를 대조한 뒤, 각 문단 쌍만으로 재검토를 뒷받침할 수 있는지 점수를 매긴다. 문서 점수와 문단 점수 중 낮은 값이 가장 높은 쌍을 고르고, 두 점수가 모두 양수일 때만 제안을 올린다. 모델이 고른 두 원문 구간과 원작성자를 함께 보존한다.

32개 사건 각각에서 후보 문서 순서를 통째로 뒤집어 두 방식 모두 다시 추론했다. 문서 속 문단 순서는 유지했다. 양성 18건에는 허용되는 과거·신규 근거 문단을 미리 지정했다. **근거 있는 재검토**는 두 순서에서 같은 결정과 허용 문단 쌍을 인용하고, 원래 전제와 바뀐 조건을 설명해 실제로 제안한 경우다. 보류한 경우에도 내부 최고점 후보는 기록하지만 사용자에게 전달한 근거로 세지 않았다. ## 같은 쌍 안에서 새 보고를 먼저 보여주면

앞의 32/32는 **후보 목록의 순서**에 대한 결과다. 추가 진단에서는 후보 목록과 시점 표지(`earlier`, `report`)를 고정하고 Qwen이 읽는 두 필드의 물리적 위치만 맞바꿨다. 양 방향을 같은 배치 행, 이웃 샘플, 패딩 폭으로 짝지었다. 이 검사는 점수·선택·발행 판단까지 다룬다.

| 32건에서 맞바꾼 것 | 판단과 양측 문단이 모두 같음 | 새 Git 양성에서 올바른 문단 쌍 | 새 Git 양성에서 제안 발행 |
|---|---:|---:|---:|
| 후보 목록의 순서, 과거를 먼저 표시 | 32/32 | 양 방향 4/4 | 양 방향 2/4 |
| 한 쌍 안의 과거·신규 필드 위치 | 4/32 | 과거 먼저 4/4, 새 보고 먼저 2/4 | 과거 먼저 2/4, 새 보고 먼저 0/4 |

한 쌍 안의 순서를 바꾸면 행동만 같은 경우는 22/32였다. 새 보고를 먼저 놓았을 때는 양성 18건에서 제안이 한 번도 나오지 않았다. 예컨대 최초 checkout은 어느 방향에서나 같은 올바른 두 문단을 선택했지만, 과거 먼저면 재검토, 새 보고 먼저면 보류였다. 임곗값에 들어가는 점수가 원문 배치에 민감하다. 추가 검사의 과거 먼저 조건은 32건 중 30건에서 본실험의 판단·문단 조합을 그대로 재현했다. 신규 Git 8건은 모두 재현했다. 이 배치 차이 때문에 표의 두 번째 행은 추가 검사의 짝지어진 결과끼리 비교했다. 세부 실패는 서로 다르다. 빈 트리에서는 선택한 문단의 증거를 문서 판정이 뒤집었다. amend에서는 올바른 후보를 다른 후보보다 높이 뒀지만 그 후보 자체의 지지 강도를 낮게 평가했다. checkout에서는 두 근거를 전달한 다음, 설명을 생성하면서 원문에 있는 부차적인 내용을 원인으로 바꿨다. [순서별 점수와 출력](pairwise.json) · [설명 판정 기록](ratings.json)


## 실제 Git pull과 기본 전략

Aurora 계산 노드에서 임시 Git 원격 저장소와 두 복제본을 만들고 실제 Qwen으로 팀원 기록을 push/pull했다. 최초 checkout 사례에서 `pending` 제안이 한 건 생겼다. 같은 원문을 가진 대조 복제본과 제안을 받은 복제본 모두 QA의 답은 `checkout.optimizeNewBranch`였고, 동일한 원문의 동일한 위치를 인용했다. checkout 근거 문단은 배치 평가와 일치했다. 제안 설명의 표현은 달라졌지만 여기서도 최초 checkout 조건을 파일시스템 접근 여부로 잘못 풀었다. 제안이 생성되지 않은 diff 버퍼 사례에서도 양쪽 모두 같은 근거로 `buf`라고 답했다. [실제 모델·Git 통합 결과](live.json)

현재 기본 전략 `simple`도 새 Git 사례 8건에 대해 두 순서에서 별도로 실행했다. 검색 결과를 정렬하기 때문에 순서를 바꿔도 8/8 동일했지만, 각 순서에서 재검토가 필요 없는 4/4에도 제안했다. 양성 4/4에 제안했지만 과거와 신규 양쪽 모두 지정된 근거 문단을 인용한 경우는 0/4였다. 후보별 방식은 같은 8건에서 오탐 0/4, **실제로 발행한 제안** 중 양측 문단이 맞은 경우 2/4, 설명까지 맞은 경우 0/4였다. 기본 전략 출력에는 자유서술 이유 필드가 없어 설명 품질은 양측 문단 점수와 분리했다. [기본 전략의 사건별 인용](default-comparison.json)

## QA의 정답·인용 보존

기존에 실제로 답과 인용을 맞혔던 20문항(일반 16, 다중 근거 4)에 대해 당시 성공했던 문항별 reader 설정과 입력을 복원했다. Git, PEP, EverMemBench-Dynamic 문항을 포함한다. 혼합 배치에서는 파서 출력이 18/20 동일했다. Git fetch의 기본 출력 형식을 묻는 문항에서 `full`을 추출하지 못했고, 다중 근거 문항에서는 카트리지 ID는 맞혔지만 두 번째 출처의 기수(brackish water) 조건을 놓쳤다. 이 실행의 QA 입력에는 새 재검토 제안이 들어가지 않았다.

같은 체크포인트·GPU에서 원래 배치의 이웃 샘플, 행 위치, 입력 길이와 생성 상한까지 복원했다. 당시 채점 경로를 다시 통과한 결과, **20/20에서 정답, 상태, 인용문 및 출처가 완전히 같았다.** 직전의 같은 받은편지함 QA 90개 응답도 원래 배치에서는 90/90 원출력이 같았다(혼합 배치에서는 84/90). 원래 배치를 복원한 263개 호출에는 비교 대상 140개와 배치 이웃이 포함된다. 20은 회귀 검사용 성공 사례 수이며, 별도 테스트셋 정확도를 뜻하지 않는다. ## 해석과 다음 검증

- 문서와 문단의 점수 차이를 기록하고, 어떤 단계가 제안을 보류시켰는지 분리할 수 있게 됐다. 다음 검증에서는 먼저 같은 쌍을 읽는 순서에 따라 판단이 뒤집히는 이유를 검사한다. 두 방향의 판정을 결합하는 규칙이 무관한 사례의 오탐을 다시 늘리는지도 새 사건에서 확인한다. 이어 문단 선택을 고정하고, 문서 판정이 구체적인 반례를 놓치는 경우와 설명이 원문의 부차적 조건을 원인으로 바꾸는 경우를 따로 평가한다. 새로 수집한 Git 사례와 특히 같은 주제의 무관한 보고를 대조군에 포함해야 한다.
- 이번 실험은 같은 모델과 원문을 통제했다. 전체 비교는 64회에 입력 토큰 96,186개, 후보별 비교는 점수 1,686회와 설명 20회에 485,412개를 사용했다. 짧은 점수 계산과 긴 생성의 비용은 다르다. 같은 계산 예산에서의 우위는 측정하지 않았다.
- 새 Git 사례는 한 저장소에서 고른 명확한 회귀 4건과 실제 문서 변경 4건이다. 후보 주제가 사건당 2개이고, 양성 보고에는 회귀를 일으킨 커밋을 직접 가리키는 경우도 있다. 모든 과거 Git 이력에서의 검색 성능, 직접 참조가 없는 팀 대화에서의 성능은 별도 검증이 필요하다. 허용 문단은 추론 전에 고정했으며 설명 적합성은 방식·순서를 가린 단일 평가자가 판정했다. 독립된 사람의 이중 채점은 수행하지 않았다.

## 실행 검증

Aurora Slurm에서 GPU 1개씩 사용했다. 본실험은 119286(기존 방식), 119288(후보별 점수), 119289(이유·혼합 배치 QA), 후속 대조는 119291(원래 QA 배치), 119293(Git 통합·기본 전략), 119294(쌍 내부 표시 순서)에서 실행했다. 완료 상태·종료 코드·프로그램 결과 및 입력 해시를 대조했다. Git 2.25의 빈 복제본 초기화 문제로 통합 실행 119290과 119292가 모델 판정 전에 실패했다. 두 실패를 포함한 이번 실험의 전체 GPU 할당 시간은 15분 36초였다. 동결한 4개 파일의 해시와 로컬 단위 테스트 42개도 통과했다. [작업별 입력·결과 해시와 자원 사용량](runs.json)
