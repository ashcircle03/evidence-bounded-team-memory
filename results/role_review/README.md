# 설명의 주체·동작·조건을 원문에 연결하는 실험

**판정은 기본값 채택 보류다.** 세 구절을 먼저 맞힌 개발 3건에서는 역할 아홉 개를 제대로 연결했다. 새 Git 보고 5건에서는 직전 전략과 이번 전략 모두 조건과 실패 동작까지 정확한 제안이 0건이었다. 이번 전략은 올바른 결정에 제안을 올린 수도 4건에서 2건으로 줄었다.

## 무엇을 바꿨나

기존 선택기가 고른 과거 결정, 새 보고, 대조 결정은 그대로 사용한다. 새 전략 `role-review`는 작성된 설명의 주체·동작·조건을 설명과 원문의 문자 범위에 각각 연결하고, 추가한 사실이 지지되는지 검사한다. 검사를 통과하지 못하면 새 보고의 원문으로 설명을 다시 구성한다. 이때 한 문장에서 입력 경로와 전달 동작, 부정 동작과 범위, 교체된 구현과 반환값을 결합하는 영어 구문을 우선 사용한다. 해당 구문이 없으면 같은 Qwen이 구절을 추출한다. 마지막으로 저장된 설명과 인용의 텍스트·화자·위치를 검증한다. 평가에는 Qwen2.5-3B-Instruct를 사용했다. 방법별 추론량은 다르다. [구현](../../team_memory/role_review.py) · [구문 규칙](../../team_memory/role_binding.py) · [사전 기준과 변경 이력](../../evaluation/role_review/PROTOCOL.md)

## 세 구절을 고정한 개발 진단

| 사례 | 주체 | 동작 | 조건 | 기존 오류를 처리한 방식 |
|---|---|---|---|---|
| 훅 | `invoked_hook` 변수 | `wasn't passed forward to run_hooks_opt()` | `passed to run_commit_hook()` | `run_commit_hook() in push_to_checkout()`이라는 중첩 관계에 근거가 없음을 지목했다. 올바르게 전달한 별도 경로와 실패 경로를 구분했다. |
| reflog | `lookup_commit()` | `started returning non-NULL` | `for the null_oid()` | 기존 문장은 거절됐다. 원문으로 재구성하면서 잘못된 객체를 역참조할 수 있다는 추측을 제거했다. 이 추측만 별도로 지목한 것은 아니다. |
| zsh | `zsh` | `does not expand PS1` | `by default` | 기존 설명에 덧붙은 `set -o prompt`에서 원문에 없는 `-o`를 지목했다. |

각 사례에 당시 잘못된 문장, 의미가 맞는 의역, 방향·극성을 바꾼 문장, 사실인 원문 발췌를 넣었다. 기존 오류 3/3과 변조 문장 3/3을 거절했고 원문 발췌 3/3을 수용했다. **정확한 의역도 3/3을 거절했다.** 개발 3건의 역할 일치는 원문 재구성 경로에서 얻은 결과다. 자유로운 설명의 옳고 그름을 안정적으로 가르는 성과로 계산하지 않았다. [실제 입력·판정·역할별 원문](development.ko.md)

## 독립된 새 Git 사례

같은 보고마다 실제 결정이 있는 양성 이력과, 주제만 가까운 결정이 든 음성 이력을 비교했다. 각각 5건이다. 직전 방식은 `referenced-review`다.

| Git 보고 | 직전 방식 | 새 방식 | 새 방식에 대한 판정 |
|---|---|---|---|
| dumb HTTP의 v1 pack index | 재검토 | 보류 | 같은 경로에서 발생한 충돌을 다루는 문단은 찾았지만 동작은 의역으로 출력하고 조건 자리에는 질문 문구를 되풀이했다. |
| `make info`의 접미사 규칙 | 재검토 | 보류 | 주체로 고른 `'$*' is set to`가 같은 문단에 두 번 나와 출처 위치를 확정하지 못했다. |
| FreeBSD의 긴 경로에서 `getcwd` | 재검토 | 재검토 | 버퍼 교체와 127바이트 초과·권한 부족을 연결했다. 주체를 “This fixes a regression”, 동작을 “fixes a regression”에 묶었다. 작은 버퍼에서는 실패하지만 더 큰 버퍼로 성공할 수 있다는 동작 차이가 빠졌다. |
| 빈 loose object에 대한 `git fsck` | 재검토 | 재검토 | 올바른 주체와 빈 파일 조건을 찾았다. 인용이 “complains with the error message”에서 끝나 실제 오진 내용이나 `EINVAL`을 전달하지 못했다. |
| 하위 디렉터리의 dir-diff | 보류 | 보류 | 기존 결정 선택 단계에서 보류했다. 역할 검증 단계에 도달하지 않았다. |

FreeBSD는 **변경 조건을 더 정확히 특정한 부분 개선 1건**이다. 사전 기준상 실패 동작과 그 근거까지 요구하므로 최종 적중에 포함하지 않았다. 새 방식이 제안한 두 건은 모두 문자 범위가 유효했지만, 원문의 의미까지 따져 세 역할을 모두 맞힌 것은 0/2였다. 의미 점수는 전략 이름을 뺀 카드에 대해 작성한 단일 평가자의 판정이며 문체로 전략을 짐작할 수 있다. [문항별 세 방법의 최종 제안과 인용](cases.ko.md) · [설명 채점 근거](ratings.json) · [역할 채점 근거](role-ratings.json)

원인 결정이 없고 관련 주제의 결정 두 개만 있으면 직전·새 방식의 오탐은 각각 0/5였다. 같은 음성에서 단순 검색과 Qwen은 5/5에서 제안했다. 대조 결정 하나만 주어도 직전·새 방식은 0/5였다. 원인 커밋 번호와 인용 제목을 가린 양성에서는 둘 다 0/5를 제안했다. 원문 양성·음성 각각 5건에서 새 방식은 후보 순서를 뒤집어도 결정과 근거가 10/10 동일했다. 음성·가림·순서 변형은 같은 다섯 보고의 반복 관측이다. [전체 집계](counts.json)

## 기존 QA와 실제 Git pull

과거 성공 20개 평가 항목의 원래 배치 위치와 이웃을 복원하고 136개 프롬프트를 실제 재생성했다. 원래 파서를 통과시킨 답, 상태, 출처, 인용문이 **20/20** 일치했다. Git, PEP, EverMemBench-Dynamic의 기존 성공 항목에 대한 회귀 검증이다.

새 보고에서도 원문만 가진 복제본과 실제 pull한 복제본에서 QA를 각각 생성했다. `make info`의 답은 양쪽 모두 `.texi`였다. FreeBSD의 답은 양쪽 모두 `EACCES`였고 작은 버퍼와 권한 제약을 함께 확인하는 동일한 문단을 인용했다. FreeBSD 복제본에는 이때 원 작성자의 승인을 기다리는 재검토 제안이 실제로 하나 있었다. [문항별 QA와 인용문](qa.ko.md) · [Git pull 원출력](comparison.json)

다음에 구별할 문제는 **선택된 문단 안에 실제 관측 결과가 있는가**다. FreeBSD는 QA가 원 보고의 다른 문단에서 이미 정확한 동작을 찾았고, fsck는 선택된 문단 바로 다음에 오류 메시지가 있었다. 역할 추출 규칙을 더 늘리기 전에, 같은 기록에서 인접 구절을 추가했을 때 이 두 오류를 복구하는지와 무관한 인접 구절에서도 제안을 올리는지를 함께 비교할 수 있다. [Slurm 작업별 해시·자원 기록](runs.json)

Aurora 작업 119304–119310 일곱 건의 종료 상태가 모두 `COMPLETED`, 종료 코드는 `0:0`이었다. 입력과 제출 파일 해시, 실제 반환 job ID, 완료 JSON을 대조했다. 개발에서 발견한 커밋 제목 괄호 처리 오류까지 고친 최종 소스는 제출 아카이브와 바이트 단위로 일치한다. 괄호 수정 전후 새 Git 평가에서 모든 최종 제안과 두 QA 결과가 동일했다. 이번 목표에 GPU 8분 21초를 사용했고, 기존 시도까지 포함한 캠페인 누적은 116분 18초/120분이다. 단위 테스트 56개가 통과했다. [입력 순서와 QA 일치 검사](checks.json)

선택 실행은 `python3 -m team_memory --store shared-records pull --model /path/to/Qwen2.5-3B-Instruct --strategy role-review`로 한다. 공개 기록을 변경하는 대신 원 작성자의 승인 대기 제안을 생성하는 기존 절차를 따른다.
