# 저자 구현 예시·근거 연결 복구: 검증 결과

2026-11-07. 구현과 실제 Qwen 비교는 완료했지만 후보를 채택하지 않는다.
기존20문항은19/20, EverMem10문항은 단순 독해·구절 연결·검색 결합 모두2/10이다.
기존 선택 경로 attributed의 역사적20/20과 이전 connected의 Ever3/10을 모두
유지하지 못했다. 이 결과를 보고 프롬프트를 바꾸거나 추가 실험을 제출하지 않았다.

## 실제 반영한 부분

[구현](../../../team_memory/reference_demonstrated.py) · [레퍼런스·변형 범위](../../../docs/reference-demonstrated.md)

1. Attribute First 공개 LFQA 원문 예시 첫2개를 문서·선택 구절·답 문장까지 사용했다.
   번호와 문장 대응을 유지하면서 JSON 대화 예시로 직렬화했다. 예시의 반복 구절을
   제거하면 문장 연결 번호가 깨지는 문제를 로컬 검사에서 발견해 제출 전에 수정했다.
2. 자유로운 purpose 설명을 없애고 선택한 구절에 번호를 붙였다. 생성기는 답과
   highlight_ids를 반환하며 코드가 선택 구절의 원문 출처·위치로 되돌린다.
3. AQA 실제3-shot 데이터는 GitHub에 없고 저자 Drive 접근이404여서 확보하지 못했다.
   기존 논문 Figure1 대통령 사례의 paraphrase를 완성된 입출력 예시로 변환했다.
   저자3-shot/학습/원 모델을 재현했다고 주장하지 않는다.
4. 새 검색 결과가 들어오면 선택을 다시 하는 최대2회 연결을 구현했다.
   원 IRCoT의 마지막 생성 문장 기반 질의와는 다른 변형이다.
5. 같은 예시로 원문에서 바로 답하는 direct를 함께 실행해 선택 단계의 이득을 비교했다.
   원래20개와 Ever10개 질문·정답 키·원문 top8·일차 채점 기준은 그대로다.

## 확인된 실패 연결

**검색은 실제로 한 번도 실행되지 않았다.** Ever10 모두 missing_queries=[]였다.
따라서 reader_only와 combined는 동일 원문·선택·최종 답을 사용했고 네이티브R 회수도
22/290 그대로다. 반복 검색 코드를 넣은 것을 실제 검색 개선으로 부를 수 없다.
이것은 원 IRCoT 실행 실패가 아니라 우리가 추가한 '선택기가 부족함을 느껴야 검색'
연결의 실패다. 선택 예시3개 모두 missing_queries=[]인 것도 확인됐다. 이 편향이
원인인지 별도 대조하지 않았으므로 인과적으로 확정하지 않는다.

**구절 연결도 모델의 원문 복사 정확도에 의존한다.** breakpoint 선택은 backtick을
뺀 구절과 원문에 없는 '빈 값이면 debugging 비활성화' 구절을 반환했다. 두 구절을
검증기가 제외했고 생성기는 여전히 원문을 보고 정답0을 썼지만 유효한 highlight가
없는 상태에서2번을 지목했다. 이를 거절한 것은 출처 보호에는 맞지만 최종 QA 회귀다.
이 결과를 맞았다고 세거나, 기호를 모두 지워 다른 코드 표현을 같다고 처리하지 않았다.

새 후보의 선택 구절 오류는 기존3문항+Ever5문항이다. 공유 선택 때문에 출력 기준으로는
13/40개 후보 답에 경고가 남았다. direct도4/10개에 인용 문자열 경고가 있다.
모든80개 요청은 finish_reason=stop이며 토큰 한도에 잘려서 생긴 오류는 아니다.
정확히 복원된 인용107개도 의미 지지를 보장하지 않는다.

**가져갈 판단:** 근거 번호를 최종 문장에 연결하는 구현과 저자 예시는 재사용 가능한
후보로 남기되 기본 경로로 승격하지 않는다. 이번에는 단순 direct 대비 Ever 정확도
이득이 없고 입력량이 약2배다. 상충2건 복구를 모든 QA/검색이 좋아졌다는 주장으로
확대하지 않는다. 원 저자의 전체 파이프라인 또는 모델 한계를 기각하는 실험도 아니다.
