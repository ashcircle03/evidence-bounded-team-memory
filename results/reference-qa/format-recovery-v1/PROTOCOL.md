# 인용 형식 복구와 검색 결과의 충분성

개발에서 관찰한 출력 형식 오류를 고친 뒤 동일한 104개 출력을 대조한다. 문항·프롬프트·모델·검색 결과를 고정한다. 인용 구절의 탭·줄바꿈을 디코딩하고 기존 스키마를 다시 적용한다. RST 일반 문단 안의 짝지어진 인라인 코드 표시는 원문 위치가 유일한 경우에 복원한다. 변경된 구절은 원문에서 잘라 반환한다. 새로운 의미 보정이나 재시도는 추가하지 않는다.

로컬에서 최초 선택 요청과 이전 생성 요청을 실제 기록과 비교하고, 입력이 달라지거나 새로 도달한 최종 생성만 Aurora에서 실행한다. 내용·근거가 같은 출력은 이전 판정의 해시와 함께 계승한다. 달라진 출력은 기존 정답·주장별 근거·조건으로 다시 읽고 이전 정답 손실과 회복을 따로 기록한다. 104개는 이전에 본 개발 출력이다. 이전 점수는 보존한다.

Ever 개발 10개의 네이티브 R 메시지와 각 문항에서 실제 제공된 top8을 대조한다. 질문에 반드시 필요한 사람, 시작·끝 사건, 기존 규칙과 적용 예외가 모두 있는가를 검토한다. 충분, 부분, 부재로 구분하고 결정적 메시지를 기록한다. 입력이 충분한 실패를 검색 누락으로 집계하지 않는다. R 밖의 top8 구절도 근거가 될 수 있다. 이 진단에서는 검색 방법을 바꾸지 않는다.

GPU 1개, 최대 25분. 개발 5건의 생성 요청만 실행한다. 나머지는 고정 출력 재생이며 추가 호출이나 유료 API를 사용하지 않는다. 채택 단위는 형식 수정이다. 이 결과로 전체 QA 프로필을 교체하지 않는다.
