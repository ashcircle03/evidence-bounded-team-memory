# 원문 QA: 상충 답 보존과 인용 누락 수정

최신 고정 비교는 [문단 ID + 실제 검색 후보](documents-v1/README.md)다. 기존20에서 direct 답19/20·답과 인용18/20, Ever10의 엄격한 답·근거는 BM252/10·Contriever1/10으로 기본 교체하지 않았다. 기존 선택은 attributed로 유지한다.

저자 예시와 구절→문장 연결을 복구한 `demonstrated` 후보의 실제 검증을 완료했다. 기존20은19/20, Ever10은 단순 독해·구절 연결·검색 결합 모두2/10이다. 이전 상충2건을 복구했지만 breakpoint1건과 이전 검색으로 맞힌 담당자 문항을 잃어 채택하지 않았다. [최신 결과·구현 차이·실제 원출력](demonstrated-v1/README.md). 현재 선택 경로는 `attributed`이며 앞으로 제출 시간은12시간 고정이다. 아래 누적 한도 수치는 과거 실행 이력이다.

검색 피드백·원문 맥락을 유지하는 `contextual` 후보도 검증했다. 같은 Ever10에서 독해만 수정2/10, 검색만 수정1/10, 결합2/10이다. 새 후보의 기존20은17/20이라 교체하지 않았고, 선택 경로 `attributed`의20개 답·근거는 고정 재생으로 보존했다. [최신 비교·문항별 원인](contextual-v1/README.md)

인용 형식 복구와 Ever 입력 진단을 완료했다. `claims`의 기존20문항 답·근거는 14/20→17/20이며, 기존 QA 선택 경로는 `attributed`를 유지한다. 고정104개 출력 중7개를 복구했고 기존 성공48개는 모두 보존했다. 새 모델 호출은5회다. [최신 결과와 Ever10문항 원인 분석](format-recovery-v1/README.md) · [수정 전 Ever·Wiki 비교](claims-v3/README.md)

해당 단계 완료 당시 실제 누적 사용량은 QA131.20/150, CUPMem503.77/520, 캠페인798.82/820 GPU분이다. 모델 준비·실패를 포함하며 검색·맥락 후보 비교는30.32 GPU분이다. 앞선 형식 수정은6.37 GPU분이었다. [사용량과 완료 기록](phase-accounting.json)

**재감사:** 기존 집계는 유지하지만, 단계 실패 상태 전파·JSONL 오류 출력·실제 토큰 설정에서 통합 결함을 재현했다. 한 문서의 여러 주장 누락도 문서 ID 검사로는 잡지 못한다. 순서 비교는 제목까지 달라 순서만의 효과로 해석할 수 없다. [감사 결과와 수정 우선순위](simplify-audit-v1/README.md)를 먼저 확인한다. 기존 선택 경로는 회귀 기준이며 완성된 팀 지식 시스템을 뜻하지 않는다.

앞선 단순화 비교는 [simplify-v2](simplify-v2/README.md)에 있다. 새12개에서 기존 경로7/12, 단순 후보9/12와 호출51→12를 확인했지만 기존20개 중1개를 잃어 교체하지 않았다. 부가 단계 예외 시 이전 답·근거를 보존하는 수정은 채택했고 기존20개 출력의 정확한 재생도 확인했다. 그 비교 완료 당시 누적은 QA77.62/90, CUPMem450.18/460, 캠페인745.23/760 GPU분이었다. 아래는 그 이전20문항 수정의 결과다.

## 실제 가져온 방식

[AQA](https://aclanthology.org/2024.emnlp-main.956/)의 상충 인식 예시 프롬프트를 기존 누락 근거 검토에 연결했다. 한 문서를 따로 읽게 하면 무관한 문서에도 답을 만드는 이전 실패가 있어, 검색된 근거 전체를 함께 제공한다. 원형3-shot 대신 논문 Figure1을 바꾸어 표현한1-shot과 Qwen3-8B를 쓰므로 논문 성능 재현이라고 부르지 않는다.

[LangChain citation_fuzzy_match](https://github.com/langchain-ai/langchain/blob/langchain%3D%3D0.3.27/libs/langchain/langchain/chains/openai_functions/citation_fuzzy_match.py)의 사실별 근거 구절 스키마와 프롬프트를 가져왔다. 답 전체를 읽어 지시어의 대상을 확인하며, 기존 답을 다시 쓰지 않고 인용 번호만 추가한다. 모델이 바꾼 줄바꿈·공백은 원문 위치로 복원하지만 단어·코드 기호·조건의 차이는 허용하지 않는다. 실제 원문의 구절과 문자 위치를 반환한다. 이 문자열 검사는 의미 정확성 인증과 다르다.

## 해석의 한계

20개는 이미 본 개발 문항이며 자연 EverMemBench 질문은3개다. 다른 조건의 공존과 상충은 통제 구성이다. **전체 벤치마크 성능, 자동 재검토, 작성자 승인·병합까지 해결됐다는 뜻이 아니다.** 의미 판정은 개발 담당 AI가 원문을 대조했으며 독립된 사람의 검증이나 AutoAIS는 없다.

필수 답·근거20/20과 전체 문장의 인용 완전성은 다르다. 자동 후보24문장 중13곳에 번호를 추가했고11곳은 추가하지 않았다. 반복 답·질문 재진술·각주도 포함하며,4개 응답은 요청 fact 목록을 지키지 않아 거절됐다. 기존 반환 문단이 이미 지지하던 답은 그대로 유지했다. 아직 추가 인용을 못 붙이는 경우를 `unattributed_sentences`·`quote_attribution_error`로 드러내므로 완전한 자동 인용기라고 부르지 않는다. 문서 판정의 오탐도 남는다.
