# 공개 QA 구현을 연결한 실제 Qwen 결과

**LlamaIndex의 분할·검색·문맥 구성·인용 QA를 실제로 연결하니 답과 인용을 함께 맞힌 문항이 과거 단순 경로의 7/20에서 15/20으로 늘었다.** 다만 기존 성공7개 중2개를 잃었고, 상충 기록3개를 처리하지 못했다. 공식 구성요소는 개발 기반으로 가져가되 이 경로 전체를 팀 메모리의 기본값으로 교체하지 않는다.

모델은 같은 로컬 Qwen3-8B다. 기존 전체 기록·질문20개를 그대로 사용하고 정답 키는 모델에 보내지 않았다. 이미 노출된 개발 문항에 대한 진단이며, 새 holdout/전체 EverMemBench 성과나 원형 CUPMem 성능이 아니다. 이전 두 열은 고정된 과거 실행으로, 이번에 함께 재실행한 대조군은 아니다.

## 무엇이 회복됐나

`ValueError`를 답했는데 인용이 “When enabled, a ValueError is”에서 끊겼던 PEP618 문제는, 이제 strict zip과 길이 불일치 조건까지 포함한 문단을 인용하며 맞혔다. `EncodingWarning`과 `tomllib`도 명칭만 들어간 조각 대신 해당 역할을 설명하는 근거를 선택했다. 이전에 문맥 초과로 실행하지 못했던 PEP 질문들도 답했다. 이번20회 요청의 최대 실제 입력은2,059토큰이고 출력 예약은1,024토큰이었다. 문맥 초과/출력 잘림은 없었다.

새 작성 알고리즘을 추가하지 않았다. 원문 적재는 LLM을 호출하지 않으며, 질문마다 공식 `CitationQueryEngine`을 한 번 호출했다. 이번20문항은 각각 실제 모델 호출1회로 끝났다. 일반적으로 upstream compact/refine는 여러 번 호출될 수 있으므로 API의1회 보장은 아니다.

## 남은5건과 책임 범위

1. **Confluence 보고서 위치:** 정답이 있는 업로드 기록을 상위4 청크 검색이 놓쳤다. 모델은 주어진 검색 결과에서 시스템이 명시되지 않았다고 답했다. 읽기 실패와 검색 누락을 구분해야 한다.
2. **Lizhen Zhou 작성자:** 정답 메시지는 검색됐지만 모델에는 작성자 메타데이터를 보내지 않았다. 답은 본문의 수신자 `@Luhao Zhao`를 작성자로 잘못 연결했다. 다른 검색 문맥에는 Boss Zhou라는 간접 단서도 있었지만 답은 틀렸다. 메타데이터 반복을 줄이면서 필요한 작성자까지 제외한 **연결 설정의 문제**가 있으며, 작성자 복원이 실제로 고칠지는 별도 확인이 필요하다.
3. **origin/upstream 상충:** 두 근거가 실제 입력에 있었으나 upstream만 확정했다.
4. **`:=`/`<-` 상충:** 두 근거가 있었으나 `:=`만 반환했다.
5. **ValueError/LengthMismatchError 상충:** 두 근거가 있었으나 LengthMismatchError만 확정하고 그 예외의 설계 목적까지 덧붙였다.

마지막3건은 일반 인용 QA 템플릿이 미해결 상충 기록의 양쪽 주장·출처를 보존하도록 보장하지 않는다는 결과다. 문자 인용의 정확성과 상충 지식 처리는 서로 다른 요구사항이다. 이번 실행에는 새로운 Git 재검토/병합 제안이 없으므로 그 기능의 개선을 주장하지 않는다.

다음 수정의 범위는 검색과 출처 메타데이터 전달, 상충 지식을 다루는 기존 구현의 적용 여부다. 이 결과를 보고 질문별 정답 예외나 새로운 재검토 규칙을 넣지 않았다.

- **119845:** Slurm COMPLETED/0:0,2분39초. 계산 노드의 개인 `NLTK_DATA`에 공식 데이터를 다시 받아20개 QA 모두 실행했다. 모델·actor 코드·질문·프롬프트는 바꾸지 않았고, 대응되는19개 실제 요청 본문도 첫 실행과 같았다. 일부 답 표현은 달랐지만 판정은 같았다.

## 검증과 한계

20개 질문과 원문 집합, 입력·실행 소스 해시, 실제 모델 원출력, 선택 인용의 원문 위치와 실제 입력 포함 여부를 확인했다. Qwen chat template로 센 입력 길이도 API 사용량과20/20 일치했다. 모든 원문은 보존됐다. [검증 기록](run-v2/verification.json)

의미 점수는 개발에 참여한 AI 한 명이 원문과 대조한 판정이다. 독립된 사람의 검증이나 ALCE AutoAIS 실행은 아니다. [ALCE 입력 형식 출력](run-v2/alce.json)은 만들었지만 자동 의미 판정을 했다고 표시하지 않는다. 청킹·검색·프롬프트·출력 상한·메타데이터 표시가 함께 달라져 특정 요소만의 인과 효과는 분리하지 못한다.

임베딩 가중치는 기존 MiniLM 경로이며 mean pooling/L2 정규화와256토큰 한도를 사용한다. 독해 청크는 Qwen 토크나이저 기준512토큰이므로 임베딩에서는 일부 긴 청크가 잘릴 수 있다. 이 제한도 [실제 설정](embedding-config/comparison.json)에 기록했다.

재채점 재현:

```bash
python3 -m evaluation.reference_qa.report results/reference-qa/run-v1
python3 -m evaluation.reference_qa.report results/reference-qa/run-v2
```

이는 저장된 실행을 검증하고 명시된 의미 판정을 집계하는 명령이다. 새 추론이나 정답 자동 판정은 하지 않는다.
