# 자연 기록의 조건·이유 연결: 원인 분석과 수정 결과

2026-11-16. **계약 누락 하나는 수정했지만, 전체 개선안은 채택하지 않았다.**
평가셋을 학습에 넣거나 정답·채점 기준을 바꾸지 않았다. 이번 단계의 새 학습은0회다.
범위는 records이며, QA를 새로 실행하거나 해결됐다고 주장하지 않는다.

## 무엇이 실패했나

1. **기존 학습은 자연 기록을 대표하지 않는다.** 학습240/개발80개가 같은10가지
   문형을 공유한다. 개발95.08%는 그 문형의 학습 결과다. 자연 기록의 길이·이유 표현·
   담화 구조에 일반화했다는 근거가 아니다. 기존 모델의 전체 사전학습 데이터는
   확인되지 않았으므로, 그 범위를 추측하지 않는다.
2. **후보 구절이 있어도 연결기가 버린다.** 학습된 GLiNER의 자연 조건·이유13개 중
   11개는 정확한 정답 구절이 내부 후보에 있었다. n03의 정확한 이유 후보 점수는
   0.68073인데 맞는 주장과의 연결 점수는0.0000047이었다. n12는 구절 역할 점수와
   연결 점수가 모두 낮았다. 이 문제를 저장/인용 포맷 오류로 설명할 수 없다.
3. **새 오연결과 구절 누락은 다르다.** m06에서 `reduced load`를 구매 완료 주장에
   연결한 것은 대상 오류다. 추정 주장에 연결하더라도 `under`를 빼서 고정 기준을
   충족하지 못한 것은 별도의 범위 오류다. 둘 다 내부 후보/연결 점수에 이미 나타났다.
4. **LLM 교체만으로 해결되지 않았다.** 기존 주장 ID와 원문을 고정해 연결만 맡긴
   8B와14B 모두 일부 이유를 찾았지만, 다른 주장에 붙이거나 조건/이유를 혼동했다.
   14B는 다른 세대인 Qwen2.5이므로 순수한 모델 크기 효과를 검증한 것은 아니다.

따라서 현재 증거는 ‘좁은 학습 범위와 현재 연결 방식의 전이 실패’를 보여준다.
‘작은 모델이라 불가능’ 또는 ‘데이터를 늘리면 반드시 해결’ 중 하나로 단정할 수 없다.

## 실제 구현에서 가져온 것과 이번에 고친 것

- GLiNER2의 실제 후보 생성기·RecordHead·최종 필터를 실행해 분리 관찰했다.
  원래/학습 후 체크포인트의136개 의미 출력이 재현됐다.67개는 confidence 수치가
  미세하게 달라 완전한 수치 재현이라고 부르지 않는다.
- Graphiti의 기존 끝점 목록과 관계 타입을 전달하는 방식을 적용했다. 첫 구현은
  주장 ID를 고정했지만 **다른 끝점이어야 한다는 전제**를 충분히 옮기지 못했다.
  주장 전체를 자기 자신의 이유/조건으로 붙이는 출력이 그대로 통과했다.
- 이를 `context_contract.bind`에서 수정했다. 새 맥락 구절이 대상의 전체 루트 주장을
  포함하면 거절한다. 주장 안의 적절한 부분 조건은 허용하고, 별도 주장에 있는
  공유 근거도 허용한다. 정답 조회·키워드 규칙·추가 LLM 호출은 없다.
- 기존 LangExtract 정렬기와 records 저장기를 재사용한다. 인용과 구조가 맞더라도
  의미상 올바른 연결이라는 보장은 없으므로 이를 별도로 채점했다.
- PAIE는 실제 학습된 역할별 시작/끝 구절 선택기와 감독 학습을 전제한다.
  이벤트 역할 모델을 이유 연결기로 이름만 바꿔 가져오지는 않았다.

구현·학습 전제와 원문 링크: [상세 감사 문서](../../../docs/records-natural-binding-audit.md).

## 같은68개 기록의 고정 평가

54개 합성 기록은 난이도·근거 가용성 분포 그대로, 자연14개는 기존 실패 감사 사례다.
별도의 미관측 일반화 벤치마크가 아니다. 수치는 원래 평가기의 typed edge 수다.
넓은 구절 하나가 여러 잘못된 연결로 계산될 수 있어 ‘오류 제안 개수’와는 다르다.

| 방식 | 올바른 연결 | 잘못된 연결 | 완전한 문서 |
|---|---:|---:|---:|
| 기존 유지 버전 |44|26|27/68|
| 주장 ID 고정 + Qwen3-8B |52|128|13/68|
| 같은 입력 + Qwen2.5-14B |55|103|13/68|
| 8B + 끝점 계약 수정 |48|54|21/68|
| 14B + 끝점 계약 수정 |53|67|18/68|

모든 후보에서 **기존 내용283개·정답 연결44개·태도187개는 유지**했다.
하지만 새 오연결 때문에 기존 완전한 문서가 훼손됐다. 계약 수정은 잘못된 연결을
줄였으나 기준선보다 여전히 나쁘다. 수정안들 모두 사전 채택 조건을 통과하지 못했다.
실험용 코드와 원출력은 보존하고, 기본 records 경로는 바꾸지 않았다.

자연 기록에서 새로 맞힌 이유 일부도 최소 구절로 제대로 분리됐는지 확인해야 한다.
예를 들어8B의 n12는 목적을 포함한 문장 전체를 basis로 반환했다. 정답 토큰이 들어
있다는 이유로 이 기록이 완성됐다고 세지 않았다.
