# Records 문서 전체 품질 평가

**기존 방식은 내용 회수와 관계 구성에서 단순 추출보다 낫지만, 전체 기록 품질은 아직 부족하다.** 문서 전체 정답을 만들자, 일부 주장만 맞으면 통과하던 평가에서 보이지 않던 잘못된 역할·연결, 불필요한 인사말/문장 조각, 저장 전 정보 손실이 드러났다.

이번 변경은 데이터셋 정답·평가기뿐이다. 생산 records/QA 코드는 변경하지 않았다. 같은 원문·프롬프트·Qwen3-8B 설정이므로 Aurora122970의 실제136개 입력/원출력을 재사용했다. 새로운 추론0회, 추가 GPU 사용0분이다. 결과를 보고 작성한 개발용 정답이므로 **새로운 비공개 테스트나 성능 향상 실험이 아니다.**

## 정답의 범위

| 항목 | 규모/정책 |
|---|---|
| 합성 입력 |54개: 난이도3×초점 근거 가용성3×각6개, 기존 원문 그대로 |
| 자연 입력 |기존 EverMem14메시지,5사례. 합성 결과와 분리 |
| 전체 기록 단위 |207개: 합성162, 자연45 |
| 전체 정보 단위 |339개: 필수336개 + 선택적 추론 이유3개 |
| 연결 |필수129개: 합성81, 자연48. 선택적 이유 연결3개 |
| 출처 |모든 단위에 원문 구절·시작/끝 위치, 문서에 source ID·작성자·관찰 시각·위치·원문 해시 |
| 포함한 정보 |주장, 조건, 이유, 시각, 필요한 대상/선행 표현, 수신자, 한정, 방법/예시 |

주된 주장만 보지 않는다. 다른 대상의 관찰과 지시, 반복된 사실의 원문 위치, 미승인·미검증 한정도 정답에 포함했다. 확인할 대상이 없는 동의문(n11)은 해소되지 않은 참조로 남기고 대상을 추측하지 않는다. 인사말·단순 수신 확인은 독립적인 기록으로 요구하지 않는다.

기존 n06의 부재 라벨 오류를 고쳤다. `file storage solution`은 실제 첫 문장에 있으므로 승인 보고의 대상에 연결해야 한다. 문서의 외형적 stratum은 과거와 동일하게 보존하되 그 잘못된 정답은 더 이상 사용하지 않는다.

가용성 full/partial/none은 기존 통제 대상인 **초점 한정 두 개**를 가리킨다. none 문서에도 다른 대상의 사실이 남아 있으며 그것도 전부 평가한다. 원문을 늘리거나 쉬운 사례로 교체하지 않았다. [전체 정답과 원문](gold-cases.md), [분포별 결과](strata.md).

## 같은 Qwen 비교

아래는 전체 문서 정보와 관계를 센 micro 값이다. 사례별 macro recall도 evaluation.json에 있으며, 전체 문서 완전 통과를 별도로 제시한다. ‘정보 회수’는 구절이 출력 어딘가에 있다는 의미로, 올바른 대상에 붙었다는 뜻이 아니다.

### 합성54문서

| 지표 | 단순 추출 raw → compiled | 기존 방식 raw → compiled |
|---|---:|---:|
| 필수 정보 회수율 |92.6% →91.4%|100.0% →85.2%|
| 관계 Precision |76.9% →83.3%|61.2% →64.2%|
| 관계 Recall |12.3% →12.3%|50.6% →42.0%|
| 관계 F1 |21.3% →21.5%|55.4% →50.7%|
| 문서 전체 완전 통과 |11/54 →11/54|28/54 →23/54|

기존 방식의 raw 정보 회수100%는 **243개 필수 구절이 어딘가에 있다는 부분 지표**다. 관계40개를 누락하고26개를 잘못 연결했으므로 전체 품질100%가 아니다. 단순 방식은 관계를 거의 만들지 않아 precision이 상대적으로 높아도 recall이12.3%에 그친다.

저장 전 컴파일에서 기존 방식의 정보36개(243→207), 올바른 관계7개(41→34)가 추가로 사라졌다. 문서 단위 거절과 그룹 단일 상태로의 합성이 영향을 줬다. 실패 그래프의 원문은 남아 있으므로 디스크에서 원문이 삭제됐다는 뜻은 아니다.

기존 방식은 독립 기록을 한 그룹에 섞은 쌍이 합성 raw에서0쌍, 단순 방식은35쌍이었다. 반대로 기존 방식에는 정답 단위와 맞지 않는 추가/불완전 행10개, 비중심 주장 행15개가 있었다. 이 두 수는 겹칠 수 있으므로 더하지 않는다. 표현 조각의 정상 여부는 사례별 감사가 필요해 정밀도 근사치로 취급한다.

### 자연14문서

| 지표 | 단순 추출 raw → compiled | 기존 방식 raw → compiled |
|---|---:|---:|
| 필수 정보 회수율 |78.5% →58.1%|96.8% →81.7%|
| 관계 F1 |23.9% →14.3%|38.9% →30.8%|
| 문서 전체 완전 통과 |0/14 →0/14|0/14 →0/14|

기존 방식 raw에는 추가/불완전 행11개와 인사말 등이 섞인 행10개가 있었다(중복 집계 가능). `Good morning everyone`, `Email received`, `Great plan`을 독립 주장으로 저장한 사례가 포함된다. `the backend` 같은 단편은 잘못된 필드인지 정상적인 부분 표현인지 원문과 함께 판별해야 하므로 모든 추가 행을 환각이라고 부르지 않는다.

## 이전 부분 평가에서 가려졌던 사례

- **n13 / polling**: 예전 부분 기준에서는 기존 방식이 통과했지만, 이제 `by requesting the interface every 10 seconds`를 condition으로 붙인 것을 **방법의 역할 오류**로 잡는다. `for now` 시각과 현재 작업을 막지 않기 위한 이유의 연결 누락도 드러난다. 이 문서의 기존 방식 raw 관계는 TP0/FP2/FN5다.
- **n06 / 승인 대상**: `The proposal is approved`를 남겨도 `file storage solution` 대상과 연결하지 못하면 완전 통과하지 않는다. `approved`와 `can be finalized`를 나눠 추출했다는 이유만으로 추가 추출로 벌점 주지는 않는다.
- **m05-full / 날짜 연결**: 날짜는 뽑았지만 `The calibration event occurred`라는 별도 조각에 붙어 실제 valve calibration 기록에 전달되지 않는다. 내용 회수와 연결 정확도를 분리해야 보인다.
- **e04-full / 제안과 미승인**: raw는 proposal과 미승인 관찰을 각각 보존해 통과한다. compiled는 둘을 unknown으로 합쳐 통과하지 못한다. 전체 주장별 상태 정답을 두어 모델과 표현 형식의 오류를 분리했다.
- **h05-full / 반복 시간**: 초점과 다른 사건까지 포함한 전체 raw 구조는 통과하지만 반복되는 시간 구절 때문에 컴파일에서 소스 전체가 실패한다.

새 기준에서 raw는 완전했으나 compiled에서 잃은 기존 방식5문서는 e04-full, e04-partial, m04-partial, h04-partial, h05-full이다. 이 수치를 과거 ‘초점만’ 평가의2건과 직접 비교하면 안 된다. 정답 범위와 상태 평가 단위가 달라졌다.

## 출처·검증과 평가기 자체의 감사

- 기존136개 모델 요청의 프롬프트·Qwen 설정·원출력을 다시 대조했다. 코드/입력/결과 해시, compiler 재생, source metadata와 원문 위치를 검증했다. 기존 actual store/reader 전달 영수증도 검증했으며 새 저장 실험을 실행한 것은 아니다.
- 모델 source metadata는136/136 그대로이고 그래프 출처 검증도 통과했다. 이는 metadata 전달의 정확성이며 모델의 작성자/수신자 해석 능력100%를 뜻하지 않는다. raw 원문 구절 변형과 typed target 오류는 별도로 채점한다.
- **147개 평가기 검사**:68개 전체 gold oracle,68개 분할 표현 동치,11개 누락·추가 주장·오연결·역할 교환·잘못된 상태·부정 제거·중복 후보 등의 변이 검사.
- v1은 정상 분할 구절을 추가 추출로 세는 문제가 있었고, v2는 같은 구절이 여러 gold 참조에 존재할 때 한 잘못된 연결을 여러 FP로 셀 수 있었다. source 기반 불변성 검사로 고쳐 v3를 동결했다. 정답·입력은 수정하지 않았고 이전 코드/점수는 보존했다. 모델 성능 개선으로 제시하지 않는다.
- raw와 compiled, 내용과 관계, 오류 있는 추가 추출과 정당한 분할, 작성자와 수신자를 구분했다. `on Thursday`/`Thursday`는 동일한 시각 표현으로 인정한다.

## 현재 판단과 제한

**문서 전체 정답과 precision/recall을 함께 보는 기반은 마련됐다. 기존 방식은 보존·분리에 이득이 있지만 연결 오류, 불필요 추출, 컴파일 손실이 남아 있다.** 기존 방식의 기록 생성 전체를 버릴 결과도, 완성됐다고 볼 결과도 아니다.

이 정답은 단일 작성자의 개발용 주석이며 독립적인 사람 검수를 거치지 않았다. 자동 평가는 원문 material-token anchors를 사용하는 범위 제한적 매칭이다. 자유로운 의미 동치, 모든 부정·범위 해석, 없는 antecedent를 미해결 상태로 표시하는 기능까지 검증된 것은 아니다. basis의 stated/inferred 자격 표시는 별도 진단이며 현재 unspecified를 완전 문서 점수에서 숨겨 해결된 것으로 간주하지 않는다. 원문의 의미를 넘어서는 자유 생성이나 서비스 품질을 이 숫자로 주장할 수 없다.

다음 records 수정은 (1) 조건/이유/방법과 대상을 연결하는 계약, (2) 불필요한 인사말·조각의 기록화, (3) 개별 주장 태도와 소스 전체 거절 경계를 우선해야 한다. 새 코드의 개선 판단은 이 개발용 정답의 독립 검토와 별도 이야기 묶음에서 확인해야 한다.
